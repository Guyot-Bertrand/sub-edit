# `convert`

<!-- machine-translated -->
> Ова страница је машински превод који још није прегледао читалац језика.

```
subedit-cli convert --to <format>
                    [--line-endings unix|windows|mac] [--to-encoding NAME]
                    [--bom | --no-bom] [--sort] [--disjoint]
                    [--join-repeats] [--repair]
                    (--output FILE | --output-dir DIR | --in-place)
                    [--dry-run]
                    [--recursive]
                    <file>...
```

Записује сваку датотеку у траженом формату и облику. **Никада не мења
улаз**, осим ако `--in-place` то изричито тражи.

<!-- example: subedit-cli convert --help -->
```console
$ subedit-cli convert --help
Write a subtitle file out in another format or shape
Usage: subedit-cli convert [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to convert

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --to TEXT:{srt,vtt,subviewer2,ssa,ass,microdvd,mpl2,tmplayer,lrc} REQUIRED
                              Format to write
  --line-endings TEXT:{unix,windows,mac}
                              Line endings to write; the source's by default
  --to-encoding NAME          Encoding to write; the source's by default
  --frame-rate RATE           Frame rate of a file counted in frames: 25, 23.976
  --bom                       Write a byte order mark
  --no-bom                    Write no byte order mark
  --sort                      Put the subtitles in order of their start before writing
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before writing
  --join-repeats              Join the subtitles that repeat each other into one, before writing
  --repair                    Join the repeats, sort, then make the ranges disjoint, before writing
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументи и опције

| Опција | Обавезно | Вредности | Подразумевано |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | једна или више путања | — |
| `--recursive`, `-r` | не | опција без вредности | искључено — види [Обрада стабла директоријума](lots.md) |
| `--to` | **да** | назив из табеле испод, и ништа друго | — |
| `--line-endings` | не | `unix`, `windows` или `mac` | они прочитане датотеке |
| `--to-encoding` | не | свако кодирање које ICU може да запише, осим оних која пишу сопствену ознаку | оно прочитане датотеке |
| `--bom` / `--no-bom` | не | опције без вредности, које се међусобно искључују | оно што је носила прочитана датотека |
| `--sort` | не | опција без вредности: ређа титлове по почетку **пре писања**, види [Ређање при писању](#ређање-при-писању) | искључено |
| `--join-repeats` | не | опција без вредности: прави један титл од делова истог текста који иду један за другим, **пре свега осталог**, види [Раздвајање интервала](#раздвајање-интервала) | искључено |
| `--repair` | не | опција без вредности: исто што и `--join-repeats --sort --disjoint`, тим редом | искључено |
| `--disjoint` | не | опција без вредности: сече титлове који се преклапају **пре писања**, види [Раздвајање интервала](#раздвајање-интервала) | искључено |
| `--output` / `--output-dir` / `--in-place` | **једна од три**, осим уз `--dry-run` | види [Покретање](invocation.md#одредиште) | — |
| `--dry-run` | не | опција без вредности: израчуна и каже, не пише ништа — види [Прво видети, па писати](invocation.md#прво-видети-па-писати) | искључено |

`mac` означава сâм повратак на почетак реда (`\r`), завршетак реда класичног Mac OS-а.

## Формати које `--to` прихвата

| Назив | Формат | Записани наставак |
| :-- | :----- | :--------------- |
| `srt` | SubRip | `.srt` |
| `vtt` | WebVTT | `.vtt` |
| `subviewer2` | SubViewer 2.0 | `.sub` |
| `ssa` | Sub Station Alpha | `.ssa` |
| `ass` | Advanced SSA | `.ass` |
| `mpl2` | MPL2 | `.txt` |
| `microdvd` | MicroDVD | `.sub` |
| `tmplayer` | TMPlayer | `.txt` |
| `lrc` | LRC | `.lrc` |

**Назив, а не наставак.** Два наставка именују по два формата —
`.sub` је и наставак формата MicroDVD, `.txt` и формата MPL2 и
TMPlayer — па опција која би примала наставке не би знала који
се тражи. Горњи називи су недвосмислени и поклапају се са
наставком где год је и наставак недвосмислен.

**Списак је затворен.** То је списак програма Gaupol, и свих девет је у њему.

## Два формата која не носе крај

**TMPlayer и LRC пишу само један положај по реду**, његов почетак. То
се види на обе стране.

**При читању** крајеви се закључују: крај реда је почетак
следећег, а последњи добија пет секунди. То ради Gaupol.
Ми то такође кажемо, помоћу дијагностике коју `--verbose` приказује на све три
подкоманде:

```
file.lrc: carries no end times; each one was taken from the next start, settled by the reader
```

**При писању** крајеви се не записују, јер нема места за њих.
Претварање у један од ова два формата зато их губи, а кружно путовање их
не враћа — поново их закључује.

**LRC губи још нешто**: нема начина да носи прелом реда.
Ред разговора у два реда записује се у један, а два дела се спајају
размаком. Ни тај губитак не може да се поправи.

Ниједан од њих нема речник за искошено писмо.

## `--frame-rate` и једини формат који броји у кадровима

**MicroDVD не броји у секундама**: његови положаји *јесу* бројеви
кадрова, а ниједна MicroDVD датотека не објављује брзину којом су
бројани. `--frame-rate` је даје, и служи на обе стране: то је
брзина којом се `.sub` у кадровима чита и она којом претварање
у MicroDVD броји кадрове.

| Опција | Обавезно | Вредности | Подразумевано |
| :----- | :----- | :------ | :----- |
| `--frame-rate` | не | брзина у кадровима у секунди: `25`, `23.976`, `29.97` | види испод |

**При читању, без `--frame-rate`, датотека се чита при 23,976** — вредност програма
Gaupol — а ниво `-vvv` то каже:
`counts in frames and states no rate; it was read at`. То је једино место у алату где сваки приказани
положај почива на претпоставци коју датотека не може да потврди.

**При писању, без `--frame-rate`, три случаја и три одговора:**

| Полазна датотека | Шта се дешава |
| :------------------- | :-------------- |
| већ је MicroDVD | брзина која ју је прочитала је и записује, а кадрови се враћају идентични |
| заснована је на времену, а њени положаји падају на мрежу | узима се мрежа, а `-vv` каже која |
| заснована је на времену, без мреже | **одбијање**, код 2: `writing frames needs a frame rate, and the positions fall on no grid to take one from — give --frame-rate` |

Одбијање је намерно. Једина преостала радња била би измишљање броја, а
сваки ред датотеке би се померио за онолико колико је тај број погрешан.

## Шта претварање губи

**Претварање у други формат никада није без губитка**, а оно што не преживи
зависи од пара:

| Шта не пролази | Зашто |
| :--------------------- | :------- |
| заглавље | има смисла само у свом формату: `[INFORMATION]` није WebVTT заглавље |
| подаци специфични за формат | координате формата SubRip, идентификатор и поставке WebVTT реплике немају еквивалент другде |
| прецизност | SubViewer 2, оба Sub Station Alpha формата и LRC пишу на стотити део, MPL2 на десети, TMPlayer на секунду, MicroDVD на кадар; `01:00:00,017` се враћа као `01:00:00,020` |
| крај реда | TMPlayer и LRC немају поље за њега; следеће читање га поново закључује |
| прелом реда | само LRC: његови редови стају у један ред, а два се слепљују размаком |
| ознаке које циљни формат не може да запише | WebVTT нема `<font color>`, TMPlayer и LRC немају ништа |
| распоред | `{\pos(x,y)}`, `{\an8}`, `<v Marie>`, `<ruby>`: преживљавају кружно путовање у свом формату, а при претварању нестају |

**Враћање датотеке у њен сопствени формат не губи ништа** — то је гаранција
на којој почива све остало, а `--to srt` на `.srt` враћа исте бајтове. Ништа
се чак ни не декодира: текст остаје сирова ниска која је прочитана.

## Ознаке се преводе, не копирају

**Сваки формат записује искошено писмо на свој начин**, а претварање без превођења
оставило би `{\i1}` у `.srt`: текст који корисник види, у
датотеци која никада неће знати да га протумачи. Пролази **шест
ствари** — подебљано, искошено, подвучено, боја, фонт и величина:

| Формат | Подебљано | Искошено | Подвучено | Боја | Фонт | Величина |
| :----- | :--: | :------: | :------: | :-----: | :----: | :----: |
| SubRip | `<b>` | `<i>` | `<u>` | `<font color="#RRGGBB">` | — | — |
| WebVTT | `<b>` | `<i>` | `<u>` | — | — | — |
| SubViewer 2 | `<b>` | `<i>` | `<u>` | `<font color="#RRGGBB">` | — | — |
| Sub Station Alpha | `{\b1}` | `{\i1}` | — | `{\c&HBBGGRR&}` | `{\fnNAME}` | `{\fsN}` |
| Advanced SSA | `{\b1}` | `{\i1}` | `{\u1}` | `{\c&HBBGGRR&}` | `{\fnNAME}` | `{\fsN}` |
| MicroDVD | `{Y:b}` | `{Y:i}` | `{Y:u}` | `{C:$BBGGRR}` | `{F:NAME}` | `{S:N}` |
| MPL2 | `\` | `/` | `_` | `{C:$BBGGRR}` | `{F:NAME}` | `{S:N}` |
| TMPlayer | — | — | — | — | — | — |
| LRC | — | — | — | — | — | — |

**Цртица је најављен губитак.** Претварање обојене `.srt` у WebVTT уклања
боју и то јавља; добијена датотека је WebVTT, а не прерушени SubRip.

**MicroDVD и MPL2 не могу да обликују део реда.** Њихове ознаке
немају крај: `{y:i}` искошава све што следи до краја реда, а
`{Y:i}` до краја титла. Ред који је само у једној половини био
подебљан зато се записује без подебљања, а не са подебљањем које прелива.

## Шта конверзија каже да је изгубила

**Каже када губи, а ћути када не губи ништа.** Извештај
који се појављује при сваком позиву је извештај који нико не чита.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,500\n<i>sur deux</i>\nlignes\n\n' > a.srt; subedit-cli convert --to lrc --output b.lrc a.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,500\n<i>sur deux</i>\nlignes\n\n' > a.srt; subedit-cli convert --to lrc --output b.lrc a.srt
a.srt: 1 subtitle written as LRC -> b.lrc
a.srt: ends are not carried by LRC, line breaks were joined in 1 subtitle, 1 tag dropped
```

Ред се појављује на подразумеваном нивоу опширности и на свакоме изнад њега.
Ставке, тим редом:

| Ставка | Шта каже |
| :---- | :----------- |
| `ends are not carried by <format>` | циљни формат не записује крај |
| `line breaks were joined in N subtitles` | само LRC: N титлова је било у више редова |
| `N tags dropped` | N ознака није могло да се запише, распоред укључен |
| `the header was dropped` | заглавље не прелази границу формата |
| `the <format> fields of N subtitles were dropped` | N титлова је носило податке специфичне за свој формат |
| `positions moved by up to N ms` | највеће растојање за које се неки положај померио |

## Промена кодирања

**`--to-encoding` бира кодирање које се записује; `--encoding` каже оно које се
чита.** Заједно поново кодирају датотеку:

```console
$ subedit-cli convert --to srt --encoding cp1252 --to-encoding utf-8 \
      --output-dir sortie film.srt
```

Без `--to-encoding`, датотека се записује у **кодирању у ком је прочитана**,
као што је случај са њеним завршецима редова и ознаком: датотека претворена без
упутства о кодирању враћа исте знакове, на истим бајтовима.

**Знак који циљно кодирање не може да запише зауставља датотеку**, а
ништа се не пише. Знак `ł` нема места у Latin-1; његова замена знаком `?`
изгубила би текст између читања и писања, а да нико то не види.

**Ознака редоследа бајтова постоји само за Unicode кодирања.**
`--bom` уз `--to-encoding` које је не носи одбија се уместо да се занемари
— види табелу грешака испод.

**И кодирање мора да именује редослед бајтова.** `UTF-16` и `UTF-32` су
називи које ICU познаје, чији претварач записује **сопствену ознаку**, ма шта
се тражило: `--no-bom` би тада био прихваћен и непослушан. Оба се
зато одбијају, а порука именује излаз:

```console
$ subedit-cli convert --to srt --to-encoding UTF-16 --output copie.srt film.srt
"UTF-16" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do
```

`UTF-16LE`, `UTF-16BE`, `UTF-32LE` и `UTF-32BE` записују потпуно исте
бајтове, ознаку укључену — али под управом опција `--bom` и `--no-bom`. Одбијање
зато не кошта ништа осим прецизнијег назива, а важи и за читање као
за писање: `--encoding UTF-16` добија исти одговор.

## Одредиште

Три опције и њихова правила заједничка су подкомандама које
пишу: види [Покретање](invocation.md#одредиште). Ништа се не пише
без једне од њих.

Оно што је специфично за `convert`: **`--output-dir` мења наставак према
формату.** `convert --to vtt` над `a.srt` записује `a.vtt`, никада `a.srt` који садржи
WebVTT — датотека чије име лаже збуњује сваки други алат.

## Претварање на самој датотеци се одбија

`--in-place` уз `--to` који мења формат даје код `1` и не пише
ништа: на самој датотеци нема другог имена које би понело нови формат, а
датотека би остала под наставком који њен садржај више не оправдава.

`--in-place` и даље може да се користи за промену **облика без формата** —
на пример, враћање `.srt` као `.srt` са другим завршецима редова.

Одбијање се одлучује **само на основу наставка**, пре било каквог читања: грешка у
употреби никада не сме да остави серију напола записану.

## Завршеци редова и ознака редоследа бајтова

Подразумевано **записана датотека преузима оно што је носила прочитана**. Модел
чува оба при читању; њихово наметање подразумевано би губило, при сваком
претварању, податак који се намерно чува.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli convert --to vtt --output b.vtt a.srt; cat b.vtt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli convert --to vtt --output b.vtt a.srt; cat b.vtt
a.srt: 1 subtitle written as WebVTT -> b.vtt
WEBVTT

00:01.000 --> 00:03.000
Bonjour.
```

## Ређање при писању

`--sort` записује датотеку **по редоследу почетака**, ма који био циљни формат. Ређање се ради **на копији**: прочитана датотека
се не дира, а записује се оно што би од ње направила подкоманда [`sort`](sort.md) — стабилно, два титла која почињу заједно задржавају свој редослед.

**Никада подразумевано**: редослед датотеке је редослед њеног аутора све док се ништа друго не тражи. Уз опцију, свака датотека то јавља, на
првом нивоу приповедања, `<path>: N subtitles moved` или `<path>: already in order`, а запис `--format json` носи број
`moved` — **одсутан без опције**, да се не мења облик онога што постојеће скрипте читају.

## Раздвајање интервала

`--disjoint` сече титлове који се преклапају тако да ниједан интервал више не прекрива други, **на истој копији као и ређање**: прочитана датотека се не дира.

Никада подразумевано. Опција ради оно што ради [`disjoint`](disjoint.md), **са својим подразумеваним поставкама**, пре писања, после ређања. Потребна јој је уређена датотека: у супротном се одбија, а `--sort` — који долази први — доводи је у ред унапред. Датотека то јавља на првом нивоу приповедања (`<path>: N subtitles split, M merged`), а запис `--format json` носи бројеве `split` и `merged`, **одсутне без опције**.

**`--join-repeats` долази пре ређања и сечења**: текст исечен на делове који иду један за другим прво се поново гради (види
[`join-repeats`](join-repeats.md)), затим се титлови ређају, затим се интервали раздвајају. **`--repair` је сва три одједном**,
као [`repair`](repair.md), са подразумеваним поставкама сечења. Уз `--join-repeats` свака датотека јавља
`<path>: N repeated subtitles joined` на првом нивоу приповедања, а запис `--format json` носи `counts.joined` — **одсутан без опције**.

## Излаз

**Стандардни излаз** — ништа: резултат је записана датотека. Ни уз `--dry-run` ништа: нема датотеке, а ред приповедања то каже — види [Прво видети, па писати](invocation.md#прво-видети-па-писати).

На излазу за грешке, према нивоу:

| Ниво | Шта се додаје |
| :----- | :-------------- |
| 1 | `<path>: N subtitles written as WebVTT -> <destination>` |
| 2 | `<path>: SubRip -> WebVTT, UTF-8, no BOM, LF line endings` — именовано кодирање је оно које се записује |
| 3 | `<path>: N bytes read, M written`, затим **свака дијагностика читања** — види [Покретање](invocation.md#читање-дијагностике) |

### У JSON-у

Уз [`--format json`](invocation.md#излаз-који-скрипта-може-да-чита), објекат сваке датотеке носи `counts.subtitles`, затим оно што је претварање изгубило: `lost_ends` и `lost_header` (`0` или `1`), `joined_lines`, `lost_tags`, `lost_fields` и `furthest_ms` — ставке [реченице о губитку](#шта-конверзија-каже-да-је-изгубила). Потпуна табела налази се у одељку [Покретање](invocation.md#шта-свака-подкоманда-уписује-у-counts).

## Излазни кодови

Они самог алата: `0` ако је свака датотека записана, `2` ако ниједна, `3` ако
само неке, `1` код грешке у употреби.

## Грешке

| Шта је изазива | Порука |
| :------------------ | :------ |
| `--bom` уз `--no-bom` | `--bom and --no-bom ask for opposite things; give one or the other` |
| `--in-place` који мења формат | `--in-place cannot change the format: the file would keep a name its content no longer matches` |
| `--bom` над кодирањем које је нема | `<path>: <encoding> has no byte order mark to write` |
| `--to-encoding` са непознатим кодирањем | `no encoding is named "<name>"` |
| `--to-encoding` са кодирањем које пише сопствену ознаку | `"<name>" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do` |
| знак којег нема у кодирању које се записује | `<path>: holds a character the chosen encoding cannot write` |

**Одбијање `--bom` над кодирањем које је не носи није
педантерија.** Ознака редоследа бајтова постоји за Unicode кодирања и
ни за једно друго: тражити је за датотеку у Windows-1252 значи тражити
нешто што не постоји. Датотека би била записана без ње, а нико не би
знао да захтев није испуњен.

Грешке одредишта заједничке су подкомандама које пишу:
види [Покретање](invocation.md#одредиште).

Грешке читања су оне подкоманде [`inspect`](inspect.md): тичу се
улазне датотеке и имају исте поруке.
