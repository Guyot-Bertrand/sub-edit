# `append`

<!-- machine-translated -->
> Ова страница је машински превод који још није прегледао читалац језика.

```
subedit-cli append --output FILE
                   [--dry-run] [--sort] [--disjoint]
                   <base> <file>...
```

Поставља датотеке **иза прве**, у **једну** датотеку: филм у два дела, претворен у
један скуп титлова. То је `Append File…` из прозора — [исти мотор](../subedit-gui/operations.md#append-file),
исти бројеви — примењен онолико пута колико има датотека за прикачивање.

- **Прва датотека је основа.** Она даје резултату **његов формат, кодирање, ознаку
  редоследа бајтова и завршетке редова**.
- **Ништа се не умеће између две датотеке**: свака се помера за **крај последњег титла онога што
  јој претходи**, а њени положаји задржавају свој редослед и размак. Трећа следи другу, а не
  основу: датотеке иду једна за другом оним редом којим су задате.
- **Свака прикачена датотека пролази кроз претварање** у формат основе: њене ознаке се преводе,
  а оно што тај формат не може да запише јавља се, датотеку по датотеку, речима прозора.
- **Прикачене датотеке немају превод**: датотека отворена сама нема га шта да да.
- **Датотека може да се зада више пута**, или да се прикачи самој себи: ништа то не забрањује.

**`append` није серија.** N улаза, **један** излаз: петља осталих подкоманди — један резултат
по датотеци и неуспех који остале пушта да наставе — овде нема смисла. Из тога следе три ствари:

- **одредиште је `--output`, и ништа друго.** `--output-dir` и `--in-place` не постоје за
  `append` и одбијају се као свака непозната опција, код `1`; исто тако `--recursive`: редослед
  датотека је онај којим су задате, а пређено стабло га нема;
- **све или ништа**: прва датотека која не може да се прочита зауставља извршавање и **ништа се не
  пише**. Филм у три дела од којих један недостаје није филм у два дела;
- **једна линија по извршавању** за резултат и, у JSON-у, **један објекат**.

<!-- example: subedit-cli append --help -->
```console
$ subedit-cli append --help
Put subtitle files one after another into a single file
Usage: subedit-cli append [OPTIONS] files...

Positionals:
  files BASE FILE...          The base file, then the files to put after it, in order

Options:
  -h,--help                   Print this help message and exit
  --output FILE               File to write
  --dry-run                   Work out and say what would be written, and write nothing
  --sort                      Put the subtitles in order of their start before writing
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before writing
```

## Аргументи и опције

| Опција | Обавезно | Вредности | Подразумевано |
| :----- | :----- | :------ | :----- |
| `<base> <file>...` | да, **најмање две** | путање: основа, па оно што се поставља иза ње, по редоследу | — |
| `--output` | **да**, осим уз `--dry-run` | путања датотеке; њен директоријум се ствара ако не постоји | — |
| `--dry-run` | не | опција без вредности: израчуна и каже, не пише ништа — види [Прво видети, па писати](invocation.md#прво-видети-па-писати) | искључено |
| `--sort` | не | опција без вредности: поређа целину по почецима **пошто је све прикачено**, види [Ређање резултата](#ређање-резултата) | искључено |
| `--disjoint` | не | опција без вредности: сече титлове који се преклапају **пошто је све прикачено и поређано**, види [Раздвајање интервала](#раздвајање-интервала) | искључено |

**Одредиште не може бити ниједан од улаза**, ни основа: писање преко датотеке која се
чита одбија се пре него што се било шта прочита, код `1`. Постојећа `--output` различита од улаза
преписује се, као свуда.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt
partie2.srt: appended 1 subtitle
partie1.srt: 3 subtitles from 2 files -> film.srt
1

un

2
00:00:03,000 --> 00:00:04,000
deux

3
00:00:04,500 --> 00:00:05,500

```

Последњи титл у `partie1.srt` завршава се у 4 s; онај у `partie2.srt`, који је почињао у 0,5 s, почиње у
4,5 s.

## Ређање резултата

Свака датотека се помера **од краја онога што јој претходи**: редослед који може да се наруши је, дакле, редослед самих датотека. Опција `--sort`
поређа резултат по почецима, **одједном, после последњег прикачивања**, као што би урадила подкоманда [`sort`](sort.md) — стабилно и без измене
садржаја.

Никада подразумевано. Уз опцију, основа то јавља на првом нивоу приповедања, `<base>: N subtitles moved` или `<base>: already in order`, а
запис `--format json` носи број `moved`, **одсутан без опције**.

## Раздвајање интервала

Никада подразумевано. Опција ради оно што ради [`disjoint`](disjoint.md), **са својим подразумеваним поставкама**, пошто је све прикачено, над целином. Потребна јој је уређена датотека: у супротном се одбија, а `--sort` — који долази први — доводи је у ред унапред. Датотека то јавља на првом нивоу приповедања (`<path>: N subtitles split, M merged`), а запис `--format json` носи бројеве `split` и `merged`, **одсутне без опције**.

## Када се формати разликују

Резултат је у **формату основе**, ма који био формат осталих. Шта прелаз кошта
јавља се датотеку по датотеку, речима прозора — иста реченица као код `Append File…` и као код
[лепљења из другог формата](../subedit-gui/clipboard.md#ознаке-другог-формата-се-преводе):

```text
d.ass: appended 1 subtitle; Advanced SSA into SubRip: 1 tag dropped, the header was dropped
```

Шта се губи зависи само од формата **сваке** прикачене датотеке: основа у формату Advanced SSA прима
SubRip датотеку без губитка, а не обрнуто. Да бисте изабрали формат резултата, ставите прво датотеку
која је већ у том формату, или касније претворите помоћу подкоманде [`convert`](convert.md).

## Излаз

**Стандардни излаз** — ништа: резултат је записана датотека.

| Ниво | Шта се додаје на излаз за грешке |
| :----- | :------------------------------------- |
| 1 | једна линија по прикаченој датотеци — `<path>: appended N subtitles`, а затим, када је формат нешто коштао, `; <source format> into <base format>: <what is lost>` — затим `<base>: N subtitles from M files -> <destination>` (уз `--dry-run`, `(dry run, nothing written)` уместо `-> <destination>`) |
| 2 | `<base>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодирање, ознака и завршеци редова основе, враћени какви су били |
| 3 | `<base>: N bytes read, M written` (све датотеке заједно), затим **свака дијагностика читања** — види [Покретање](invocation.md#читање-дијагностике) |

### У JSON-у

Уз [`--format json`](invocation.md#излаз-који-скрипта-може-да-чита), **један објекат** за цело извршавање,
чији је `file` **основа**. Његови `counts`:

| Број | Шта каже |
| :----- | :----------- |
| `files` | датотеке извршавања, основа укључена |
| `subtitles` | титлови резултата |
| `appended` | они који долазе из прикачених датотека |
| `lost_ends`, `lost_header` | `0` или `1`: једна од прикачених датотека га је изгубила |
| `joined_lines`, `lost_tags`, `lost_fields` | збир онога што су прикачене датотеке изгубиле |
| `furthest_ms` | највеће померање положаја, све датотеке заједно |

**Низ `inputs`** иде уз `counts`, изван њих: један елемент по прикаченој датотеци, по редоследу,
`{"file", "counts"}` — `counts` носи `appended`, па исте губитке, **само за ту датотеку**. Он говори,
у извршавању од десет датотека, која је шта коштала. Упозорења читања свих датотека
скупљена су у `warnings`.

Неуспех је такође објекат, **један једини**: онај прве датотеке која није могла да се прочита.

## Излазни кодови

| Код | Када |
| :--- | :---- |
| `0` | резултат је записан — или израчунат, уз `--dry-run` |
| `1` | грешка у употреби: мање од две датотеке, нема `--output`, опција коју `append` нема, одредиште које је један од улаза |
| `2` | **датотека није могла да се прочита**, или одредиште није могло да се запише: ништа се не пише. Не постоји код `3`: извршавање које пише само једну датотеку или успе или не успе |

## Грешке

| Шта их изазива | Порука |
| :------------------- | :------ |
| задата једна датотека | `append needs a base file and at least one file to put after it` |
| ни `--output` ни `--dry-run` | `no destination given: append writes one file, use --output` |
| `--output` именује улаз | `<destination>: would be written over the input <input>` |
| датотека која недостаје, не чита се или је непознатог формата | `<path>: does not exist`, `<path>: is in no format this tool knows`… — исто као свуда |

**Празна датотека се не прикачује**: ниједан формат се не чита без бар једног титла, а датотека се
одбија као свака датотека која не може да се прочита — `<path>: holds nothing recognisable as a subtitle` —, што
зауставља извршавање и не пише ништа.
