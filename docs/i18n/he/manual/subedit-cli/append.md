# `append`

<!-- machine-translated -->
> דף זה הוא תרגום מכונה שעדיין לא נבדק על ידי דובר השפה.

```
subedit-cli append --output FILE
                   [--dry-run] [--sort] [--disjoint]
                   <base> <file>...
```

מניח קבצים **אחרי הראשון**, ב**קובץ אחד**: הסרט בשני חלקים, שהפך
לסדרה אחת של כתוביות. זוהי `Append File…` של החלון — [אותו מנוע](../subedit-gui/operations.md#append-file),
אותן ספירות — המוחלת פעמים רבות ככל שיש קבצים להוסיף.

- **הקובץ הראשון הוא הבסיס.** הוא נותן לתוצאה **את הפורמט שלו, את הקידוד שלו, את סימן סדר
  הבתים שלו ואת סוף השורה שלו**.
- **דבר אינו מוכנס בין שני קבצים**: כל אחד מוזז **בסוף הכתובית האחרונה של מה
  שקדם לו**, כשמיקומיו שומרים על סדרם ועל המרווחים ביניהם. השלישי בא אחרי השני, לא אחרי
  הבסיס: הקבצים באים זה אחר זה בסדר שבו ניתנו.
- **כל קובץ שנוסף עובר המרה** לפורמט הבסיס: התגיות שלו מתורגמות,
  ומה שהפורמט הזה אינו יכול לכתוב נאמר, קובץ אחר קובץ, במילות החלון.
- **לקבצים שנוספו אין תרגום**: לקובץ שנפתח לבדו אין תרגום לתת.
- **אפשר לתת קובץ כמה פעמים**, או להוסיף אותו לעצמו: דבר אינו אוסר זאת.

**`append` אינה אצווה.** N קלטים, פלט **אחד**: הלולאה של שאר תת-הפקודות — תוצאה אחת
לכל קובץ, וכישלון שמניח לאחרים להמשיך — חסרת משמעות כאן. שלושה דברים נובעים מכך:

- **היעד הוא `--output`, ולא דבר אחר.** `--output-dir` ו-`--in-place` אינם קיימים
  ב-`append` ונדחים כמו כל אפשרות לא מוכרת, קוד `1`; וכך גם `--recursive`: סדר
  הקבצים הוא הסדר שניתן, ולעץ שנסרק אין סדר;
- **הכול או כלום**: הקובץ הראשון שאי אפשר לקרוא עוצר את ההרצה, ו**דבר אינו נכתב**.
  סרט בשלושה חלקים שאחד מהם חסר אינו סרט בשניים;
- **שורה אחת בלבד לכל הרצה** לתוצאה, וב-JSON, **אובייקט אחד**.

<!-- example: subedit-cli append --help -->
```console
$ subedit-cli append --help
Put subtitle files one after another into a single file
Usage: subedit-cli append [OPTIONS] files...

Positionals:
  files BASE FILE...          The base file, then the files to put after it, in order

Options:
  -h,--help                   Print this help message and exit
  --output FILE               File to write
  --dry-run                   Work out and say what would be written, and write nothing
  --sort                      Put the subtitles in order of their start before writing
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before writing
```

## ארגומנטים ואפשרויות

| אפשרות | חובה | ערכים | ברירת מחדל |
| :----- | :----- | :------ | :----- |
| `<base> <file>...` | כן, **לפחות שניים** | נתיבים: הבסיס, ואחריו מה שמונח אחריו, לפי הסדר | — |
| `--output` | **כן**, מלבד עם `--dry-run` | נתיב קובץ; התיקייה שלו נוצרת אם היא חסרה | — |
| `--dry-run` | לא | דגל: מחשב ואומר, אינו כותב — ראו [לראות לפני שכותבים](invocation.md#לראות-לפני-שכותבים) | כבוי |
| `--sort` | לא | דגל: מסדר את הכול לפי ההתחלות **לאחר שהכול נוסף**, ראו [מיון התוצאה](#מיון-התוצאה) | כבוי |
| `--disjoint` | לא | דגל: חותך את הכתוביות החופפות **לאחר שהכול נוסף ומוין**, ראו [הפיכת הטווחים לזרים](#הפיכת-הטווחים-לזרים) | כבוי |

**היעד אינו יכול להיות אחד מהקלטים**, הבסיס בכלל זה: כתיבה על קובץ שקוראים
נדחית לפני שקוראים דבר, קוד `1`. `--output` קיים השונה מהקלטים
נדרס, כמו בכל מקום.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt
partie2.srt: appended 1 subtitle
partie1.srt: 3 subtitles from 2 files -> film.srt
1
00:00:01,000 --> 00:00:02,000
un

2
00:00:03,000 --> 00:00:04,000
deux

3
00:00:04,500 --> 00:00:05,500
trois
```

הכתובית האחרונה של `partie1.srt` מסתיימת בשנייה 4; זו של `partie2.srt`, שהתחילה בשנייה 0.5, מתחילה
בשנייה 4.5.

## מיון התוצאה

כל קובץ מוזז **מסוף מה שקדם לו**: הסדר שעלול להישבר הוא אפוא סדר הקבצים עצמם. `--sort`
מסדר את התוצאה לפי ההתחלות, **במכה אחת, אחרי ההוספה האחרונה**, כמו ש-[`sort`](sort.md) היה עושה — יציב, בלי לשנות דבר
בתוכן.

לעולם לא כברירת מחדל. עם האפשרות, הבסיס אומר זאת ברמת הקריינות הראשונה, `<base>: N subtitles moved` או `<base>: already in order`, והרשומה
של `--format json` נושאת ספירת `moved`, **חסרה בלי האפשרות**.

## הפיכת הטווחים לזרים

לעולם לא כברירת מחדל. האפשרות עושה מה ש-[`disjoint`](disjoint.md) עושה, **עם הגדרות ברירת המחדל שלו**, לאחר שהכול נוסף, על השלם. היא צריכה קובץ ממוין: אחרת היא נדחית, ו-`--sort` — שבא קודם — מסדר אותו מראש. הקובץ אומר זאת ברמת הקריינות הראשונה (`<path>: N subtitles split, M merged`), והרשומה של `--format json` נושאת את ספירות `split` ו-`merged`, **חסרות בלי האפשרות**.

## כשהפורמטים שונים

התוצאה היא **בפורמט הבסיס**, יהיה אשר יהיה פורמט האחרים. מה שהמעבר עולה
נאמר קובץ אחר קובץ, במילות החלון — אותו משפט כמו ב-`Append File…` וכמו ב-
[הדבקה מפורמט אחר](../subedit-gui/clipboard.md#תגיות-של-פורמט-אחר-מתורגמות):

```text
d.ass: appended 1 subtitle; Advanced SSA into SubRip: 1 tag dropped, the header was dropped
```

מה שאובד תלוי רק בפורמט של **כל** קובץ שנוסף: בסיס ב-Advanced SSA מקבל קובץ
SubRip בלי לאבד דבר, לא להפך. כדי לבחור את פורמט התוצאה, מניחים תחילה קובץ
שכבר בפורמט הזה, או ממירים אחר כך עם [`convert`](convert.md).

## פלט

**הפלט הסטנדרטי** — ריק: התוצאה היא הקובץ שנכתב.

| רמה | מה מתווסף בפלט השגיאה |
| :----- | :------------------------------------- |
| 1 | שורה אחת לכל קובץ שנוסף — `<path>: appended N subtitles`, ואחריה, כשהפורמט עלה במשהו, `; <source format> into <base format>: <what is lost>` — ואז `<base>: N subtitles from M files -> <destination>` (עם `--dry-run`, `(dry run, nothing written)` במקום `-> <destination>`) |
| 2 | `<base>: SubRip, UTF-8, no BOM, LF line endings kept` — הפורמט, הקידוד, הסימן וסוף השורה של הבסיס, מוחזרים כפי שהיו |
| 3 | `<base>: N bytes read, M written` (כל הקבצים יחד), ואחריו **כל אבחוני הקריאה** — ראו [הפעלה](invocation.md#אבחוני-קריאה) |

### ב-JSON

עם [`--format json`](invocation.md#פלט-שסקריפט-יכול-לקרוא), **אובייקט אחד** לכל ההרצה,
ו-`file` שלו הוא **הבסיס**. ה-`counts` שלו:

| ספירה | מה היא אומרת |
| :----- | :----------- |
| `files` | קבצי ההרצה, הבסיס בכלל זה |
| `subtitles` | כתוביות התוצאה |
| `appended` | אלה שבאות מהקבצים שנוספו |
| `lost_ends`, `lost_header` | `0` או `1`: אחד הקבצים שנוספו איבד אותו |
| `joined_lines`, `lost_tags`, `lost_fields` | סכום מה שהקבצים שנוספו איבדו |
| `furthest_ms` | ההזזה הגדולה ביותר של מיקום, כל הקבצים יחד |

**מערך `inputs`** מלווה את ה-`counts`, מחוצה להם: איבר אחד לכל קובץ שנוסף, לפי הסדר,
`{"file", "counts"}` — כש-`counts` נושא `appended`, ואחריו אותם אובדנים, **של אותו קובץ בלבד**. הוא מה
שאומר, בהרצה של עשרה קבצים, איזה מהם עלה במה. אזהרות הקריאה של כל הקבצים
נאספות ב-`warnings`.

גם כישלון הוא אובייקט, **אחד בלבד**: זה של הקובץ הראשון שאי אפשר היה לקרוא.

## קודי יציאה

| קוד | מתי |
| :--- | :---- |
| `0` | התוצאה נכתבה — או חושבה, עם `--dry-run` |
| `1` | שגיאת שימוש: פחות משני קבצים, חסר `--output`, אפשרות שאין ב-`append`, יעד שהוא אחד הקלטים |
| `2` | **קובץ אי אפשר היה לקרוא**, או שאי אפשר היה לכתוב את היעד: דבר אינו נכתב. אין קוד `3`: הרצה שכותבת קובץ אחד בלבד מצליחה או לא |

## שגיאות

| מה מפעיל אותן | הודעה |
| :------------------- | :------ |
| ניתן קובץ אחד בלבד | `append needs a base file and at least one file to put after it` |
| לא `--output` ולא `--dry-run` | `no destination given: append writes one file, use --output` |
| `--output` נוקב בקלט | `<destination>: would be written over the input <input>` |
| קובץ חסר, שאי אפשר לקרוא או שפורמטו לא מוכר | `<path>: does not exist`, `<path>: is in no format this tool knows`… — כמו בכל מקום |

**קובץ ריק אינו נוסף**: שום פורמט אינו נקרא בלי כתובית אחת לפחות, והקובץ
נדחה כמו כל קובץ שאי אפשר לקרוא — `<path>: holds nothing recognisable as a subtitle` —, מה
שעוצר את ההרצה ואינו כותב דבר.
