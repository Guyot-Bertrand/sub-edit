# `framerate`

<!-- machine-translated -->
> דף זה הוא תרגום מכונה שעדיין לא נבדק על ידי דובר השפה.

> **זו אינה [`snap`](snap.md).** הפקודה הזו **משנה את קנה המידה של הקובץ**: היא נועדה למקרה שהתזמון שגוי וסוטה בכמה שניות עד סוף הסרט. `snap` מחזירה את חותמות הזמן אל הרשת הקרובה ביותר בלי לתזמן דבר מחדש, והיא נועדה למקרה שהתזמון כבר נכון. לשתיהן אותה צורה, קצב פריימים אחד או שניים, ובלבול ביניהן אינו גורם לשום שגיאה.

```
subedit-cli framerate --from <fps> --to <fps>
                      (--output FILE | --output-dir DIR | --in-place)
                      [--dry-run]
                      [--recursive]
                      <file>...
```

הפקודה מתזמנת מחדש קובץ שתוזמן לקצב פריימים אחד אל קצב אחר. זו הפעולה שקובץ כתוביות דורש כשנבחר עבור עותק שאינו זה של הסרט שבידי המשתמש — למשל תקליטור DVD בתקן PAL מול העברה בתקן NTSC.

הפורמט של הקובץ שנקרא **נשמר**: שינוי פורמט הוא עבודתה של [`convert`](convert.md).

<!-- example: subedit-cli framerate --help -->
```console
$ subedit-cli framerate --help
Re-time a file mastered at one frame rate for another
Usage: subedit-cli framerate [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to re-time

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --from TEXT REQUIRED        Frame rate the file is timed at: 25, 23.976
  --to TEXT REQUIRED          Frame rate to time it for: 24, 29.97
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## ארגומנטים ואפשרויות

| אפשרות | חובה | ערכים | ברירת מחדל |
| :----- | :----- | :------ | :----- |
| `<file>...` | כן | נתיב אחד או יותר | — |
| `--recursive`, `-r` | לא | דגל | כבוי — ראו [עיבוד עץ קבצים](lots.md) |
| `--from` | **כן** | קצב פריימים, ראו בהמשך | — |
| `--to` | **כן** | קצב פריימים, ראו בהמשך | — |
| `--output` / `--output-dir` / `--in-place` | **אחת משלוש**, פרט ל-`--dry-run` | ראו [הפעלה](invocation.md#היעד) | — |
| `--dry-run` | לא | דגל: מחשב ומדווח, לא כותב דבר — ראו [לראות לפני שכותבים](invocation.md#לראות-לפני-שכותבים) | כבוי |

`--from` הוא קצב הפריימים שהקובץ **מתוזמן** לו, ו-`--to` הוא הקצב שרוצים אליו. החלפה ביניהם מזיזה את הקובץ לכיוון ההפוך — בערך שבע שניות בסרט באורך מלא בין 25 ל-23.976 — ושום דבר אינו מתריע על כך לפני שצופים בסרט.

## איך כותבים קצב פריימים

בפריימים לשנייה, כולל ספרות עשרוניות, עם נקודה כמפריד:

```
25      24      23.976      29.97      60
```

**קצב פריימים אפס או שלילי נדחה**: זה אינו קצב פריימים.

### שלושת קצבי הפריימים של NTSC אינם ניתנים לכתיבה מדויקת

`23.976`, `29.97` ו-`59.94` הם **תוויות**. קצבי הפריימים שהן מציינות הם `24000/1001`, `30000/1001` ו-`60000/1001`, ואין לאף אחד מהם כתיבה עשרונית סופית. הכלי מזהה אותם ככאלה:

| מה כתוב | מה הוא מציין |
| :------------- | :------------------ |
| `23.976` | `24000/1001` — קולנוע שהועבר לווידאו NTSC |
| `24` | `24` — קולנוע |
| `25` | `25` — וידאו PAL ו-SECAM |
| `29.97` | `30000/1001` — וידאו NTSC |
| `30`, `50`, `60` | הם עצמם |
| `59.94` | `60000/1001` |

הזיהוי נוגע ל**ערך ולא לאותיות**: `23.9760` מציין את אותו קצב פריימים כמו `23.976`.

כל ערך עשרוני אחר נלקח כפשוטו — `23.9` אינו תקן של אף אחד, ואין מה לקרוא בו. זה גם מה שהופך את הטבלה שלמעלה לנחוצה: בלעדיה `23.976` היה `23976/1000`, ושורת הפקודה הייתה אומרת דבר אחר מהחלון על אותן מילים.

## מה קורה למיקומים

```
t′ = round( t × (from / to) )
```

סרט שנעשה לו מאסטר ב-23.976 ומנוגן ב-25 פריימים לשנייה רץ מהר יותר, ולכן הכתוביות שלו מגיעות מוקדם יותר; בכיוון ההפוך הן מגיעות מאוחר יותר.

**הגורם הוא שבר מדויק, והעיגול מתבצע פעם אחת בלבד.** הדרך שנראית שקולה — המרת המיקום למספר פריים בקצב הקלט, ואז בחזרה לאלפיות שנייה בקצב הפלט — אינה כזו: היא מכמתת כל מיקום על רשת הקלט וטועה עד חצי פריים, 21 אלפיות שנייה במדידה. ראו [ADR 0013](../../../../adr/0013-mise-a-l-echelle-exacte-des-positions.md).

בפועל, מ-25 ל-23.976 הגורם הוא `1001/960`:

| מיקום שנקרא | נכתב | מה שהמעבר דרך הפריימים היה נותן |
| -----------: | -----: | -----------------------------------------: |
| `1 010 ms` | `1 053 ms` | `1 043 ms` |
| `3 600 017 ms` | `3 753 768 ms` | `3 753 750 ms` |

<!-- example: printf '1\n00:00:01,010 --> 00:00:02,020\nUn.\n\n' > a.srt; subedit-cli framerate --from 25 --to 23.976 --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:01,010 --> 00:00:02,020\nUn.\n\n' > a.srt; subedit-cli framerate --from 25 --to 23.976 --output b.srt a.srt; cat b.srt
a.srt: 1 subtitle retimed from 25 to 24000/1001 fps -> b.srt
1
00:00:01,053 --> 00:00:02,106
Un.
```

## פלט

**פלט סטנדרטי** — ריק: התוצאה היא הקובץ שנכתב. גם עם `--dry-run` ריק: אין קובץ, ושורת הדיווח אומרת זאת — ראו [לראות לפני שכותבים](invocation.md#לראות-לפני-שכותבים).

| רמה | מה נוסף בפלט השגיאות |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles retimed from 25 to 24000/1001 fps -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — הפורמט, הקידוד, הסימן וסוף השורה של הקובץ שנקרא, מוחזרים כפי שהיו |
| 3 | `<path>: N bytes read, M written`, ואחריו **כל אבחוני הקריאה** — ראו [הפעלה](invocation.md#אבחוני-קריאה) |

**שורת הדיווח מציינת את קצב הפריימים המדויק, לא את התווית שהוקלדה.** כתיבת `23.976` בשורה הזו הייתה מדווחת על המרה שלא התרחשה; זהו המקום היחיד שבו רואים מי משני הקצבים שימש. קצב פריימים שכתיבה עשרונית מציינת במדויק מוצג שם כעשרוני, והאחרים כשבר.

### ב-JSON

עם [`--format json`](invocation.md#פלט-שסקריפט-יכול-לקרוא), האובייקט של כל קובץ נושא את `counts.subtitles` (כל כתובית בקובץ). הטבלה המלאה נמצאת ב[הפעלה](invocation.md#מה-כל-תת-פקודה-מציבה-ב-counts).

## קודי יציאה

אלו של הכלי: `0` אם כל הקבצים נכתבו, `2` אם אף אחד לא נכתב, `3` אם רק חלקם נכתבו, `1` בשגיאת שימוש.

שום סירוב אינו תלוי בתוכן של קובץ: שני קצבי פריימים מגדירים תמיד גורם. זוהי תת-הפקודה היחידה מבין אלה שכותבות שכל סירוביה באים לפני הקריאה הראשונה.

<!-- example: printf '1\n00:00:01,010 --> 00:00:02,020\nUn.\n\n' > a.srt; subedit-cli framerate --from 0 --to 25 --output b.srt a.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:01,010 --> 00:00:02,020\nUn.\n\n' > a.srt; subedit-cli framerate --from 0 --to 25 --output b.srt a.srt; echo "code=$?"
"0" is not a frame rate: a frame rate must be strictly positive; nothing runs at that speed
code=1
```

## שגיאות

| מה גורם לה | הודעה |
| :------------------ | :------ |
| קצב פריימים אפס או שלילי | `"…" is not a frame rate: a frame rate must be strictly positive; nothing runs at that speed` |
| פסיק עשרוני | `"…" is not a frame rate: use a decimal point and not a comma, in every language` |
| טקסט שאינו מספר | `"…" is not a frame rate: expected frames per second, like 25 or 23.976` |
| קצב פריימים מופרז | `"…" is not a frame rate: no video runs at that many frames per second` |

**דבר אינו נכתב בלי אחת משלוש אפשרויות היעד**, והשגיאות שלהן משותפות לתת-הפקודות שכותבות: ראו [הפעלה](invocation.md#היעד).
