# התקנה

<!-- machine-translated -->
> דף זה הוא תרגום מכונה שעדיין לא נבדק על ידי דובר השפה.

**הדף הזה תקף לשתי התוכנות** — `subedit-cli` ו-`subedit-gui`. הן נבנות ומותקנות יחד.

שתי דרכים: **חבילה מקורית**, `.deb` או `.rpm`, או **בנייה מקוד המקור**, שמתקינה אז היכן שרוצים.

## החבילות

שתיהן מופקות על ידי CPack מתוך **אותם כללי התקנה**: הן מציבות את אותם קבצים באותם מקומות, ונבדלות רק בשמות החבילות שהן תלויות בהן — אותן ספריות נקראות בשם אחר ב-Debian וב-Fedora.

```bash
sudo apt install ./subedit_<version>_amd64.deb      # Debian, Ubuntu
sudo dnf install ./subedit-<version>.x86_64.rpm     # Fedora, and relatives
```

| מה החבילה מתקינה | היכן |
| :---------------------- | :-- |
| `subedit-cli`, `subedit-gui` | `/usr/bin` |
| פריט התפריט, הסמל, המטא-נתונים של מרכז התוכנות | `/usr/share/applications`, `/usr/share/icons`, `/usr/share/metainfo` |
| המדריך הזה, ב-Markdown | `/usr/share/subedit/manual` |
| תרגומו לכל שפה מותקנת — קטלאנית, צ׳כית, גרמנית, ספרדית, פינית, צרפתית, גליסית, עברית, הונגרית, אינטרלינגה | `/usr/share/subedit/manual/<language>` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie` |
| תבניות התיקון של Gaupol | `/usr/share/subedit/patterns` |
| דפי ה-man של `subedit-cli`, אחד לכל תת-פקודה, ושל `subedit-gui` — ראו [דפי ה-man](invocation.md#דפי-ה-man) | `/usr/share/man/man1` |
| דפי `subedit-cli` בכל שפה מותקנת — קטלאנית, צ׳כית, גרמנית, ספרדית, פינית, צרפתית, גליסית, עברית, הונגרית, אינטרלינגה | `/usr/share/man/<language>/man1` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie` |

`ffmpeg` **מומלצת ואינה חובה** בשתי החבילות: בלעדיה החלון רק מפסיק להציע את קצב הפריימים שהסרט מצהיר עליו — ראו [מה `ffmpeg` משנה](../subedit-gui/video.md#ffmpeg-אינו-חובה).

### מה החבילות דורשות מההפצה

**מתקינים עם `apt` או `dnf`, לעולם לא עם `dpkg -i` או `rpm -i`.** שתי הפקודות האלה מניחות את החבילה בלי לפתור את התלויות שלה: הן רק מונות את החסרות, ועוצרות. זו התשובה של `rpm -i` ב-Fedora שיש בה כל מה שנחוץ בהישג יד של `dnf`:

```console
$ rpm -i subedit-0.13.0-1.fc43.x86_64.rpm
error: Failed dependencies:
        libicui18n.so.77()(64bit) is needed by subedit-0.13.0-1.fc43.x86_64
        libicuuc.so.77()(64bit) is needed by subedit-0.13.0-1.fc43.x86_64
```

`sudo dnf install ./subedit-<version>-1.fc43.x86_64.rpm` מביאה את הספריות האלה, היכן שהן קיימות.

**ה-`.rpm` שיש לקחת הוא זה של ה-Fedora שלכם**: שם הקובץ נושא את הגרסה, `fc42`, `fc43`, `fc44`. כל אחד נבנה על אותה Fedora, מול ה-ICU שלה — `cat /etc/fedora-release` אומרת איזה לקחת. `.rpm` מ-Fedora אחרת מבקש ICU שאין לכם.

| תלות | `.deb` | `.rpm` | אילוץ |
| :--------- | :----- | :----- | :--------- |
| Qt 6: `Widgets`, `Gui`, `Core` | `libqt6widgets6`, `libqt6gui6`, `libqt6core6` | `qt6-qtbase-gui` | **≥ 6.4**, בשביל החלון |
| libmpv | `libmpv2` או `libmpv1` | `mpv-libs` | הקובץ הבינארי מקשר את `libmpv.so.2` |
| Enchant 2 | `libenchant-2-2` | `enchant2` | בודק האיות, ומשימות `join-words` ו-`split-words` של [`correct`](correct.md) |
| **ICU** | **`libicu74`** | `libicu`, כלומר `libicuuc.so.N` ו-`libicui18n.so.N` **של ה-Fedora שבנתה אותה** | **הגרסה שיש ל-Fedora של ה-`.rpm`**, בדיוק — ראו בהמשך |
| glibc ו-libstdc++ | — | — | **חדשות מספיק**: אלה של Ubuntu 24.04 עבור ה-`.deb`, אלה של ה-Fedora של ה-`.rpm` עבורו |

**ICU הוא האילוץ שחשוב, ואי אפשר להקל בו על ידי שינוי שורה בחבילה.** הסמלים של ICU נושאים את מספר הגרסה הראשית שלה (`u_strToUTF8_74`): קובץ בינארי שנבנה מול ICU 74 אינו יכול להתקשר ל-ICU 76 או 77. תלות שנכתבת רחב יותר הייתה מאפשרת לחבילה להותקן ואז להיכשל בהפעלה — הצהרה מדויקת היא שנשארת ישרה. **לכן ה-`.rpm` אינו נבנה פעם אחת, אלא על כל Fedora שפורסמה**, מול ה-ICU שלה; ה-`.deb` נבנה על Ubuntu 24.04.

| הפצה | מה היא נותנת |
| :----------- | :---------------- |
| Ubuntu 24.04 | ה-`.deb` מותקן: ה-ICU שם בגרסה 74 |
| Fedora 42, 43, 44 | ה-`.rpm` של הגרסה שלה (`…fc42…`, `…fc43…`, `…fc44…`) מותקן **דרך `dnf`**, ונבנה מול ה-ICU של אותה Fedora |
| Fedora rawhide (הבאה), שאר הפצות ה-`.rpm` | **לא**: לא נבנה עבורן `.rpm` — בונים מקוד המקור |
| כל הפצת Debian או Ubuntu שה-ICU שלה אינו בגרסה 74 | **לא**: ה-`.deb` דורש `libicu74` — בונים מקוד המקור |

**בנייה מקוד המקור היא הברירה האחרונה, ואין בה את האילוץ הזה**: היא מתקשרת ל-ICU של המחשב, יהיה אשר יהיה. היא גם מה שנחוץ בהפצה ש-glibc שלה ישנה יותר מזו של החבילות.

### מה נבדק בכל אחת, ומה לא

**השתיים אינן נבדקות עד אותה נקודה, וטוב לומר זאת מאשר לתת להאמין בשוויון שאינו קיים.** הפיתוח נעשה על Ubuntu; `.rpm` שנבנה שם אינו יכול להיות מותקן שם. הוא מותקן במקום אחר: על Fedora בקונטיינר, פעם בשבוע.

| | `.deb` | `.rpm` |
| :--- | :----- | :----- |
| רשימת הקבצים | נבדקת | נבדקת, ו**מושווית לזו של ה-`.deb`** |
| התלויות המוצהרות | נבדק שהן קיימות | נבדק שהן קיימות |
| ששמות התלויות קיימים בהפצה | כן, הם של Ubuntu | **כן**, נפתרים על ידי `dnf` |
| שהחבילה מותקנת | לא — זה דורש הרשאות מנהל | **כן**, על Fedora בקונטיינר |
| שהקבצים הבינאריים המותקנים עולים | כן, מקידומת זמנית | **כן**, מהחבילה המותקנת |

**בדיקת ה-Fedora בודקת את ה-`.rpm` שנבנה על Ubuntu, לא את אלה שמפורסמים.** לתמונה הזו אין ICU 74 משלה: החבילה מותקנת שם כי ל-Fedora יש `libicu74` לתאימות, והבדיקה הייתה ירוקה כל עוד החבילה הזו קיימת. קובצי ה-`.rpm` המפורסמים נבנים על ה-Fedora שלהם, ואינם תלויים עוד בתאימות הזו. ראו [מה החבילות דורשות](#מה-החבילות-דורשות-מההפצה).

**השוואת שתי הרשימות היא הבדיקה החשובה ביותר.** שתי החבילות יוצאות מאותה התקנה: פער ביניהן היה פגם בכללי ההתקנה, לא בפורמט.

**מה שה-`.deb` עדיין אינו מוכיח הוא שהוא מותקן**, והסיבה לא השתנתה: `dpkg -i` דורש הרשאות מנהל, שלשער איכות אין ואסור לו לבקש. ה-`.rpm`, לעומת זאת, מותקן בקונטיינר שאינו שייך לאיש. ראו [ADR 0023](../../../../adr/0023-deb-et-rpm-pour-la-premiere-livraison.md).

**Flatpak ו-AppImage אינם מוצעים**, וזו בחירה — לא השמטה. היא מוסברת באותו ADR, והיא **סופית**: הפצה שאינה לא ממשפחת Debian ולא ממשפחת Fedora בונה מקוד המקור, מה שהסעיף הבא מתאר במלואו.

## בנייה מקוד המקור

### דרישות קדם

| מה נחוץ | בשביל מה | Debian, Ubuntu |
| :------------ | :------- | :------------- |
| CMake ≥ 3.28 | הבנייה | `cmake` |
| מהדר C++23 — GCC 13 מספיק | — | `g++` |
| `make`, `pkg-config` | הבנייה | `make`, `pkg-config` |
| CLI11 | קריאת שורת הפקודה | `libcli11-dev` |
| Qt 6 ≥ 6.4, מודול `Widgets` | החלון | `qt6-base-dev` |
| `libmpv` | הנגן המובנה | `libmpv-dev` |
| ICU | קריאת הקידודים | `libicu-dev` |
| Enchant 2 | ספריית בודק האיות | `libenchant-2-dev` |

**ארבעת האחרונים נחוצים גם כדי לבנות רק את `subedit-cli`**: תצורת CMake מחפשת אותם עבור הפרויקט כולו, ועוצרת אם הם חסרים. ICU ו-Enchant נחוצים פעמיים — קובץ ההרצה טוען אותם, אחד כדי להמיר את הקידודים והאחר בשביל בודק האיות — והם ספריות הצד השלישי היחידות שהוא טוען בזמן ריצה.

**חיבור לרשת בהרצת `cmake` הראשונה**: ספריית הבדיקות Catch2 נמשכת מ-GitHub בעת התצורה. היא אינה מורדת שוב לאחר מכן. כדי לבנות את הכלי בלבד, בלי רשת, ראו בהמשך.

#### מה אינו חובה

| מה אופציונלי | מה אובד בלעדיו |
| :-------------------- | :--------------------- |
| `ffmpeg`, בשביל `ffprobe` שלה | החלון אינו מציע עוד את קצב הפריימים שהסרט מצהיר עליו — [הפרטים](../subedit-gui/video.md#ffmpeg-אינו-חובה) |
| שרת תצוגה | דבר ב-`subedit-cli`; `subedit-gui` זקוק לאחד כדי להציג את עצמו |

### בנייה

```bash
git clone git@github.com:Guyot-Bertrand/sub-edit.git subedit
cd subedit
make build
```

הקבצים הבינאריים מופקים ב-`build/dev/bin/` — `subedit-cli` ו-`subedit-gui`.

לגרסה מיטבית:

```bash
make release
```

שני הקבצים הבינאריים נמצאים אז ב-`build/release/bin/` — `subedit-cli` ו-`subedit-gui`. היעד אינו בונה דבר נוסף: לא את מדד הביצועים, ולא את ערכת הבדיקות מקצה לקצה, שיש להם יעדים משלהם.

**העדיפו את היעד הזה על פני שתי פקודות `cmake` שקולות**, שאינן יודעות כמה תהליכים אופטימיזציית זמן הקישור רשאית להפעיל: בכל קישור היא מפעילה כמספר הליבות. `make release` מעביר לה את `JOBS`, כמו לשאר הבנייה.

### ביצוע ההתקנה

```bash
make release
cmake --install build/release --prefix ~/.local
```

מה שמותקן, בנתיבים ש-`GNUInstallDirs` קובעת עבור הקידומת שנבחרה:

| קובץ | היכן |
| :------ | :-- |
| `subedit-cli`, `subedit-gui` | `<prefix>/bin` |
| פריט תפריט שולחן העבודה | `<prefix>/share/applications` |
| הסמל | `<prefix>/share/icons/hicolor/scalable/apps` |
| המטא-נתונים של מרכז התוכנות | `<prefix>/share/metainfo` |
| המדריך הזה, ב-Markdown | `<prefix>/share/subedit/manual` |
| תרגומו לכל שפה מותקנת — קטלאנית, צ׳כית, גרמנית, ספרדית, פינית, צרפתית, גליסית, עברית, הונגרית, אינטרלינגה | `<prefix>/share/subedit/manual/<language>` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie` |
| תבניות התיקון של Gaupol | `<prefix>/share/subedit/patterns` |
| דפי ה-man של שני הקבצים הבינאריים, אחד לכל תת-פקודה עבור `subedit-cli` | `<prefix>/share/man/man1` |
| דפי `subedit-cli` בכל שפה מותקנת — קטלאנית, צ׳כית, גרמנית, ספרדית, פינית, צרפתית, גליסית, עברית, הונגרית, אינטרלינגה | `<prefix>/share/man/<language>/man1` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie` |

**אלה אותם קבצים שהחבילות מתקינות**: החבילות יוצאות מהם, ולא מתוארות פעם שנייה.

עם `--prefix ~/.local`, שני הקבצים הבינאריים נוחתים ב-`~/.local/bin`, שנמצא ב-`PATH` של רוב ההפצות. קידומת מערכת — `/usr/local`, למשל — דורשת את ההרשאות המתאימות.

**פריט תפריט שהונח תחת `~/.local` אינו מופיע תמיד מיד**: שולחנות עבודה קוראים מחדש את המטמון שלהם בקצב שלהם. `subedit-gui` עולה מטרמינל בינתיים, כמו כל פקודה אחרת.

`DESTDIR` נתמך, מה שמי שמארז חבילות מצפה לו: התקנה בשלבים אינה נוגעת בדבר מחוץ לתיקיית השלבים.

```bash
DESTDIR=/tmp/scene cmake --install build/release --prefix /usr
```

### בניית הכלי לבדו

הבדיקות נבנות כברירת מחדל, והן מה שמבקש את הרשת — `make release` אינה בונה אותן, אבל היא מגדירה את הפרויקט, והתצורה היא שמושכת את Catch2. די לכבות אותן פעם אחת: ההגדרה נשארת במטמון של CMake, והבניות הבאות שומרות עליה.

```bash
cmake --preset release -DSUBEDIT_BUILD_TESTS=OFF
make release
```

זה אינו פוטר את התורם מדבר: שער האיכות כן דורש אותן.

### אם הבנייה נכשלת בשלב הקישור

מפל של "undefined reference to `std::cout`" בקוד תקין פירושו בדרך כלל שהחלופה `c++` של המערכת מצביעה על `gcc` במקום על `g++`: ה-C++ מתקמפל, אבל ספריית התקן אינה מקושרת.

```bash
ls -l /etc/alternatives/c++                                       # check
sudo update-alternatives --install /usr/bin/c++ c++ /usr/bin/g++ 100   # fix
CXX=g++ make build                                                # work around
```

תצורת CMake מזהה את המקרה הזה ועוצרת עם ההודעה הזו במקום לתת לקישור להיכשל.

### אם התקנת החבילה מתלוננת על `libicu`

```console
error: Failed dependencies:
        libicuuc.so.74()(64bit) is needed by subedit-<version>.x86_64
```

שלוש סיבות, המובחנות לפי הפקודה שהוקלדה ולפי שם הקובץ:

- **`rpm -i`**: היא אינה פותרת דבר. נסו שוב עם `sudo dnf install ./subedit-<version>.fcNN.x86_64.rpm`;
- **`.rpm` בלי `fcNN` בשמו**, או מ-Fedora שאינה שלכם: הוא מבקש את ה-ICU של המחשב שבנה אותו. קחו את זה ש-`fcNN` שלו הוא הפלט של `cat /etc/fedora-release`;
- **אין `.rpm` לגרסה שלכם**: Fedora rawhide או הפצה אחרת. אף חבילה של המאגר הזה לא תותקן שם; [בונים מקוד המקור](#בנייה-מקוד-המקור).
