# `append`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli append --output FILE
                   [--dry-run] [--sort] [--disjoint]
                   <base> <file>...
```

Ставит файлы **после первого** в **один** файл: фильм из двух частей превращается в
один набор субтитров. Это `Append File…` из окна — [тот же движок](../subedit-gui/operations.md#append-file),
те же счётчики, — применяемое столько раз, сколько файлов нужно добавить.

- **Первый файл — основа.** От него результат получает **формат, кодировку, метку порядка
  байтов и символы конца строки**.
- **Между двумя файлами ничего не вставляется**: каждый файл сдвигается на **конец последнего субтитра того, что
  ему предшествует**, а его позиции сохраняют порядок и интервалы. Третий файл идёт за вторым, а не
  за основой: файлы следуют друг за другом в том порядке, в каком указаны.
- **Каждый добавляемый файл проходит преобразование** в формат основы: его теги преобразуются,
  а то, что этот формат записать не может, сообщается по каждому файлу теми же словами, что и в окне.
- **У добавляемых файлов нет перевода**: у файла, открытого отдельно, его нет.
- **Файл можно указать несколько раз** или добавить к самому себе: ничто этого не запрещает.

**`append` — не пакетная обработка.** N входных файлов, **один** выходной: цикл остальных подкоманд — один результат
на файл и неудача, после которой остальные продолжают обрабатываться, — здесь не имеет смысла. Отсюда три следствия:

- **место назначения — это `--output` и ничто другое.** `--output-dir` и `--in-place` для
  `append` не существуют и отклоняются как любой неизвестный параметр, код `1`; `--recursive` тоже: порядок
  файлов — тот, в каком они указаны, а у обойденного дерева его нет;
- **всё или ничего**: первый же файл, который не удалось прочитать, останавливает запуск, и **ничего не
  записывается**. Фильм из трёх частей, одной из которых нет, — это не фильм из двух;
- **одна строка на запуск** для результата и, в JSON, **один объект**.

<!-- example: subedit-cli append --help -->
```console
$ subedit-cli append --help
Put subtitle files one after another into a single file
Usage: subedit-cli append [OPTIONS] files...

Positionals:
  files BASE FILE...          The base file, then the files to put after it, in order

Options:
  -h,--help                   Print this help message and exit
  --output FILE               File to write
  --dry-run                   Work out and say what would be written, and write nothing
  --sort                      Put the subtitles in order of their start before writing
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before writing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<base> <file>...` | да, **не менее двух** | пути: основа, затем то, что ставится после неё, по порядку | — |
| `--output` | **да**, кроме случая с `--dry-run` | путь к файлу; его каталог создаётся, если отсутствует | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выкл. |
| `--sort` | нет | флаг: упорядочивает всё по началу **после добавления всех файлов**, см. [Сортировка результата](#сортировка-результата) | выкл. |
| `--disjoint` | нет | флаг: обрезает перекрывающиеся субтитры **после добавления всех файлов и сортировки**, см. [Устранение перекрытий диапазонов](#устранение-перекрытий-диапазонов) | выкл. |

**Местом назначения не может быть ни один из входных файлов**, включая основу: запись поверх читаемого
файла отклоняется до того, как что-либо прочитано, код `1`. Существующий `--output`, отличный от входных файлов,
перезаписывается, как и везде.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n' > partie1.srt; printf '1\n00:00:00,500 --> 00:00:01,500\ntrois\n\n' > partie2.srt; subedit-cli append --output film.srt partie1.srt partie2.srt; cat film.srt
partie2.srt: appended 1 subtitle
partie1.srt: 3 subtitles from 2 files -> film.srt
1
00:00:01,000 --> 00:00:02,000
un

2
00:00:03,000 --> 00:00:04,000
deux

3
00:00:04,500 --> 00:00:05,500

```

Последний субтитр файла `partie1.srt` заканчивается на 4 с; субтитр файла `partie2.srt`, который начинался на 0,5 с, начинается
на 4,5 с.

## Сортировка результата

Каждый файл сдвигается **от конца того, что ему предшествует**, поэтому порядок может нарушиться только между самими файлами. `--sort`
упорядочивает результат по началу, **за один проход, после последнего добавления**, как это сделала бы подкоманда [`sort`](sort.md) — устойчиво и без изменения
содержимого.

Никогда по умолчанию. С этим параметром основа сообщает об этом на первом уровне пояснений: `<base>: N subtitles moved` или `<base>: already in order`, а
запись `--format json` содержит счётчик `moved`, **отсутствующий без параметра**.

## Устранение перекрытий диапазонов

Никогда по умолчанию. Параметр делает то, что делает [`disjoint`](disjoint.md), **с его настройками по умолчанию**, после добавления всех файлов, над всем результатом. Ему нужен упорядоченный файл: иначе он отклоняется, а `--sort`, который выполняется первым, предварительно наводит порядок. Файл сообщает об этом на первом уровне пояснений (`<path>: N subtitles split, M merged`), а запись `--format json` содержит счётчики `split` и `merged`, **отсутствующие без параметра**.

## Когда форматы различаются

Результат записывается в **формате основы**, каким бы ни был формат остальных. То, что стоит такое преобразование,
сообщается по каждому файлу теми же словами, что и в окне, — той же фразой, что у `Append File…` и у
[вставки из другого формата](../subedit-gui/clipboard.md#теги-другого-формата-преобразуются):

```text
d.ass: appended 1 subtitle; Advanced SSA into SubRip: 1 tag dropped, the header was dropped
```

Что теряется, зависит только от формата **каждого** добавляемого файла: основа в Advanced SSA принимает
файл SubRip без потерь, но не наоборот. Чтобы выбрать формат результата, поставьте первым файл,
который уже в этом формате, или потом преобразуйте результат подкомандой [`convert`](convert.md).

## Вывод

**Стандартный вывод** — пусто: результат — записанный файл.

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | по одной строке на каждый добавляемый файл — `<path>: appended N subtitles`, за которой, если формат что-то стоил, следует `; <source format> into <base format>: <what is lost>` — затем `<base>: N subtitles from M files -> <destination>` (с `--dry-run` вместо `-> <destination>` стоит `(dry run, nothing written)`) |
| 2 | `<base>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки основы, возвращённые как были |
| 3 | `<base>: N bytes read, M written` (все файлы вместе), затем **все диагностические сообщения чтения** — см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) выводится **один объект** на весь запуск,
в поле `file` которого стоит **основа**. Его `counts`:

| Счётчик | Что он сообщает |
| :----- | :----------- |
| `files` | файлы запуска, включая основу |
| `subtitles` | субтитры результата |
| `appended` | те, что пришли из добавляемых файлов |
| `lost_ends`, `lost_header` | `0` или `1`: один из добавляемых файлов это потерял |
| `joined_lines`, `lost_tags`, `lost_fields` | сумма того, что потеряли добавляемые файлы |
| `furthest_ms` | наибольшее смещение позиции среди всех файлов |

**Массив `inputs`** идёт вместе с `counts`, но вне него: по одному элементу на каждый добавляемый файл, по порядку,
`{"file", "counts"}` — в `counts` лежат `appended`, затем те же потери, **только для этого файла**. Он
показывает, в запуске из десяти файлов, какой из них что стоил. Предупреждения чтения всех файлов
собираются в `warnings`.

Неудача — тоже объект, **один**: объект первого файла, который не удалось прочитать.

## Коды завершения

| Код | Когда |
| :--- | :---- |
| `0` | результат записан — или вычислен, с `--dry-run` |
| `1` | ошибка использования: меньше двух файлов, нет `--output`, параметр, которого у `append` нет, место назначения совпадает с одним из входных файлов |
| `2` | **файл не удалось прочитать** или не удалось записать место назначения: ничего не записывается. Кода `3` нет: запуск, который записывает единственный файл, либо успешен, либо нет |

## Ошибки

| Что их вызывает | Сообщение |
| :------------------- | :------ |
| указан единственный файл | `append needs a base file and at least one file to put after it` |
| ни `--output`, ни `--dry-run` | `no destination given: append writes one file, use --output` |
| `--output` называет входной файл | `<destination>: would be written over the input <input>` |
| файл отсутствует, нечитаем или в неизвестном формате | `<path>: does not exist`, `<path>: is in no format this tool knows`… — те же, что везде |

**Пустой файл не добавляется**: ни один формат не читается без хотя бы одного субтитра, и файл
отклоняется, как любой файл, который не удаётся прочитать, — `<path>: holds nothing recognisable as a subtitle` —, что
останавливает запуск и ничего не записывает.
