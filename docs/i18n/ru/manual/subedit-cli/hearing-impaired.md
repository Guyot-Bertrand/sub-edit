# `hearing-impaired`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli hearing-impaired
                  (--output FILE | --output-dir DIR | --in-place)
                  [--dry-run]
                  [--recursive] [--parentheses]
                  [--document main|translation] [-t FILE] [--align-method position|number]
                  <file>...
```

Удаляет из всего файла **пометки для слабослышащих** — звуки, описанные в квадратных
скобках. **Круглые скобки по умолчанию остаются**: их так же часто используют для реплики,
произнесённой шёпотом, как и для описанного звука, и их удаление стёрло бы диалог. `--parentheses` удаляет
и их, для файла, который описывает звуки в круглых скобках.

Чего эта подкоманда не делает: слова песен между знаками решётки, имя говорящего
перед двоеточием, повторное написание заглавных букв, исправление ошибок распознавания. Эти
шаблоны относятся к мастеру
[`Correct Texts…`](../subedit-gui/correct-texts.md) в окне, который командная
строка предлагает под именем [`correct`](correct.md); а здесь ничего настроить нельзя: преобразование
жёстко задано и не настраивается.

<!-- example: subedit-cli hearing-impaired --help -->
```console
$ subedit-cli hearing-impaired --help
Remove the sounds described between square brackets
Usage: subedit-cli hearing-impaired [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to clean

Options:
  -h,--help                   Print this help message and exit
  --parentheses               Also remove the sounds between parentheses, often whispered lines
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --document main|translation The document to change: the main one, or the translation given by -t
  -t,--translation-file FILE  Translation file to lay over the subtitle file, for a single input
  --align-method position|number
                              How the lines of the translation find their subtitles
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--parentheses` | нет | флаг: удаляет также пометки в круглых скобках | выключен |
| `--recursive`, `-r` | нет | флаг | выключен — см. [Обработка дерева каталогов](lots.md) |
| `--document` | нет | `main` или `translation` — см. [Перевод](invocation.md#перевод) | `main` |
| `-t`, `--translation-file` | при `--document translation` | файл перевода, для **одного** входного файла | — |
| `--align-method` | нет, и только вместе с `-t` | `position` или `number` | `position` |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

Формат прочитанного файла **сохраняется**: смена формата — задача
[`convert`](convert.md).

**По умолчанию изменяется основной текст; перевод — с `--document translation -t FILE`.** Тогда
изменяется и записывается перевод, и только он — см. [Перевод](invocation.md#перевод).

**Если из-за пометки перевод становится пустым, он записывается пустым, а субтитр сохраняется**: субтитр
остаётся в файле, без текста. Основной текст, напротив, теряет полностью опустошённый субтитр, как
описано ниже.

## Что удаляется, а что остаётся

Пометка — это квадратная скобка (или круглая, с `--parentheses`) и всё, что она заключает, **включая
перевод строки**: в реальных файлах пометку часто разрывает
конец строки.

| Вход | Выход |
| :----- | :----- |
| `Bonjour [il tousse] Marie` | `Bonjour Marie` |
| `Bonjour[il tousse]Marie` | `Bonjour Marie` |
| `[Bruit de pas] Bonjour` | `Bonjour` |
| `A [un] [deux] B` | `A B` |

После удаления между тем, что её окружало, остаётся **ровно один пробел, а на
краю строки — ничего**. Это не очистка пробелов файла: два пробела,
которые уже были в тексте, так и остаются двумя пробелами.

**Когда пометка захватывает перевод строки, остаётся именно он**: две
строки остаются двумя строками. Этот случай не курьёз: в пятнадцати
реальных файлах субтитров каждая квадратная скобка, казавшаяся одинокой, оказывалась
пометкой, разорванной таким образом.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nReculez ! [Il\nhurle] Tout de suite !\n\n' > a.srt; subedit-cli --quiet hearing-impaired --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nReculez ! [Il\nhurle] Tout de suite !\n\n' > a.srt; subedit-cli --quiet hearing-impaired --output b.srt a.srt; cat b.srt
1
00:00:01,000 --> 00:00:03,000
Reculez !
Tout de suite !
```

**Что не является пометкой и не затрагивается:**

| Случай | Что происходит |
| :-- | :-------------- |
| чисто числовое содержимое — `[1]`, `(12)`, `[ 156478 ]` | остаётся как есть вместе с ограничителями: ссылка никогда не называла звук |
| круглая скобка и её содержимое, без `--parentheses` | остаётся как есть: `Venez (chut) ici` не меняется |
| скобка, которую ничто не закрывает | остаётся как есть |
| тег формата — `<i>`, `</i>` | никогда не удаляется |

Пробел **между** цифрами, буква или знак — `[1 2]`, `[1a]`,
`[-1]` — превращают это в пометку. То же относится к пустому содержимому, `[]` или `( )`: нет
цифры, значит, это не ссылка; сказать нечего, значит, и сохранять нечего.

## Что исчезает полностью

**Строка, опустошённая удалением, исчезает**, а **субтитр, полностью
опустошённый, удаляется из файла**. Следующие за ним субтитры перенумеровываются.

Строка считается пустой, когда в ней остались только пробелы, теги формата
или одинокое тире диалога: `<i>[Musique]</i>` не оставляет на экране
`<i></i>`.

**Теги — это теги формата файла.** `{\i1}[Musique]{\i0}` в
Advanced SSA, `{Y:i}[Musique]` в MicroDVD и `/[Musique]` в MPL2 тоже не оставляют
ничего. И наоборот, `<i>` в формате, который не записывает
теги (TMPlayer, LRC), это текст, который читает зритель, и строка, которая
его содержит, не пуста.

**Диалог, сведённый к одному голосу, диалогом быть перестаёт**, и оставшееся тире
удаляется. Пока остаются два голоса, тире сохраняются.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\n[Bruit de pas]\n\n2\n00:00:04,000 --> 00:00:06,000\nAttends [il tousse] Marie.\n\n3\n00:00:07,000 --> 00:00:09,000\nVoir [1] la note.\n\n' > a.srt; subedit-cli hearing-impaired --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\n[Bruit de pas]\n\n2\n00:00:04,000 --> 00:00:06,000\nAttends [il tousse] Marie.\n\n3\n00:00:07,000 --> 00:00:09,000\nVoir [1] la note.\n\n' > a.srt; subedit-cli hearing-impaired --output b.srt a.srt; cat b.srt
a.srt: 1 subtitle cleaned, 1 removed -> b.srt
1
00:00:04,000 --> 00:00:06,000
Attends Marie.

2
00:00:07,000 --> 00:00:09,000
Voir [1] la note.
```

## Файл без единой пометки всё равно записывается

Он копируется без изменений, код завершения равен `0`, а в отчёте говорится, что
удалять было нечего.

Это правило подкоманд, которые записывают: **указанное место назначения —
это место назначения, в которое записывается файл**. Исключение здесь заставило бы скрипт знать,
какие из подкоманд иногда создают файл, а иногда нет.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nRien à signaler.\n\n' > a.srt; subedit-cli hearing-impaired --output b.srt a.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nRien à signaler.\n\n' > a.srt; subedit-cli hearing-impaired --output b.srt a.srt
a.srt: no mention to remove -> b.srt
```

## Вывод

**Стандартный вывод** — пуст: результат — это записанный файл. **С `--dry-run` это предлагаемые изменения**: для каждого субтитра, текст которого изменился бы, его номер, текст до и текст после — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles cleaned, M removed -> <destination>`, или `<path>: no mention to remove -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые в прежнем виде |
| 3 | `<path>: N bytes read, M written`, затем **каждое диагностическое сообщение чтения** — см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

`N` — число субтитров, текст которых изменился, `M` — число тех, которые удаление
опустошило полностью и которые поэтому покинули файл.

### В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит `counts.cleaned` (переписанные тексты) и `counts.removed` (удалённые субтитры); **с `--dry-run`** ключ `changes` дополнительно перечисляет изменённые субтитры, как стандартный вывод текстовой формы. Полная таблица приведена в разделе [Запуск](invocation.md#что-каждая-подкоманда-помещает-в-counts).

## Коды завершения

Коды самой программы: `0`, если записаны все файлы, `2`, если не записан ни один, `3`, если
записаны лишь некоторые, `1` при ошибке использования.

## Ошибки

У этой подкоманды нет собственных ошибок: у неё нет значений,
которые нужно разбирать, и никакой текст не может заставить её отвергнуть файл. Сбой
возможен при чтении или записи, как и у остальных подкоманд.

**Без одного из трёх параметров места назначения ничего не записывается**, а их ошибки
общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).
