# Установка

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

**Эта страница относится к обеим программам** — `subedit-cli` и `subedit-gui`.
Они собираются и устанавливаются вместе.

Есть два пути: **собственный пакет** дистрибутива, `.deb` или `.rpm`, или **сборка из
исходного кода**, после которой установить можно куда угодно.

## Пакеты

Оба пакета создаются CPack по **одним и тем же правилам установки**:
они помещают одни и те же файлы в одни и те же места и различаются только
именами пакетов, от которых зависят: одни и те же библиотеки называются
по-разному в Debian и в Fedora.

```bash
sudo apt install ./subedit_<version>_amd64.deb      # Debian, Ubuntu
sudo dnf install ./subedit-<version>.x86_64.rpm     # Fedora, and relatives
```

| Что устанавливает пакет | Куда |
| :---------------------- | :-- |
| `subedit-cli`, `subedit-gui` | `/usr/bin` |
| пункт меню, значок, метаданные для центра приложений | `/usr/share/applications`, `/usr/share/icons`, `/usr/share/metainfo` |
| это руководство в формате Markdown | `/usr/share/subedit/manual` |
| его перевод на каждый установленный язык — каталанский, чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий, китайский (упрощённый) | `/usr/share/subedit/manual/<language>` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr`, `zh_CN` |
| шаблоны исправлений из Gaupol | `/usr/share/subedit/patterns` |
| страницы руководства man для `subedit-cli`, по одной на подкоманду, и для `subedit-gui` — см. [Страницы руководства man](invocation.md#страницы-руководства-man) | `/usr/share/man/man1` |
| страницы `subedit-cli` на каждом установленном языке — каталанский, чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий, китайский (упрощённый) | `/usr/share/man/<language>/man1` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr`, `zh_CN` |

`ffmpeg` **рекомендуется, но не требуется** обоими пакетами: без него окно
лишь перестаёт предлагать частоту кадров, которую объявляет фильм, — см.
[что меняет `ffmpeg`](../subedit-gui/video.md#ffmpeg-не-обязателен).

### Что пакеты требуют от дистрибутива

**Устанавливайте с помощью `apt` или `dnf`, но не `dpkg -i` и не `rpm -i`.** Эти две
команды просто кладут пакет на место, не разрешая его зависимости: они лишь
перечисляют недостающие и останавливаются. Вот что отвечает `rpm -i` в
Fedora, где всё необходимое доступно через `dnf`:

```console
$ rpm -i subedit-0.13.0-1.fc43.x86_64.rpm
error: Failed dependencies:
        libicui18n.so.77()(64bit) is needed by subedit-0.13.0-1.fc43.x86_64
        libicuuc.so.77()(64bit) is needed by subedit-0.13.0-1.fc43.x86_64
```

`sudo dnf install ./subedit-<version>-1.fc43.x86_64.rpm` загружает эти
библиотеки, если они существуют.

**Нужно брать тот `.rpm`, который соответствует вашей версии Fedora**: в имени файла указана
версия — `fc42`, `fc43`, `fc44`. Каждый из них собран в той Fedora, с её
ICU; какой брать, подскажет `cat /etc/fedora-release`. `.rpm` от другой версии
Fedora требует ICU, которого у вас нет.

| Зависимость | `.deb` | `.rpm` | Ограничение |
| :--------- | :----- | :----- | :--------- |
| Qt 6: `Widgets`, `Gui`, `Core` | `libqt6widgets6`, `libqt6gui6`, `libqt6core6` | `qt6-qtbase-gui` | **≥ 6.4**, для окна |
| libmpv | `libmpv2` или `libmpv1` | `mpv-libs` | двоичный файл компонуется с `libmpv.so.2` |
| Enchant 2 | `libenchant-2-2` | `enchant2` | проверка орфографии, а также задачи `join-words` и `split-words` подкоманды [`correct`](correct.md) |
| **ICU** | **`libicu74`** | `libicu`, то есть `libicuuc.so.N` и `libicui18n.so.N` **той Fedora, в которой пакет собран** | **именно та версия, которая есть в Fedora для этого `.rpm`**, — см. ниже |
| glibc и libstdc++ | — | — | **достаточно новые**: для `.deb` — из Ubuntu 24.04, для `.rpm` — из той Fedora, для которой он собран |

**ICU — это ограничение, которое имеет значение, и его нельзя ослабить,
изменив строку в пакете.** Символы ICU несут номер её
основной версии (`u_strToUTF8_74`): двоичный файл, собранный с ICU 74, не может
компоноваться с ICU 76 или 77. Более широкая зависимость позволила бы пакету
установиться, а затем завершиться ошибкой при запуске, поэтому честным остаётся
только точное указание. **Вот почему `.rpm` собирается не один раз, а
для каждой выпущенной Fedora**, с её ICU; `.deb` собирается в Ubuntu 24.04.

| Дистрибутив | Что получается |
| :----------- | :---------------- |
| Ubuntu 24.04 | `.deb` устанавливается: ICU там версии 74 |
| Fedora 42, 43, 44 | `.rpm` для своей версии (`…fc42…`, `…fc43…`, `…fc44…`) устанавливается **через `dnf`**, он собран с ICU этой Fedora |
| Fedora rawhide (следующая версия), другие дистрибутивы с `.rpm` | **нет**: для них `.rpm` не собирается — собирайте из исходного кода |
| любой дистрибутив Debian или Ubuntu, ICU в котором не версии 74 | **нет**: `.deb` требует `libicu74` — собирайте из исходного кода |

**Сборка из исходного кода — запасной вариант, и этого
ограничения у неё нет**: она компонуется с ICU машины, какой бы ни была её версия.
Это же нужно на дистрибутиве, glibc которого старше, чем
у пакетов.

### Что проверяется у каждого, а что нет

**Проверяются они не в одинаковой мере, и лучше сказать об этом, чем
позволить поверить в паритет, которого нет.** Разработка ведётся в Ubuntu; собранный
там `.rpm` невозможно в ней установить. Его устанавливают в другом месте: в
Fedora в контейнере, раз в неделю.

| | `.deb` | `.rpm` |
| :--- | :----- | :----- |
| список файлов | проверяется | проверяется и **сравнивается со списком `.deb`** |
| объявленные зависимости | проверяется их наличие | проверяется их наличие |
| существование имён зависимостей в дистрибутиве | да, это имена Ubuntu | **да**, разрешаются через `dnf` |
| установка пакета | нет — для неё нужны права администратора | **да**, в Fedora в контейнере |
| запуск установленных двоичных файлов | да, из временного префикса | **да**, из установленного пакета |

**Проверка в Fedora тестирует `.rpm`, собранный в Ubuntu, а не те, что
выпускаются.** В этом образе нет собственного ICU 74: пакет устанавливается там, потому что
в Fedora есть пакет совместимости `libicu74`, и проверка будет зелёной, пока
этот пакет существует. Выпускаемые файлы `.rpm` собираются в своей собственной Fedora и больше не
зависят от этой совместимости. См.
[что пакеты требуют от дистрибутива](#что-пакеты-требуют-от-дистрибутива).

**Сравнение двух списков — самая важная проверка.** Два
пакета получаются из одной и той же установки: расхождение между ними было бы
дефектом правил установки, а не формата.

**Чего `.deb` по-прежнему не доказывает, так это того, что он устанавливается**, и причина
не изменилась: для `dpkg -i` нужны права администратора, которых у контроля
качества нет и которые он не должен запрашивать. `.rpm` же устанавливается в
контейнере, который никому не принадлежит. См.
[ADR 0023](../../../../adr/0023-deb-et-rpm-pour-la-premiere-livraison.md).

**Flatpak и AppImage не предлагаются**, и это выбор, а не недосмотр.
Он объяснён в том же ADR и **окончателен**: дистрибутив, который
не относится ни к семейству Debian, ни к семейству Fedora, собирается из
исходного кода, что полностью описано в следующем разделе.

## Сборка из исходного кода

### Предварительные требования

| Что нужно | Зачем | Debian, Ubuntu |
| :------------ | :------- | :------------- |
| CMake ≥ 3.28 | сборка | `cmake` |
| компилятор C++23 — подойдёт GCC 13 | — | `g++` |
| `make`, `pkg-config` | сборка | `make`, `pkg-config` |
| CLI11 | разбор командной строки | `libcli11-dev` |
| Qt 6 ≥ 6.4, модуль `Widgets` | окно | `qt6-base-dev` |
| `libmpv` | встроенный проигрыватель | `libmpv-dev` |
| ICU | чтение кодировок | `libicu-dev` |
| Enchant 2 | библиотека проверки орфографии | `libenchant-2-dev` |

**Последние четыре нужны, даже чтобы собрать только
`subedit-cli`**: конфигурация CMake ищет их для всего проекта и
останавливается, если их нет. ICU и Enchant нужны вдвойне — исполняемый файл загружает их: одну
для преобразования кодировок, другую для проверки орфографии, — и
это единственные сторонние библиотеки, которые он загружает во время работы.

**Сетевое подключение при первом запуске `cmake`**: тестовая библиотека Catch2
загружается с GitHub при конфигурации. Позже она не загружается повторно.
О сборке одной программы без сети см. ниже.

#### Что не требуется

| Что необязательно | Что теряется без него |
| :-------------------- | :--------------------- |
| `ffmpeg`, ради его `ffprobe` | окно перестаёт предлагать частоту кадров, которую объявляет фильм, — [подробности](../subedit-gui/video.md#ffmpeg-не-обязателен) |
| сервер отображения | ничего для `subedit-cli`; `subedit-gui` нужен он, чтобы показать окно |

### Сборка

```bash
git clone git@github.com:Guyot-Bertrand/sub-edit.git subedit
cd subedit
make build
```

Двоичные файлы создаются в `build/dev/bin/` — `subedit-cli` и
`subedit-gui`.

Для оптимизированной версии:

```bash
make release
```

Оба двоичных файла тогда находятся в `build/release/bin/` — `subedit-cli` и
`subedit-gui`. Эта цель не собирает ничего другого: ни эталонные тесты производительности, ни
сквозной тестовый стенд, у которых есть собственные цели.

**Предпочитайте эту цель двум равнозначным командам `cmake`**, которые
не могут знать, сколько процессов разрешено запускать оптимизации во время компоновки:
при каждой компоновке она запускает столько, сколько есть ядер.
`make release` передаёт ей `JOBS`, как и остальной сборке.

### Установка собранной программы

```bash
make release
cmake --install build/release --prefix ~/.local
```

Что устанавливается, по путям, которые `GNUInstallDirs` задаёт для выбранного
префикса:

| Файл | Куда |
| :------ | :-- |
| `subedit-cli`, `subedit-gui` | `<prefix>/bin` |
| пункт меню рабочего стола | `<prefix>/share/applications` |
| значок | `<prefix>/share/icons/hicolor/scalable/apps` |
| метаданные для центра приложений | `<prefix>/share/metainfo` |
| это руководство в формате Markdown | `<prefix>/share/subedit/manual` |
| его перевод на каждый установленный язык — каталанский, чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий, китайский (упрощённый) | `<prefix>/share/subedit/manual/<language>` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr`, `zh_CN` |
| шаблоны исправлений из Gaupol | `<prefix>/share/subedit/patterns` |
| страницы руководства man для обоих двоичных файлов, по одной на подкоманду для `subedit-cli` | `<prefix>/share/man/man1` |
| страницы `subedit-cli` на каждом установленном языке — каталанский, чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий, китайский (упрощённый) | `<prefix>/share/man/<language>/man1` — `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr`, `zh_CN` |

**Это те же файлы, которые устанавливают пакеты**: пакеты собираются из них,
а не описываются повторно.

С `--prefix ~/.local` оба двоичных файла попадают в `~/.local/bin`,
который входит в `PATH` большинства дистрибутивов. Для системного префикса,
например `/usr/local`, нужны соответствующие права.

**Пункт меню, помещённый в `~/.local`, появляется не всегда сразу**:
рабочие столы перечитывают свой кэш в собственном темпе. А пока `subedit-gui` запускается
из терминала, как любая другая команда.

`DESTDIR` учитывается, чего и ожидает упаковщик: промежуточная установка
не затрагивает ничего за пределами промежуточного каталога.

```bash
DESTDIR=/tmp/scene cmake --install build/release --prefix /usr
```

### Сборка одной программы

Тесты собираются по умолчанию, и именно им нужна сеть:
`make release` их не собирает, но конфигурирует проект, а Catch2 загружается
именно при конфигурации. Достаточно один раз отключить их: настройка
остаётся в кэше CMake, и последующие сборки сохраняют её.

```bash
cmake --preset release -DSUBEDIT_BUILD_TESTS=OFF
make release
```

Это ни от чего не освобождает участника разработки: контроль
качества их требует.

### Если сборка завершается ошибкой при компоновке

Лавина сообщений «undefined reference to `std::cout`» на корректном коде
обычно означает, что системная альтернатива `c++` указывает на `gcc` вместо
`g++`: C++ компилируется, но стандартная библиотека не подключается.

```bash
ls -l /etc/alternatives/c++                                       # check
sudo update-alternatives --install /usr/bin/c++ c++ /usr/bin/g++ 100   # fix
CXX=g++ make build                                                # work around
```

Конфигурация CMake обнаруживает этот случай и останавливается с этим сообщением, а не
допускает сбой компоновки.

### Если при установке пакета возникает жалоба на `libicu`

```console
error: Failed dependencies:
        libicuuc.so.74()(64bit) is needed by subedit-<version>.x86_64
```

Три причины, различаемые по введённой команде и по имени файла:

- **`rpm -i`**: он ничего не разрешает. Повторите с
  `sudo dnf install ./subedit-<version>.fcNN.x86_64.rpm`;
- **`.rpm` без `fcNN` в имени** или от другой Fedora, не вашей:
  он требует ICU той машины, на которой был собран. Возьмите тот, у которого `fcNN`
  совпадает с выводом `cat /etc/fedora-release`;
- **нет `.rpm` для вашей версии**: Fedora rawhide или другой дистрибутив.
  Ни один пакет из этого репозитория там не установится;
  [соберите из исходного кода](#сборка-из-исходного-кода).
