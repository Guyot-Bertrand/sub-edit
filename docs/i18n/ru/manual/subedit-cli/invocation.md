# Запуск

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli [global options] <subcommand> [options] <file>...
```

Без подкоманды программа выводит справку и останавливается.

## Язык

Командная строка говорит на языке своего окружения: **её справка, пояснения и
ошибки** следуют запрошенному языку. Примеры в этом руководстве выполняются на английском: их
блоки создаются командой `make manual`, а не копируются вручную.

**Как выбирается язык.** Первая из переменных `LC_ALL`, `LC_MESSAGES` и `LANG`, которая задана и
не пуста, определяет локаль; `LANGUAGE`, если она задана, затем перечисляет нужные языки через
двоеточие (`LANGUAGE=pt_BR:fr`) и читается первой. Таков порядок gettext, который программа
читает сама: локаль не нужно генерировать на машине.

| Правило | Действие |
| :--- | :----- |
| кодировка и модификатор | игнорируются: для `fr_FR.UTF-8@euro` ищется `fr_FR`, затем `fr` |
| `LC_ALL=C`, локаль `C` или `POSIX` либо отсутствие локали | английский, и `LANGUAGE` не читается |
| запись, называющая английский (`en`, `en_GB`) | английский: то, что следует за ней в `LANGUAGE`, не читается |
| язык, каталог которого не установлен | следующий из запрошенных, а после последнего — английский, **без единого слова** |
| сообщение, которое каталог не переводит | выводится на английском |

**Название шаблона исправления**, который `correct` сообщает как неприменимый, тоже следует языку,
если каталог его знает: это шаблоны, поставляемые с программой; собственный шаблон
называется так, как его пишет его файл. Сами файлы шаблонов никогда не переписываются.

Каталоги устанавливаются в `<prefix>/share/subedit/locale/<language>/LC_MESSAGES/subedit.mo`
и ищутся от собственного каталога исполняемого файла. Английский встроен. Эта версия устанавливает `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr` и `zh_CN` — каталанский,
чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий и китайский (упрощённый), — переведённые полностью. Французский перевод проверен
носителем языка; каталанский, чешский, немецкий, испанский, финский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий и китайский (упрощённый) переведены

При `LANG=fr_FR.UTF-8` вывод `subedit-cli --help` начинается со слов «Lire,
inspecter et recaler des fichiers de sous-titres.» Скрипт, который читает слова текстового
вывода, задаёт `LANGUAGE=en` (или `LC_ALL=C`) либо читает `--format json`, который никогда не меняется.

**Что никогда не следует языку** — то, что читает скрипт:

| Никогда не переводится | Почему |
| :--------------- | :-- |
| вывод `--format json`: ключи, значения, а также `message` и `detail` отказов и предупреждений | одни и те же байты на любом языке; слова английские |
| коды завершения | четыре кода из раздела [Коды завершения](#коды-завершения) на любом языке |
| вводимые имена: подкоманды, параметры, их значения (`off`, `srt`), метапеременные (`FILE`, `TEXT`, `OPTIONS`) | командная строка, написанная один раз, работает на любом языке |
| названия шаблонов исправления, которые принимают `correct --enable` и `--disable` | шаблон называется английским именем, которое хранит его файл |
| названия форматов и кодировок | формат называется своим именем |
| собственные диагностические сообщения CLI11 (отсутствующий обязательный аргумент, неизвестный параметр, недопустимое для параметра значение) и его `Run with --help for more information.` | сформулированы внутри анализатора, на котором построена командная строка; остаются английскими |

Запрос английского при любом окружении:

<!-- example: LC_ALL=C LANGUAGE=fr subedit-cli shift --output-dir out a.srt; echo "code=$?" -->
```console
$ LC_ALL=C LANGUAGE=fr subedit-cli shift --output-dir out a.srt; echo "code=$?"
shift needs --by, or --to-grid to work the amount out from the positions
code=1
```

## Глобальные параметры

**Они пишутся перед именем подкоманды и только там.**
Правильная форма — `subedit-cli --encoding cp1252 inspect film.srt`;
`subedit-cli inspect --encoding cp1252 film.srt` отвергается с сообщением
`The following argument was not expected: --encoding`. То же относится к
`--version`, `-v` и `--quiet`.

**`--help` — исключение, и на самом деле не совсем исключение**:
`subedit-cli inspect --help` допустимо, потому что у каждой подкоманды есть собственная справка, и выводится
справка подкоманды, а не программы.

| Параметр | Действие |
| :----- | :---- |
| `-h`, `--help` | выводит справку и останавливается; справку подкоманды, если она названа |
| `--version` | выводит `subedit <version>`, библиотеки, с которыми работает программа, и установленные языки, затем останавливается — см. [`--version`](#--version) |
| `-q`, `--quiet` | уровень 0 — никаких пояснений |
| `-v`, `-vv`, `-vvv` | уровни с 1 по 3; уровень 1 используется по умолчанию |
| `--encoding NAME` | читает файлы в этой кодировке вместо того, чтобы угадывать её |
| `--list-encodings` | выводит кодировки, которые программа умеет читать и записывать, по одной в строке, и **останавливается** (код `0`) — см. [`--list-encodings`](#--list-encodings) |
| `--format text\|json` | вид результата в стандартном выводе: текст или один объект JSON на файл — см. [Вывод, пригодный для чтения скриптом](#вывод-пригодный-для-чтения-скриптом) |
| `--config FILE` | читает настройки операций из `FILE` вместо файла настроек пользователя — см. [Файл настроек](#файл-настроек) |
| `--no-config` | не читает файл настроек: каждая настройка операции, не заданная в строке, принимает встроенное значение по умолчанию — см. [Файл настроек](#файл-настроек) |

`--quiet` и `-v` в одном вызове отвергаются: два противоположных намерения
не разрешаются в пользу того, которое записано последним.

`--config` и `--no-config` в одном вызове тоже отвергаются, с сообщением
`--config excludes --no-config`, как и `--config` с пустым именем, с сообщением
`--config needs a file name`: пустое имя не называет никакого файла, и собственный файл пользователя не читается
вместо него.

### Файл настроек

**[`adjust`](adjust.md) и [`correct`](correct.md) по умолчанию читают настройки операций из
файла настроек** — значения, которые `Adjust Durations…` и `Correct Texts…` запоминают в
окне или которые записал [`config set`](config.md). Никакая другая подкоманда его не читает. Файл:

```
$XDG_CONFIG_HOME/subedit/settings.conf
```

или `~/.config/subedit/settings.conf`, если `XDG_CONFIG_HOME` не задана, пуста или не является абсолютным
путём; это файл окна, описанный в [его руководстве](../subedit-gui/preferences.md#файл).

**Приоритет, от высшего к низшему: параметр командной строки, затем файл, затем встроенное значение
по умолчанию.** Параметр всегда побеждает: `--speed off` отключает скорость, заданную файлом. Читается только
**блок операций** файла; параметры отображения (геометрия, столбцы, тема…)
не читаются никогда. [`config list`](config.md#config-list) называет ключи и сообщает, какие из них читает
командная строка: девять ключей `duration-adjust.*`, `correction.human`, `correction.ocr`,
`correction.remove-blank` и `correction.line-break.max-lines`. **У каждого из них есть параметр,
переопределяющий его для одного вызова**, как бы ни задавал его файл; они названы в таблицах
[`adjust`](adjust.md#что-задаёт-файл-настроек) и
[`correct`](correct.md#что-выбирается-а-что-нет).

**Чтение файла пользователя никогда не приводит к сбою команды.** Отсутствующий файл даёт значения по умолчанию; файл,
который нельзя прочитать, даёт значения по умолчанию и сообщает об этом; значение, которое нельзя прочитать, сохраняет значение по умолчанию и называется; неизвестный
ключ игнорируется. Файл никогда не записывается командами `adjust` или `correct`.

**О прочитанном сообщается** при уровне 1 по умолчанию, в поток ошибок, перед первым файлом:

| Случай | Строка |
| :--- | :--- |
| файл прочитан | `settings: read <path>` |
| значение в нём не удалось прочитать | `settings: <key>: cannot read '<value>', default kept` |
| файла пользователя не существует | `settings: <path> not found, defaults used` |
| файл не удаётся прочитать | `settings: <path> unreadable, defaults used` |
| `--no-config` | ничего |

С [`--format json`](#вывод-пригодный-для-чтения-скриптом) объект каждого файла команд `adjust` и
`correct` содержит `settings`: прочитанный путь или `null`, если ничего не читалось.


**`--no-config` делает запуск воспроизводимым**: одна и та же строка даёт один и тот же результат на любой
машине, что бы пользователь ни задал в окне. Используйте его в скриптах, тестах и сообщениях об ошибках — или
`--config FILE` с файлом, который прилагается к ним.

**`--config FILE` называет другой файл**, читаемый так же, — **но он обязан существовать**. Имя,
указанное в командной строке, не является запросом значений по умолчанию: если `FILE` не существует,
`adjust` и `correct` останавливаются до чтения любого входного файла, выводят `settings file not found: <FILE>` в
поток ошибок и завершаются с кодом использования `1`. `FILE`, который существует, но не читается,
даёт значения по умолчанию и сообщает об этом, как и файл пользователя. [`config show`](config.md#config-show)
по-прежнему показывает отсутствующий `FILE` как `(not found)`, а [`config set`](config.md#config-set-и-config-unset) по-прежнему
создаёт его.

<!-- example: printf '1\n00:00:01,000 --> 00:00:01,200\nUn.\n\n' > a.srt; subedit-cli --config mine.conf adjust --dry-run a.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:01,000 --> 00:00:01,200\nUn.\n\n' > a.srt; subedit-cli --config mine.conf adjust --dry-run a.srt; echo "code=$?"
settings file not found: mine.conf
code=1
```

### `--version`

**Версия программы, одна в первой строке** — `subedit <version>`, то, чем был вывод до
0.15.38 и что читает скрипт. Затем **по строке на каждую библиотеку, с которой работает программа**, затем установленные
языки интерфейса — всё это в стандартный вывод; программа останавливается с кодом `0`. Указанная дополнительно подкоманда
не выполняется, а `-q` и `-v` ничего не меняют.

<!-- example: subedit-cli --version | head -n 1 -->
```console
$ subedit-cli --version | head -n 1
subedit 1.2.0
```

Полный вывод на машине с ICU 74.2 и Enchant 2.3.3 (номера версий зависят от машины):

```console
$ subedit-cli --version
subedit <version>
  ICU      74.2 (built with 74.2)
  Enchant  2.3.3 (built with 2.3.3)
  CLI11    2.4.1 (built with 2.4.1)
  Languages: en, fr
```

| Библиотека | Для чего её использует программа |
| :------ | :------------------------ |
| `ICU` | чтение и запись кодировок, их определение, смена регистра букв |
| `Enchant` | проверка орфографии в `correct` |
| `CLI11` | разбор этой командной строки |

- **Каждая строка содержит две версии**: найденную во время работы, первой, и ту, с которой программа
  была скомпилирована, в скобках. Они различаются, если библиотека машины была обновлена после сборки
  программы; это первое, что нужно указать в сообщении об ошибке.
- **Заголовочные файлы Enchant не несут версии**: версия в скобках — та, о которой сообщил `pkg-config`
  при конфигурации сборки.
- **CLI11 компилируется в программу**, от неё есть только заголовочные файлы: две её версии
  всегда одинаковы.
- **Ни Qt, ни libmpv**: командная строка не компонуется ни с одной из них и перечисляет только то, с чем работает.
  Окно перечисляет их — см. [его руководство](../subedit-gui/invocation.md#--version).
- **`Languages`** перечисляет `en`, исходный язык, которому не нужен каталог, затем каждый каталог,
  установленный в `<prefix>/share/subedit/locale` и читаемый, по коду — это языки, которые
  предлагает `Edit ▸ Preferences…`.
- **Что следует языку**: `built with` и `Languages`. Первая строка, имена,
  номера и коды языков не следуют ему никогда.
- **С `--format json`**, до или после `--version`, **один объект в одной строке**: `schema`
  (`1`), `command` (`"version"`), `version`, `libraries` — массив из
  `{"name":"ICU","loaded":"74.2","built":"74.2"}` в порядке текста — и `languages`,
  массив кодов. Ничто в нём не переводится.

<!-- example: subedit-cli --version --format json | grep -o '"name":"[^"]*"' -->
```console
$ subedit-cli --version --format json | grep -o '"name":"[^"]*"'
"name":"ICU"
"name":"Enchant"
"name":"CLI11"
```

### `--list-encodings`

**Кодировки, которые программа умеет читать и записывать, по одной в строке, отсортированные по имени**, в стандартный вывод,
после чего программа останавливается с кодом `0`, как и при `--version`: это ответ, а не шаг. Указанная дополнительно
подкоманда не выполняется.

<!-- example: subedit-cli --list-encodings | grep '^UTF' | head -4 -->
```console
$ subedit-cli --list-encodings | grep '^UTF' | head -4
UTF-16BE
UTF-16LE
UTF-32BE
UTF-32LE
```

- **Это имена, которые принимает `--encoding`**, канонические; их псевдонимы (`cp1252`) тоже принимаются,
  хотя и не перечисляются.
- **Число кодировок зависит от установленной ICU**, и не обещается ни одно имя сверх тех, что есть в любой ICU
  (`UTF-8`, `UTF-16LE`, `windows-1252`…). Поэтому в руководстве число не приводится.
- **`UTF-16` и `UTF-32` в списке нет**: ICU их знает, но их преобразователь записывает собственную метку,
  а модель их отвергает — см. ниже. Список для выбора не предлагает того, что следующее поле
  отвергло бы.
- **С `--format json`** — **по одному объекту на кодировку**:
  `{"schema":1,"command":"list-encodings","name":"UTF-8"}`. Это не отчёт о файле: такие
  объекты **не содержат ни `file`, ни `ok`**, что является единственным исключением из оболочки, описанной в
  разделе [форма](#форма). Тем не менее это по одному объекту в строке, по одному на запись.
- **Уровень пояснений ничего не меняет**: список — это результат, и `-q` его не убирает.

### `--encoding` и то, что он не может навязать

**Он применяется к каждой подкоманде**, потому что все они читают: файл, кодировка
которого угадана неверно, остаётся неверным, что бы с ним ни делали, а параметр,
который был бы только у `inspect`, оставил бы это несоответствие без средства исправления.

**Имя берётся из ICU, и принимаются все её псевдонимы**: `cp1252`,
`windows-1252` и `WINDOWS 1252` называют одну и ту же кодировку. Этот набор нигде
не записан: это тот, который может преобразовать ICU машины, и его
перечисляет [`--list-encodings`](#--list-encodings). Имя, которое она не может преобразовать,
отвергается до чтения первого же файла:

```console
$ subedit-cli --encoding klingon-1 inspect film.srt
no encoding is named "klingon-1"
```

**Одно исключение, и только одно: кодировка должна называть свой порядок байтов.**
`UTF-16` и `UTF-32` — имена, которые знает ICU и преобразователь которых записывает **собственную
метку**. Такая кодировка не может существовать в этой модели: метка перестаёт
быть выбором, а `--no-bom` принимался бы и не выполнялся, — поэтому обе
отвергаются и для чтения, и для записи:

```console
$ subedit-cli --encoding UTF-16 inspect film.srt
"UTF-16" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do
```

`UTF-16LE` и `UTF-16BE` читают и записывают те же байты, включая метку; точное
имя добавляет лишь то, что известно, какой именно порядок.

**Метка порядка байтов побеждает параметр.** Это единственное, что файл
субтитров объявляет о себе, и читать его иначе, чем он объявляет себя,
значило бы подчиняться вызывающему вопреки файлу. О несоответствии **сообщается**
диагностическим сообщением:

```console
$ subedit-cli -vvv --encoding cp1252 inspect avec-bom.srt
avec-bom.srt: a byte order mark that contradicts the encoding asked for ("UTF-16LE"), settled by the reader
```

Так поступает и Gaupol: он начинает чтение заново с кодировкой
метки, но не сообщает об этом; здесь расхождение между запрошенным и
сделанным не замалчивается.

## Подкоманды

| Подкоманда | Что делает | Записывает ли? |
| :------------ | :-------------- | :----------- |
| [`inspect`](inspect.md) | сообщает, из чего состоит файл, ничего не изменяя | нет |
| [`convert`](convert.md) | записывает файл в другом формате или в другой форме | да |
| [`shift`](shift.md) | сдвигает каждую позицию на одну и ту же величину | да |
| [`transform`](transform.md) | исправляет каждую позицию по двум заведомо верным точкам | да |
| [`framerate`](framerate.md) | пересчитывает тайминг файла с одной частоты кадров на другую | да |
| [`snap`](snap.md) | привязывает каждую метку времени к ближайшему кадру | да |
| [`hearing-impaired`](hearing-impaired.md) | удаляет пометки для слабослышащих | да |
| [`adjust`](adjust.md) | подгоняет длительности под скорость чтения и пределы | да |
| [`replace`](replace.md) | заменяет текст в субтитрах, не нарушая тегов | да |
| [`case`](case.md) | переводит тексты в регистр «каждое слово с заглавной», «как в предложении», верхний или нижний | да |
| [`italics`](italics.md) | выделяет тексты курсивом или убирает с них курсив | да |
| [`dialogue-dashes`](dialogue-dashes.md) | ставит тире диалога или убирает их | да |
| [`sort`](sort.md) | возвращает субтитры в порядок их начал | да |
| [`join-repeats`](join-repeats.md) | превращает в один субтитр части одного текста, следующие друг за другом | да |
| [`disjoint`](disjoint.md) | разрезает перекрывающиеся субтитры так, чтобы ни один диапазон больше не перекрывал другой | да |
| [`repair`](repair.md) | выполняет подряд `join-repeats`, `sort` и `disjoint` | да |
| [`correct`](correct.md) | исправляет тексты по шаблонам Gaupol: пометки, объединение и разделение слов, частые ошибки, заглавные буквы, разбиение на строки | да |
| [`append`](append.md) | добавляет файлы после первого, в **один** файл | да |
| [`split-file`](split-file.md) | разрезает файл на **два**: начало и конец | да |
| [`pair`](pair.md) | записывает перевод на позиции его основного файла и сообщает, как легли его строки | да |
| [`transcribe`](transcribe.md) | записывает речь видео или аудиофайла в виде субтитров | да — своё место назначения, `--output` |
| [`sync`](sync.md) | пересчитывает время субтитров файла по звуку фильма | да |
| [`config`](config.md) | перечисляет, показывает и изменяет настройки операций в файле настроек | только файл настроек |

Перечислена каждая из двадцати трёх подкоманд; справка программы перечисляет их в том же порядке.

**Только одна подкоманда ничего не затрагивает**, о чём говорит правый столбец: `inspect` читает и
сообщает. Остальные двадцать одна записывают, а то, что сказано далее, относится к восемнадцати из них:
у [`append`](append.md) и [`split-file`](split-file.md) своя арность — N файлов на
**один** результат, один файл на **два**, — а значит, и своё место назначения, которое они описывают на своей странице;
[`transcribe`](transcribe.md) делает новый файл из видео или аудиофайла и принимает только `--output`.
[`config`](config.md) не записывает файлов субтитров: она читает и изменяет файл настроек, и
ничто из сказанного далее к ней не относится.

## Место назначения

Восемнадцать подкоманд, которые записывают, — [`convert`](convert.md),
[`shift`](shift.md), [`transform`](transform.md), [`framerate`](framerate.md),
[`snap`](snap.md), [`hearing-impaired`](hearing-impaired.md), [`adjust`](adjust.md),
[`replace`](replace.md), [`case`](case.md), [`italics`](italics.md),
[`dialogue-dashes`](dialogue-dashes.md), [`sort`](sort.md), [`join-repeats`](join-repeats.md),
[`disjoint`](disjoint.md), [`repair`](repair.md), [`correct`](correct.md), [`pair`](pair.md), [`sync`](sync.md) — задают место назначения одним и тем же способом. (У [`append`](append.md) и
[`split-file`](split-file.md) оно своё, оно описано на их странице.) [`inspect`](inspect.md) не записывает файлов и
не принимает ни один из этих параметров.

**Уже существующее место назначения перезаписывается** без вопросов и без параметра,
позволяющего этого избежать: запись атомарна — файл никогда не бывает записан наполовину, а
прерванная запись оставляет прежний файл нетронутым, — но прежнее содержимое
теряется. Это не недосмотр, который терпят: это правило, и повторный запуск команды
в тот же выходной каталог выполняет её заново поверх самой себя.

**Ничто никогда не записывается без явно указанного места назначения.** Три способа его
указать исключают друг друга, и нужен один из них: без него ничего не записывается, а код
завершения равен `1`, за исключением [`--dry-run`](#просмотр-перед-записью), который ничего не записывает
и потому не требует его.

| Параметр | Куда попадает результат |
| :----- | :---------------- |
| `--output FILE` | в этот файл под этим точным именем; один входной файл |
| `--output-dir DIR` | в этот каталог под базовым именем входного файла |
| `--in-place` | поверх входного файла, атомарной записью |

Программа, которая перезаписывает входной файл, потому что ей ничего не сказали, — это программа, которой
перестают пользоваться со второго раза. Отказ стоит одной строки и спасает
файл.

`--output` с несколькими входными файлами отвергается: последний файл был бы записан поверх
предыдущих. Для пакета осмысленны только `--output-dir` из этих трёх и
`--in-place`.

**Выходной каталог создаётся**, если его нет, вместе с родительскими, — и для
`--output-dir`, и для каталога, в который записывает `--output`. Это делается после проверки
командной строки и **до первого файла**. Если создать его не удаётся,
об этом сообщается один раз, ни один файл не читается, а код завершения равен
`2`.

**Пакет оценивается целиком до записи.** Сначала вычисляется место назначения каждого
входного файла, и из этого следуют два отказа — ошибки использования, код
`1`, **ни один файл не записан** и ни один каталог не создан:

- **два входных файла, которые оказались бы в одном файле**: `a/film.srt` и
  `b/film.srt` с `--output-dir` либо `a/film.srt` и `b/film.vtt`, оба
  преобразуемые в WebVTT, итоговое место назначения которых сменило расширение. В
  сообщении названы место назначения и оба входных файла; переименование второго или
  победа последнего потеряли бы файл молча, а отказ
  стоит одной строки;
- **место назначения, совпадающее с одним из входных файлов**, без `--in-place`, в том числе
  через `--output-dir .`, через `--output` или через символическую ссылку. Запись поверх
  своего входного файла — жест, который нужно назвать.

Два пути называют один и тот же файл, когда так говорит система, а не когда они
записаны одинаково: `in/../in/film.srt` и `in/film.srt` — это один файл.

**Расширение следует записываемому формату.** Оно меняется только у
[`convert`](convert.md), единственной подкоманды, меняющей формат; остальные
сохраняют формат прочитанного файла, а значит, и его расширение.

| Что её вызывает | Сообщение |
| :------------------ | :------ |
| место назначения не указано, без `--dry-run` | `no destination given: use --output, --output-dir or --in-place` |
| указаны два места назначения | `--output, --output-dir and --in-place exclude one another` |
| `--output` для пакета | `--output names one file but several were given: use --output-dir instead` |
| два входных файла, одно место назначения | `<destination>: would be written by both <input> and <input>` |
| входной файл был бы перезаписан | `<destination>: would be written over the input <input>` — то же предложение для [`append`](append.md) и [`split-file`](split-file.md) |
| выходной каталог, который нельзя создать | `<directory>: cannot be created: permission denied` или `: cannot be created` |
| место назначения, в которое нельзя записать | `<path>: <destination>: cannot be written: permission denied` или `: cannot be written` |
| символ, отсутствующий в записываемой кодировке | `<path>: holds a character the chosen encoding cannot write` |

**Последний случай заслуживает пояснения.** Файл записывается обратно в **той кодировке, в которой
был прочитан**, так же как с его символами конца строки и меткой. Если
изменение внесло в него символ, которого эта кодировка не знает, например
`ł` в Latin-1, запись завершается неудачей и **ничего не записывается**. Замена его
на `?` означала бы потерю текста на глазах у того, кто его только что написал.

## Просмотр перед записью

**`--dry-run`** принимает каждая из шестнадцати подкоманд, которые записывают, и означает везде одно и то же:
**прочитать, вычислить, сообщить, не записывать файл**. Его добавляют к
строке, которую собирались выполнить; применение — это повторный запуск той же строки без него. Вычисление
детерминировано: то, что показал `--dry-run`, будет записано при следующем запуске, пока
файл не изменился.

- **Он не записывает файлов и не создаёт каталогов**, включая `--in-place`: входной
  файл остаётся таким, каким был.
- **Он не требует места назначения.** Его можно указать, и **тогда оно проверяется так же, как без
  `--dry-run`**: два входных файла для одного места назначения, входной файл, который был бы перезаписан,
  `--output` для пакета, два способа сказать, куда писать: командная строка, отвергнутая без `--dry-run`,
  отвергается и с ним, тем же сообщением и тем же кодом `1`.
- **Код завершения такой же, как у настоящего запуска**: `0`, когда всё вычислено, `2` или `3`,
  когда файлы не удалось прочитать или обработать, `1` при ошибке использования. Символ, который
  кодировка файла не смогла бы записать, приводит пробный запуск к сбою так же, как настоящий.
  **Наличие изменений код не меняет**: четыре кода говорят о том, успешно ли выполнила работу
  программа, а не о том, соответствует ли файл.
- **Пояснения сообщают об этом.** Там, где настоящий запуск выводит `-> <destination>`, пробный
  запуск выводит `(dry run, nothing written)`.

<!-- example: printf '1\n00:00:10,000 --> 00:00:12,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by 1 --dry-run a.srt; ls -- *.srt -->
```console
$ printf '1\n00:00:10,000 --> 00:00:12,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by 1 --dry-run a.srt; ls -- *.srt
a.srt: 1 subtitle shifted by 1.000 s (dry run, nothing written)
a.srt
```

**У подкоманды, которая изменяет тексты**
([`hearing-impaired`](hearing-impaired.md), [`replace`](replace.md), [`case`](case.md),
[`italics`](italics.md), [`dialogue-dashes`](dialogue-dashes.md) и [`correct`](correct.md)), **стандартный вывод содержит предлагаемые
изменения**. По одному блоку на изменённый субтитр, в порядке файла:

```
<path>: subtitle <number>
- <the text before, line by line>
+ <the text after, line by line>
```

- **номер** — тот, который субтитр имеет в прочитанном файле, считая с единицы;
- перед каждой строкой текста «до» стоит `- `, перед каждой строкой текста «после» — `+ `: текст
  из нескольких строк читается как есть, а строка, которая сама начинается с тире диалога,
  даёт `- - `;
- **субтитр, который операция удалила бы,** сообщает об этом в своей первой строке:
  `<path>: subtitle <number> (removed)`, и строк с `+` у него нет;
- субтитр перевода при `--document translation` объявляет себя как `(translation)` на том же
  месте — см. [Перевод](#перевод);
- первая строка каждого блока начинается с пути, чтобы `grep '^film.srt: '`
  находил блоки одного файла в пакете;
- **блока нет**, если ничего не изменилось бы.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\n[Bruit de pas]\n\n2\n00:00:04,000 --> 00:00:06,000\nAttends [il tousse] Marie.\n\n3\n00:00:07,000 --> 00:00:09,000\n- [Grincement]\n- Qui est là ?\n\n' > mentions.srt; subedit-cli hearing-impaired --dry-run mentions.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\n[Bruit de pas]\n\n2\n00:00:04,000 --> 00:00:06,000\nAttends [il tousse] Marie.\n\n3\n00:00:07,000 --> 00:00:09,000\n- [Grincement]\n- Qui est là ?\n\n' > mentions.srt; subedit-cli hearing-impaired --dry-run mentions.srt
mentions.srt: 2 subtitles cleaned, 1 removed (dry run, nothing written)
mentions.srt: subtitle 1 (removed)
- [Bruit de pas]
mentions.srt: subtitle 2
- Attends [il tousse] Marie.
+ Attends Marie.
mentions.srt: subtitle 3
- - [Grincement]
- - Qui est là ?
+ Qui est là ?
```

**В JSON список тот же**: объект файла содержит массив `changes`, см.
[форму](#форма), причём `after` равно `null` для удалённого субтитра. **Он
вычисляется только тогда, когда его запрашивает `--dry-run` или `--format json`**: пакет из тысяч
субтитров не строит его зря.

У **остальных подкоманд** ([`convert`](convert.md), [`shift`](shift.md),
[`transform`](transform.md), [`framerate`](framerate.md), [`snap`](snap.md),
[`adjust`](adjust.md), [`sort`](sort.md), [`append`](append.md), [`split-file`](split-file.md), [`pair`](pair.md)) стандартный
вывод содержит то, что содержал бы вывод настоящего запуска, то есть в текстовом виде ничего; в
JSON — объект каждого файла с `"dry_run":true`, `"destination":null` и теми же
`counts`.

## Два потока вывода, две роли

| Поток | Что он содержит |
| :----- | :--------------- |
| стандартный | **результат и только результат** — отчёт `inspect`, предлагаемые изменения текстового [`--dry-run`](#просмотр-перед-записью); с `--format json` — один объект на файл, а у [`append`](append.md), [`split-file`](split-file.md) и [`pair`](pair.md) — один на запуск |
| ошибок | **всё остальное** — пояснения, предупреждения, ошибки |

Именно это разделение позволяет перенаправить результат, не получив вместе с ним рассказа о ходе работы:

```console
$ subedit-cli inspect *.srt > rapport.txt
```

Отчёт попадает в файл, а пояснения остаются на экране.

## Вывод, пригодный для чтения скриптом

**`--format json`** заменяет текст стандартного вывода **одним объектом JSON на
входной файл** в формате JSON Lines: один компактный объект в строке, в UTF-8 без
метки, символ конца строки — `\n`. `text` используется по умолчанию и не меняется. Это
глобальный параметр, поэтому он пишется перед подкомандой; любое значение, кроме
`text` и `json`, — ошибка использования, код `1`.

<!-- example: printf '1\n00:00:10,000 --> 00:00:12,000\nUn.\n\n' > a.srt; subedit-cli --format json shift --by 1 --output-dir sortie a.srt absent.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:10,000 --> 00:00:12,000\nUn.\n\n' > a.srt; subedit-cli --format json shift --by 1 --output-dir sortie a.srt absent.srt; echo "code=$?"
a.srt: 1 subtitle shifted by 1.000 s -> sortie/a.srt
{"schema":1,"command":"shift","file":"a.srt","ok":true,"dry_run":false,"destination":"sortie/a.srt","counts":{"subtitles":1,"shifted_by_ms":1000},"warnings":[]}
absent.srt: does not exist
{"schema":1,"command":"shift","file":"absent.srt","ok":false,"error":{"kind":"not-found","message":"absent.srt: does not exist"}}
1 of 2 files shifted, 1 failed
code=3
```

**Один объект на входной файл, никогда ни нуля, ни двух**, успешно ли обработан входной файл или нет, в
том порядке, в котором входные файлы заданы или найдены при [`--recursive`](lots.md). Один
считает строки, один находит свои файлы. **Три подкоманды составляют исключение, потому что их
арность не та, что у пакета: [`append`](append.md) (N входных файлов, один выходной), [`split-file`](split-file.md)
(один входной, два выходных) и [`pair`](pair.md) (два файла, один выходной) записывают **один объект на весь
запуск**, который называет тот файл, что указан на их странице.** **Подкоманды, которые перезаписывают файлы, поэтому
выводят данные и в стандартный вывод**, чего их контракт в текстовом виде не делал: их
файл остаётся их результатом, а объект — отчётом о нём.

**Пояснения не меняются.** `-q`, `-v`, `-vv` и `-vvv` действуют на поток
ошибок в текстовом виде, как и без `--format`; **стандартный вывод от них не зависит**.
Диагностические сообщения чтения, которые текст оставляет на уровне 3, — это данные, и они
**всегда** находятся в `warnings`. Ошибка использования не выводит объекта: она обнаруживается
до того, как затронут какой-либо файл, так что ей не к чему быть привязанной; она попадает в поток
ошибок с кодом `1`, а стандартный вывод остаётся пустым.

### Форма

| Ключ | Содержимое | Присутствует |
| :-- | :------ | :------- |
| `schema` | целое число, версия этой формы — `1` | всегда |
| `command` | имя подкоманды | всегда |
| `file` | путь **как указан** или как его составил обход каталога | всегда |
| `ok` | логическое значение | всегда |
| `error` | `{"kind", "message"}` | если `ok` ложно |
| `dry_run` | логическое значение: истинно для [`--dry-run`](#просмотр-перед-записью) | если `ok` истинно, у подкоманды, которая записывает |
| `destination` | записанный путь или `null`, когда `dry_run` истинно: ничего не записано | так же |
| `counts` | объект из **целых чисел**, свой у каждой подкоманды | так же |
| `changes` | массив из `{"subtitle", "document", "before", "after"}`: изменённые тексты, см. ниже | у подкоманды, которая изменяет тексты |
| `warnings` | массив из `{"kind", "line"?, "detail"?, "settled"?}` | если `ok` истинно |
| `alignment` | как был наложен перевод, см. [Перевод](#перевод) | с `-t` и для `pair` |
| `constraints` | использованные настройки | `adjust` |
| `settings` | прочитанный файл настроек или `null`, если ничего не читалось — см. [Файл настроек](#файл-настроек) | `adjust`, `correct`, если `ok` истинно |
| `inputs`, `tail` | по одному элементу на каждый добавленный файл; путь к концу | `append`; `split-file` |

`line` отсутствует в диагностическом сообщении, относящемся ко всему файлу; `detail` отсутствует, если
добавить нечего; `settled` равно `true`, когда чтение что-то **разрешило** (например,
заново создало нумерацию), и отсутствует, когда оно оставило всё как есть.

**`changes`** перечисляет в порядке файла каждый субтитр, текст которого изменяется:
`subtitle` — его номер в прочитанном файле, считая с единицы; `document` равно `"main"`
или `"translation"`; `before` — текст до; `after` — текст после или **`null`, если
субтитр удалён**. Переводы строк в тексте записываются как `\n`. Оно
записывается и при настоящем запуске, и при [`--dry-run`](#просмотр-перед-записью) и **пусто
(`[]`), когда ничего не меняется**: его наличие говорит о том, что подкоманда перечисляет свои изменения,
отсутствие — о том, что их у неё нет.

**Никаких чисел с плавающей запятой нигде.** Позиция или длительность — целое число
**миллисекунд** (`…_ms`); счётчик — целое число; частота кадров — **строка**
(`"25"`, `"24000/1001"`), потому что она точна, а рациональное число с плавающей запятой
этого не обеспечит; концентрация сетки — целое число **тысячных долей**: `1000` — это
идеальная сетка. Два вывода тогда сравниваются побайтово, без округления.

**Путь не в UTF-8** (Linux это допускает) невозможно представить в JSON: он
записывается с U+FFFD вместо недопустимых байтов, и объект несёт предупреждение
`path-not-utf8`. Верность такого пути не гарантируется, и об этом сказано.

### Идентификаторы ошибок

`error.kind` — один из этих; **читающий воспринимает неизвестный идентификатор как
«other»**.

| `kind` | Что это |
| :----- | :----------- |
| `not-found`, `permission-denied`, `io` | система отказалась читать файл или записывать его |
| `unknown-format`, `no-subtitle-found`, `undecodable` | файл прочитан и не поддаётся чтению |
| `unencodable` | символ, который выбранная кодировка не может записать |
| `no-byte-order-mark`, `no-frame-rate` | то, что `convert` не может записать, если ему не сказали |
| `before-the-origin`, `beyond-the-end`, `no-transform`, `no-grid` | операция, неприменимая к этому файлу |
| `range-out-of-bounds` | `--range`, которого в этом файле нет |
| `no-style` | формат, не записывающий стиль (TMPlayer, LRC), для `italics` |
| `refused` | любой другой отказ операции |

### Что гарантируется, а что нет

**Гарантируется, пока `schema` равно `1`**: имена ключей, их тип и единица измерения; смысл
`ok`, `file` и `destination`; **один объект на входной файл, в порядке входных файлов**, а у трёх подкоманд со своей арностью — один на запуск;
существующие идентификаторы `kind`; детерминизм — те же входные данные, те же аргументы,
те же байты.

**Не гарантируется**: **текст сообщений** (`message`, `detail`), английский для человека,
который исправляется, когда нужно, — скрипт, который его сравнивает, заранее сломан; **порядок
ключей** в объекте, зафиксированный, но не гарантированный JSON; наличие **ключей, которые ещё не
добавлены**.

**Поэтому читающий игнорирует неизвестный ключ** и воспринимает неизвестный `kind` как «other»:
добавление ключа или идентификатора не меняет `schema`. Удаление или переименование ключа,
смена типа или единицы, удаление идентификатора увеличивают её — это разрыв
совместимости, о котором объявляется в CHANGELOG и здесь.

## Уровни пояснений

Каждый уровень **включает предыдущий**: повышение на ступень добавляет, но никогда не
заменяет.

| Уровень | Как | Что содержит поток ошибок |
| :----- | :------ | :------------------------------ |
| 0 | `--quiet` | ничего, **кроме ошибок** |
| 1 | по умолчанию или `-v` | одну строку на каждый обработанный файл и итог, как только файлов несколько |
| 2 | `-vv` | а также то, что было распознано: формат, кодировка, BOM, символы конца строки |
| 3 | `-vvv` | а также отладочную трассировку: прочитанные и записанные байты и **каждое диагностическое сообщение чтения** |

**Ошибки не подавляются никогда, включая `--quiet`.** Команда, которая завершается неудачей
молча, оставила бы лишь код завершения.

Итог появляется только начиная с двух файлов: для одного входного файла он
повторял бы предыдущую строку.

## Чтение диагностических сообщений

Форматы субтитров читаются **как можно лучше**: столкнувшись с аномалией,
читающий не останавливается — он принимает решение или оставляет всё как есть и сообщает об
этом. То, с чем он столкнулся, выводится на **уровне 3**, по одной строке на сообщение, в поток
ошибок:

```
a.srt: 2 diagnostics while reading
a.srt: line 6: SubRip numbers that do not follow ("7"), settled by the reader
a.srt: line 9: a line that fits nowhere, left as it stands
```

Сообщают о них все восемнадцать подкоманд, а не только [`inspect`](inspect.md):
файл, прочитанный как можно лучше и затем записанный обратно, прошёл через те же решения, и умолчание о них
позволило бы поверить, что ничего не произошло.

**Диагностическое сообщение никогда не является сбоем.** Файл прочитан, команда
выполнена успешно, код завершения равен `0`. Поэтому они находятся на самом
подробном уровне: на более низком они заглушили бы строку, которая сообщает, что на самом деле
было сделано.

### Что содержит каждая строка

| Часть | Что сообщает |
| :----- | :------------- |
| `line N` | где, считая с 1, как показывает редактор; **отсутствует** для сообщений, относящихся ко всему файлу |
| фраза | с чем столкнулись, одна из двенадцати категорий ниже |
| `("…")` | проблемный текст файла, если категории недостаточно; усечённый до 80 байтов |
| конец | что с этим сделали: `settled by the reader` или `left as it stands` |

**У двух категорий нет строки**, и это две категории, касающиеся
кодировки: байты были проанализированы или их метка прочитана ещё до того, как возникла хоть одна
строка файла. Поэтому их строка начинается с фразы, без `line N`
впереди: называть нечего.

**Самое важное — конец строки.** `settled by the reader` означает,
что читающий принял решение и что записанный файл несёт это решение: отсутствующая
нумерация создаётся заново. `left as it stands` означает, что он ничего не
затронул, потому что **решить может только пользователь**: субтитр, который заканчивается раньше, чем
начинается, остаётся как есть.

### Номер строки блока

Аномалия, относящаяся ко **всему блоку**, привязывается к его строке
тайминга, а не к той точной строке, которая её вызвала. Нарушенная нумерация,
записанная в строке 5, поэтому сообщается в строке 6, то есть в следующей за ней строке
тайминга; ошибочный номер находится в `("…")`. На самих себя указывают только аномалии, относящиеся
к **строке**: нечитаемая строка тайминга, текст перед первой из них.

### Двенадцать категорий

| Фраза | Что её вызывает |
| :----- | :------------------ |
| `a line that fits nowhere` | строка, не входящая ни в один блок |
| `a timing line that could not be read` | нечитаемая строка тайминга |
| `a SubRip block without its number` | отсутствующая нумерация, создаваемая заново при записи |
| `SubRip numbers that do not follow` | нумерация со скачками |
| `text before the first timing line` | текст перед первой строкой тайминга |
| `a WebVTT block of an unknown kind` | нераспознанный блок WebVTT |
| `declares an event column this tool cannot fill` | столбец событий Sub Station Alpha, который здесь нечем заполнить |
| `counts in frames and states no rate; it was read at` | файл в кадрах, не указывающий частоту кадров; использованная частота — в подробностях |
| `carries no end times; each one was taken from the next start` | формат без концов, TMPlayer или LRC: **ни один конец в таблице не берётся из файла** |
| `more than one kind of line ending` | смешанные символы конца строки |
| `an encoding nothing declared` | кодировка предложена анализом байтов, и это не UTF-8 |
| `a byte order mark that contradicts the encoding asked for` | файл несёт метку, а `--encoding` назвал другую кодировку — побеждает метка |

**Три средние категории относятся к фазе 9**, а последние две из этих
трёх говорят не о строке, а обо всём файле: они сообщают, что
показанное значение не было прочитано. Столбец `End`, заполненный в LRC, или
позиция в MicroDVD — в файле ничего из этого не было.

**Операция может добавлять собственные сообщения**, не являющиеся диагностическими сообщениями чтения:
[`correct`](correct.md#шаблон-который-нельзя-применить) сообщает вместе с субтитром о шаблоне,
который не удалось применить. Об этом сообщается на уровне 1, и в объекте файла оно несёт идентификатор
`pattern-failed` — это никогда не сбой файла.

## Перевод

Файл перевода обрабатывается **как любой файл субтитров**:
`subedit-cli case --to sentence film.fr.srt` изменяет его без каких-либо новшеств. То, что добавляет сопоставление, и то, о чём говорят
три параметра, узко: **узнать, как строки перевода ложатся на
субтитры основного файла** — это `inspect -t` — и **изменять перевод, удерживая его
наложенным на основной файл**, по тем же правилам, что и в окне.

| Параметр | Где | Значение | По умолчанию |
| :----- | :---- | :----- | :----- |
| `-t`, `--translation-file` | `inspect`, `hearing-impaired`, `replace`, `case`, `italics`, `dialogue-dashes`, `correct`, `pair` | файл перевода | — |
| `--document` | шесть текстовых подкоманд, но не `inspect` и не `pair` | `main` или `translation` | `main` |
| `--align-method` | как у `-t` | `position` или `number` | `position` |

- **`position`** сравнивает середину каждой строки с границами субтитров: отсутствующая строка не
  сдвигает следующие за ней. **`number`** отправляет строку *n* в субтитр *n*, не глядя на
  позиции. По умолчанию используется позиция по той же причине, что и в окне: отсутствующая строка в
  середине сдвигает весь остаток перевода, сопоставленного по номеру.
- **`--document translation` требует `-t`, а `-t` требует `--document translation`** у текстовой
  подкоманды: одно без другого — ошибка использования, код `1`, потому что прочитанный файл, который не
  используется ни одним действием, — это упущение, а не предпочтение. У `-t` в `inspect` нет `--document`: она
  сообщает. **`--align-method` без `-t` — тоже ошибка использования.**
- **`-t` называет файл, поэтому имеет смысл только для одного входного файла**: при нескольких входных файлах или
  при каталоге, обрабатываемом через `--recursive`, он отвергается так же, как `--output`, **до чтения какого-либо
  файла**. Для пакета выполняйте по одному вызову на пару.
- **Файл перевода, совпадающий с основным файлом, отвергается**, как бы ни был записан его
  путь: `<translation>: the file is already open as the main document`, код `2`.
- **Записывается только тот документ, на который направлена операция**, по **его собственному пути и в его собственном формате**: формат,
  кодировка и символы конца строки файла перевода. `--output` называет файл
  перевода, `--output-dir` помещает туда его базовое имя, `--in-place` переписывает его; **основной файл
  не затрагивается никогда**. Пути в отчёте — это пути перевода.
- **Субтитры, которые сопоставление оживляет**, то есть строка, до которой ничто не дошло, записываются в
  перевод с **их собственными позициями**, каким бы ни был метод; **субтитр, который никто не
  перевёл, записывается как блок без текста**, читаемый без аномалий.
- **`--encoding` и `--frame-rate` применяются к обоим файлам.**
- У подкоманд для **позиций** (`shift`, `transform`, `framerate`, `snap`, `adjust`) этих параметров
  нет: передайте им оба файла, как для пакета,
  `subedit-cli shift --by 2 film.srt film.fr.srt --output-dir out/`.
- **Запись перевода, заново выровненного по основному файлу,** — единственное, что делает сопоставление и чего не делает
  отдельный файл, — это работа [`pair`](pair.md), у которой нет ни `--document`, ни `--recursive`.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nHello.\n\n2\n00:00:03,000 --> 00:00:04,000\nBye.\n\n' > film.srt; printf '1\n00:00:01,000 --> 00:00:02,000\n[Un oiseau] Bonjour.\n\n2\n00:00:03,000 --> 00:00:04,000\nAu revoir.\n\n' > film.fr.srt; subedit-cli hearing-impaired film.srt -t film.fr.srt --document translation --output propre.fr.srt; cat propre.fr.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nHello.\n\n2\n00:00:03,000 --> 00:00:04,000\nBye.\n\n' > film.srt; printf '1\n00:00:01,000 --> 00:00:02,000\n[Un oiseau] Bonjour.\n\n2\n00:00:03,000 --> 00:00:04,000\nAu revoir.\n\n' > film.fr.srt; subedit-cli hearing-impaired film.srt -t film.fr.srt --document translation --output propre.fr.srt; cat propre.fr.srt
film.fr.srt: 1 subtitle cleaned, 0 removed -> propre.fr.srt
1
00:00:01,000 --> 00:00:02,000
Bonjour.

2
00:00:03,000 --> 00:00:04,000
Au revoir.
```

С `--format json` объект каждого файла содержит также ключ `alignment`, который сообщает, как
был наложен перевод: `{"file", "method", "attached", "born", "untranslated", "out_of_order"}`, как
ключ `translation` у [`inspect`](inspect.md#в-формате-json); а **с `--dry-run`** `changes` перечисляет
субтитры перевода, каждый с `"document":"translation"`.

## Несколько файлов

Каждая подкоманда принимает несколько путей, кроме [`append`](append.md), [`split-file`](split-file.md) и
[`pair`](pair.md), арность которых указана на их странице. Каждый файл обрабатывается
независимо: сбой одного не прерывает остальные, а о сбоях
сообщается с указанием файла и причины.

**Каталог означает содержащиеся в нём файлы при `--recursive` (`-r`)**:
без этого параметра указание каталога — ошибка использования, код `1`, и ничего не
обрабатывается: отказать лучше, чем ничего не обработать и вернуть `0`:

<!-- example: mkdir films; printf '1\n00:00:01,000 --> 00:00:02,000\nUn.\n\n' > films/a.srt; subedit-cli inspect films; echo "code=$?" -->
```console
$ mkdir films; printf '1\n00:00:01,000 --> 00:00:02,000\nUn.\n\n' > films/a.srt; subedit-cli inspect films; echo "code=$?"
films: is a directory: use --recursive
code=1
```

Обход, дерево, сохраняемое в `--output-dir`, и то, что оставляется
в стороне, описаны в разделе [Обработка дерева каталогов](lots.md).

## Страницы руководства man

При установке рядом с `subedit-cli(1)` помещается **по одной странице руководства man на подкоманду**:
`subedit-cli-shift(1)`, `subedit-cli-convert(1)` и остальные, по одной на каждую строку
[таблицы подкоманд](#подкоманды). `subedit-cli(1)` содержит эту главу — глобальные параметры,
потоки вывода, коды завершения, — а каждая другая страница содержит главу своей подкоманды, включая
примеры. Страница окна, `subedit-gui(1)`, находится рядом с ними.

```console
$ man subedit-cli
$ man subedit-cli-shift
```

**Страницы не пишутся отдельно от этого руководства**: они создаются из него при сборке
программы, поэтому говорят то же, что и оно, и не могут от него отклониться. Раздел ФАЙЛЫ каждой
страницы называет каталог, в который установлено руководство.

| Страницы | Куда они устанавливаются |
| :---- | :----------------------- |
| английские | `share/man/man1` |
| каждый установленный язык — каталанский, чешский, немецкий, испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий, китайский (упрощённый) | `share/man/<language>/man1` — `share/man/fr/man1` |

**`man` выбирает язык по локали**, как и программа: в французской локали
`man subedit-cli` показывает французскую страницу, а язык, страницы которого не установлены, получает
английские. `-L` запрашивает язык независимо от локали:

```console
$ man -L fr subedit-cli-shift
```

## Коды завершения

| Код | Значение |
| :--- | :------------ |
| `0` | всё выполнено успешно |
| `1` | ошибка использования: неизвестный параметр, недопустимое значение, запрещённое сочетание |
| `2` | не удалось обработать ни один файл |
| `3` | одни файлы обработаны, другие нет |

`2` и `3` различаются для того, чтобы скрипт знал, как действовать, не перечитывая вывод:
«ничего не получилось» и «одного не хватает» не требуют одинаковой реакции.

Ошибка использования обнаруживается **до любой обработки**: она никогда не оставляет
пакет обработанным наполовину.

## Ошибки

| Что её вызывает | Что выводится в поток ошибок |
| :------------------ | :--------------------------------------- |
| неизвестный параметр или подкоманда | ошибочное имя и указание на `--help` |
| `--quiet` с `-v` | `--quiet and -v ask for opposite things; give one or the other` |
| `--config` с `--no-config` | `--config excludes --no-config` |
| `--config` с пустым именем | `--config needs a file name` |
| отсутствующий файл | `<path>: does not exist` |
| нечитаемый файл | `<path>: cannot be opened: permission denied` |
| кодировка, которая записывает собственную метку | `"<name>" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do` |
| байты, которые не декодируются | `<path>: cannot be decoded in the chosen encoding` |
| формат не распознан | `<path>: is in no format this tool knows` |
| ничего, похожего на субтитр | `<path>: holds nothing recognisable as a subtitle` |
| `--document translation` без `-t` | `--document translation needs the translation file: use -t` |
| `-t` без `--document translation` | `-t names a translation to change: use --document translation` |
| `--align-method` без `-t` | `--align-method needs a translation file: use -t` |
| `-t` с несколькими входными файлами или каталогом | `-t names one file but several inputs were given: use one invocation per pair` |
| перевод, совпадающий с основным файлом | `<translation>: the file is already open as the main document` |
