# `sort`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli sort (--output FILE | --output-dir DIR | --in-place)
                 [--dry-run]
                 [--recursive]
                 <file>...
```

Возвращает субтитры **в порядок их начал**. Больше ничего не меняется: ни тексты, ни
позиции, ни формат файла. При записи субтитры **нумеруются заново** с 1,
как и у любого файла, записываемого обратно.

**Ядро никогда не сортирует само**: чтение файла оставляет его порядок как был, а
[`inspect`](inspect.md#о-чём-сообщает-anomalies) сообщает о нарушении порядка словами
`subtitle N starts before the previous one starts`. `sort` — это **сознательное действие**, предназначенное для файла
или пакета с нарушенным порядком, и его можно отменить в окне, как любую операцию.

- **Сортировка устойчива**: два субтитра, начинающиеся в один и тот же момент, **сохраняют тот порядок, который
  дал им файл**. Ни один не идёт раньше другого; их перестановка была бы решением, о котором никто
  не просил.
- **`sort` не принимает ни диапазона, ни документа**: выбирать нечего, порядок определяется началами.

<!-- example: subedit-cli sort --help -->
```console
$ subedit-cli sort --help

Positionals:
  files TEXT ... REQUIRED     Subtitle files to sort

```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выключен; см. [Обработка дерева каталогов](lots.md) |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

## Что подсчитывается

**Подсчитываются места, сменившие субтитр**, как их сообщает ядро, — то, что
история в окне назвала бы перемещёнными. Один неверно стоящий субтитр сдвигает несколько других: в
примере выше ни одно из трёх мест не сохраняет свой субтитр, и фраза гласит `3 subtitles moved`.

**Файл, уже стоящий по порядку, всё равно записывается** и сообщает об этом: заданное место назначения — это
записанное место назначения, а если сделать `sort` исключением, скрипту пришлось бы знать, какие
подкоманды иногда создают файл, а иногда ничего.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ntrois\n\n' > ordre.srt; subedit-cli sort --output copie.srt ordre.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ntrois\n\n' > ordre.srt; subedit-cli sort --output copie.srt ordre.srt
ordre.srt: already in order -> copie.srt
```

## Вывод

**Стандартный вывод** — пусто: результат — это записанный файл. С параметром `--dry-run` тоже пусто: файла
нет, и строка пояснений сообщает об этом; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles moved -> <destination>`, или `<path>: already in order -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые как были |
| 3 | `<path>: N bytes read, M written`, затем **все диагностические сообщения чтения**; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит
`counts.subtitles` (все субтитры файла) и `counts.moved` (места, которые изменились;
`0` для файла, уже стоящего по порядку).

## Коды завершения

Те же, что у всего инструмента: `0`, если обработан каждый файл (файл, уже стоящий по порядку, тоже считается обработанным), `2`, если
не обработан ни один, `3`, если обработаны только некоторые, `1` при ошибке использования.

## Ошибки

Собственных ошибок у `sort` нет: нечитаемый файл вызывает сбой, как у любой подкоманды, а
ошибки места назначения общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).
