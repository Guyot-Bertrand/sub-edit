# `inspect`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli inspect [--frame-rate RATE] [--recursive] [--detail]
                   [-t FILE] [--align-method position|number] <file>...
```

Сообщает, из чего состоит каждый файл. **Ничего не изменяет и не записывает
файлов.**

<!-- example: subedit-cli inspect --help -->
```console
$ subedit-cli inspect --help
Report what a subtitle file is made of
Usage: subedit-cli inspect [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to report on

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --detail                    List every anomaly, subtitle by subtitle, instead of counting them
  --frame-rate RATE           Frame rate of a file counted in frames: 25, 23.976
  -t,--translation-file FILE  Translation file to lay over the subtitle file, for a single input
  --align-method position|number
                              How the lines of the translation find their subtitles
```

## Аргументы

| Аргумент | Обязательный | Значение | По умолчанию |
| :------- | :----- | :----- | :----- |
| `<file>...` | да | один или несколько путей к файлам субтитров | — |
| `--recursive`, `-r` | нет | флаг | выключен — см. [Обработка дерева каталогов](lots.md) |
| `--detail` | нет | флаг: называет каждую аномалию вместо того, чтобы считать их, — см. [О чём сообщает `anomalies`](#о-чём-сообщает-anomalies) | выключен |

Отсутствие путей — ошибка использования, то есть код `1`.

## Параметры

| Параметр | Обязательный | Значение | По умолчанию |
| :----- | :------ | :----- | :----- |
| `--frame-rate` | нет | частота в кадрах в секунду: `25`, `23.976`, `29.97` | 23,976 |

**Он нужен только для файлов, считаемых в кадрах**, то есть MicroDVD, единственного
из девяти форматов. Файл MicroDVD содержит одни лишь номера кадров; частота,
с которой они читаются, определяет **каждую позицию в отчёте**,
начиная с `span`. Если указать её для другого формата, она ничего не меняет и не является
ошибкой.

Значение, которое ничего не обозначает, — ошибка использования, то есть код `1`:

<!-- example: subedit-cli inspect --frame-rate douze film.sub; echo $? -->
```console
$ subedit-cli inspect --frame-rate douze film.sub; echo $?
--frame-rate: "douze" is not a frame rate: expected frames per second, like 25 or 23.976
1
```

Это тот же параметр, что и у [`convert`](convert.md), слово в слово, потому что
это та же частота. `convert` использует его также для **записи**.

## Перевод: `-t`

| Параметр | Обязательный | Значение | По умолчанию |
| :----- | :------ | :----- | :----- |
| `-t`, `--translation-file` | нет | файл перевода, для **одного** входного файла | — |
| `--align-method` | нет, и только вместе с `-t` | `position` или `number` | `position` |

С `-t` перевод накладывается на файл **так же, как это делает окно при открытии** (см.
[Перевод](invocation.md#перевод)), и в отчёте сказано, **как его строки нашли свой
субтитр**. Так скрипт узнаёт, выровнен ли перевод, прежде чем исправлять его.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nHello.\n\n2\n00:00:03,000 --> 00:00:04,000\nBye.\n\n' > film.srt; printf '1\n00:00:01,000 --> 00:00:02,000\nBonjour.\n\n' > film.fr.srt; subedit-cli --quiet inspect -t film.fr.srt film.srt | tail -3 -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nHello.\n\n2\n00:00:03,000 --> 00:00:04,000\nBye.\n\n' > film.srt; printf '1\n00:00:01,000 --> 00:00:02,000\nBonjour.\n\n' > film.fr.srt; subedit-cli --quiet inspect -t film.fr.srt film.srt | tail -3
  anomalies: none
  translation file: film.fr.srt, matched by position
  translation: 1 line attached; 1 subtitle left without a translation
```

Первая добавленная строка называет файл и метод; вторая — **та же фраза, которую выводит окно**
при открытии перевода, причём каждая часть выводится, только если она не равна нулю:

| Часть | Что считает |
| :----- | :---------------- |
| `N lines attached` | строки перевода, нашедшие субтитр основного файла |
| `N subtitles born of a line` | строки, не нашедшие ни одного и породившие собственные субтитры на своих позициях |
| `N subtitles left without a translation` | субтитры основного файла, до которых не дошла ни одна строка |
| `N lines out of order` | строки, шедшие в файле после более поздней |

Перевод, не содержащий ни одной строки, сообщает `translation: the file holds no line`. **Отчёт о самом
файле остаётся отчётом только о файле**: субтитр, порождённый строкой, не учитывается в
`subtitles`.

Ошибки `-t` — это ошибки чтения, сообщаемые с путём к переводу, и ещё одна:
`<translation>: the file is already open as the main document`, когда указанный файл — основной.
`--align-method` без `-t` — ошибка использования, как и `-t` с несколькими входными файлами; см.
[Перевод](invocation.md#перевод).

## Вывод

Отчёт направляется в **стандартный вывод**: это результат команды, и
он выводится на любом уровне, включая `--quiet`. Один блок на файл, перед которым
стоит путь:

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,500\nLe canot dérive.\n\n2\n00:00:04,000 --> 00:00:06,200\nPersonne n a vu la côte.\n' > exemple.srt; subedit-cli --quiet inspect exemple.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,500\nLe canot dérive.\n\n2\n00:00:04,000 --> 00:00:06,200\nPersonne n a vu la côte.\n' > exemple.srt; subedit-cli --quiet inspect exemple.srt
exemple.srt
  format: SubRip
  encoding: UTF-8, detected
  byte order mark: absent
  line endings: LF
  subtitles: 2
  span: 00:00:01.000 -> 00:00:06.200
  frame rate grid: none (too few subtitles to tell)
  anomalies: none
```

| Поле | Что сообщает |
| :---- | :----------- |
| `format` | один из форматов, принимаемых `--to`, в полном написании: `SubRip`, `WebVTT`, `SubViewer 2`, `Sub Station Alpha`, `Advanced SSA`, `MicroDVD`, `MPL2`, `TMPlayer`, `LRC` |
| `encoding` | прочитанная кодировка, затем **источник ответа**: `, from its byte order mark`, если её объявляет файл, `, as asked for`, если её навязал `--encoding`, `, detected`, если она была определена анализом |
| `byte order mark` | `present` или `absent` |
| `line endings` | `LF`, `CRLF` или `CR`, затем `, mixed from line N`, если файл их смешивает |
| `subtitles` | число прочитанных субтитров |
| `span` | от самого раннего начала до самого позднего конца, `HH:MM:SS.mmm` |
| `frame rate grid` | частота кадров, по которой были вычислены позиции, **выведенная** из них — см. ниже |
| `frame rate` | для файла, считаемого в кадрах, частота, с которой он был прочитан, и **её источник** — заменяет предыдущую строку, см. ниже |
| `anomalies` | `none` в той же строке или перечень неполадок: **по одному виду в строке с его числом**, с отступом под `anomalies:`; с `--detail` — **по одной аномалии в строке**, субтитр за субтитром |

**`span` — это не «от первого до последнего»**, а от самого раннего до самого позднего:
в файле с нарушенным порядком эти два значения различаются, и лишь второе говорит
правду о том, что охватывает файл.

**`anomalies` с `--detail` нумерует субтитры с 1**, как их нумерует файл,
а не по строкам файла. Номер субтитра переживает
изменение; номер строки — нет. См. ниже.

## О чём сообщает `frame rate grid`

**Файл субтитров не объявляет свою частоту кадров.** У SubRip нет
заголовка, а заголовок WebVTT — свободный текст. Поэтому эта строка ничего не читает:
она **выводит** частоту, измеряя, ложатся ли позиции на сетку кадров.

Измеряются **начала**. Везде, где есть сетка, они лежат на ней
без исключений, тогда как концы часто от неё отклоняются: конец
нередко вычисляется по правилу скорости чтения, а не ставится
на кадр.

Первая строка всегда говорит одно и то же: выбранную частоту, вердикт
и концентрацию, которая его подтверждает.

| Вердикт | Что означает |
| :------ | :----------------- |
| `clean` | позиции лежат на сетке |
| `partial` | часть позиций лежит на сетке, остальные нет |
| `none` | ни один кандидат ничего не объясняет |

У `none` **две причины, и ответы на них разные**: либо ни одна
сетка не подходит (тогда строка приводит лучшего кандидата и его оценку,
чтобы было видно, насколько он не подходит), либо в файле слишком мало
субтитров, чтобы можно было что-то сказать. Два начала всегда выглядят
идеально выровненными; это ничего не доказывает.

**Равномерный файл с нестандартной частотой даёт `none`, и так задумано.**
Набор кандидатов закрыт — это восемь частот, которые предлагает
преобразование, — и называть наименее неверную из них значило бы давать
неверный ответ там, где правильный — «не знаю».

### Строки, следующие дальше, когда им есть что сказать

| Строка | Когда появляется |
| :---- | :------------------ |
| `grid offset` | позиции лежат на сетке **с точностью до постоянной**: файл был сдвинут, и здесь указано, на сколько |
| `also fits` | другой кандидат подходит так же хорошо, потому что он кратен выбранному |
| `too short a span to separate` | протяжённость файла не позволяет отличить выбранную частоту от названных |
| `off the grid` | сколько начал отклоняется от сетки и в скольких **сериях** |

**`also fits` — это не колебание.** Сетка в 25 кадр/с
*включена* в сетку в 50 кадр/с: файл с таймингом по 25, следовательно, подходит к обеим.
Обратное неверно — настоящие 50 не сводятся к 25, — поэтому выбирается меньшая
частота, а другая называется, а не замалчивается. Это касается только
пар 25 и 50, 29,97 и 59,94, 30 и 60.

**`too short a span to separate` страхует от излишне самоуверенного ответа.** 23,976
и 24 расходятся на одну миллисекунду на секунду фильма: на полнометражном фильме они
различаются несомненно, на десяти секундах их не отличить. Строка сообщает,
какая из них остаётся возможной.

**`off the grid` различает две истории, которые один лишь процент смешивает.**
Много серий из единственного начала — это позиции, исправленные вручную
по одной. Несколько длинных серий — это заново расставленный по времени фрагмент или файл,
собранный из двух других. Отличает их число серий.

### Пример

Двенадцать строк, поставленных на сетку в 25 кадр/с, то есть на
позиции, кратные 40 миллисекундам, и растянутых почти на девять минут:

<!-- example: k=0; while [ $k -lt 12 ]; do s=$((1000 + k*47000 + (k%3)*40)); e=$((s+2000)); k=$((k+1)); printf '%d\n%02d:%02d:%02d,%03d --> %02d:%02d:%02d,%03d\nRéplique %d.\n\n' $k $((s/3600000)) $((s/60000%60)) $((s/1000%60)) $((s%1000)) $((e/3600000)) $((e/60000%60)) $((e/1000%60)) $((e%1000)) $k; done > grille.srt; subedit-cli --quiet inspect grille.srt | tail -3 -->
```console
$ k=0; while [ $k -lt 12 ]; do s=$((1000 + k*47000 + (k%3)*40)); e=$((s+2000)); k=$((k+1)); printf '%d\n%02d:%02d:%02d,%03d --> %02d:%02d:%02d,%03d\nRéplique %d.\n\n' $k $((s/3600000)) $((s/60000%60)) $((s/1000%60)) $((s%1000)) $((e/3600000)) $((e/60000%60)) $((e/1000%60)) $((e%1000)) $k; done > grille.srt; subedit-cli --quiet inspect grille.srt | tail -3
  frame rate grid: 25 fps, clean (100.0%)
  also fits: 50 fps, of which this rate is a whole divisor
  anomalies: none
```

Пример создаёт собственный файл, а не читает файл из репозитория, и это
сделано намеренно: его можно воспроизвести как есть, а цикл показывает, что такое сетка,
лучше любой фразы: позиции, кратные длительности кадра.

## О чём сообщает `frame rate` и почему это не сетка

**Лишь один из девяти форматов считает в кадрах**: MicroDVD, каждая строка которого
содержит два номера кадров и больше ничего. Для такого файла `inspect`
выводит не `frame rate grid`, а `frame rate`, и две эти строки
никогда не показываются вместе.

**Причину можно выразить одной фразой.** Позиции файла MicroDVD были
вычислены *из* его кадров при заданной частоте; выведение их из
сетки вернуло бы ту самую частоту, которая только что была задана. Это было бы
заданное число, выдаваемое за измерение.

Вместо этого выводится **частота чтения и её источник** —
в том же виде, что и строка `encoding`:

| Что говорит строка | Когда |
| :------------------ | :---- |
| `frame rate: 25 fps, as asked for` | её навязал `--frame-rate` |
| `frame rate: 24000/1001 fps, assumed` | никто её не указал; это значение по умолчанию |

**Два ответа, а не три**, как у `encoding`: файл MicroDVD
ничего не объявляет. В этом вся проблема: частота обязательно приходит
извне, и отчёт говорит, из какого из двух источников.

**Частота определяет весь остальной отчёт.** `span` зависит от неё, и два
чтения одного файла с двумя частотами дают два разных промежутка:

<!-- example: printf '{25}{75}Première.\n{100}{150}Deuxième.\n{200}{260}Troisième.\n' > images.sub; subedit-cli --quiet inspect images.sub | tail -3; subedit-cli --quiet inspect --frame-rate 25 images.sub | tail -3 -->
```console
$ printf '{25}{75}Première.\n{100}{150}Deuxième.\n{200}{260}Troisième.\n' > images.sub; subedit-cli --quiet inspect images.sub | tail -3; subedit-cli --quiet inspect --frame-rate 25 images.sub | tail -3
  span: 00:00:01.043 -> 00:00:10.844
  frame rate: 24000/1001 fps, assumed
  anomalies: none
  span: 00:00:01.000 -> 00:00:10.400
  frame rate: 25 fps, as asked for
  anomalies: none
```

## О чём сообщает `anomalies`

В документе могут быть неверны три вещи, и каждая исправляется по-своему.
**По умолчанию `inspect` считает их**, по одной строке на вид, в порядке таблицы:
в плохо сделанном файле их сотни, и знание того, сколько их каждого вида,
подсказывает, что запускать. **`--detail` называет их по одной.**

| Что записано | С `--detail` | Что означает |
| :--------------- | :-------------- | :------------------ |
| `subtitle ends before it starts: N` | `subtitle N ends before it starts` | конец раньше начала |
| `subtitle starts before the previous one ends: N` | `subtitle N starts before the previous one ends` | перекрывает предыдущий |
| `subtitle starts before the previous one starts: N` | `subtitle N starts before the previous one starts` | нарушает порядок файла — [`sort`](sort.md) возвращает его |

Отсутствующий вид не выводится. В левом столбце `N` — число
субтитров; в следующем — номер субтитра.

**Один и тот же субтитр может появиться дважды**, и это задумано: субтитр, который
начинается раньше начала предыдущего, начинается также раньше его
конца. Первое решается перемещением субтитра, второе —
изменением длительности.

**Называется тот субтитр, который стоит не на месте**, а не тот, относительно которого он
сдвинут. При началах `0`, `4 s`, `2 s`, `3 s` третий нарушает порядок, а
четвёртый как раз следует за третьим и потому не называется: делать с ним
нечего.

<!-- example: printf '1\n00:00:00,000 --> 00:00:00,500\nA\n\n2\n00:00:04,000 --> 00:00:04,500\nB\n\n3\n00:00:02,000 --> 00:00:02,500\nC\n\n4\n00:00:03,000 --> 00:00:03,500\nD\n' > desordre.srt; subedit-cli --quiet inspect desordre.srt | tail -3 -->
```console
$ printf '1\n00:00:00,000 --> 00:00:00,500\nA\n\n2\n00:00:04,000 --> 00:00:04,500\nB\n\n3\n00:00:02,000 --> 00:00:02,500\nC\n\n4\n00:00:03,000 --> 00:00:03,500\nD\n' > desordre.srt; subedit-cli --quiet inspect desordre.srt | tail -3
  anomalies:
    subtitle starts before the previous one ends: 1
    subtitle starts before the previous one starts: 1
```

А с `--detail` называется субтитр:

<!-- example: printf '1\n00:00:00,000 --> 00:00:00,500\nA\n\n2\n00:00:04,000 --> 00:00:04,500\nB\n\n3\n00:00:02,000 --> 00:00:02,500\nC\n\n4\n00:00:03,000 --> 00:00:03,500\nD\n' > desordre.srt; subedit-cli --quiet inspect --detail desordre.srt | tail -3 -->
```console
$ printf '1\n00:00:00,000 --> 00:00:00,500\nA\n\n2\n00:00:04,000 --> 00:00:04,500\nB\n\n3\n00:00:02,000 --> 00:00:02,500\nC\n\n4\n00:00:03,000 --> 00:00:03,500\nD\n' > desordre.srt; subedit-cli --quiet inspect --detail desordre.srt | tail -3
  anomalies:
    subtitle 3 starts before the previous one ends
    subtitle 3 starts before the previous one starts
```

**Одна строка на аномалию с `--detail`**, потому что сто находок,
склеенных в одну строку, нельзя ни прочитать, ни найти поиском. Документ без дефектов сохраняет
единственную строку `anomalies: none`, которую ищет скрипт. **Запись
`--format json` всегда перечисляет каждую аномалию**: скрипт читает подробности, а
`--detail` меняет только текст.

**Это не диагностическое сообщение чтения.** Диагностические сообщения говорят о том, с чем
столкнулось чтение, и указывают на **строку файла**; аномалии говорят о том,
*каков* документ, и указывают на **субтитр**. Файл с нарушенным порядком
при этом не считается повреждённым: чтению сказать о нём нечего.

## В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) `inspect` выводит **по одному
объекту на файл** вместо блоков, описанных выше; пояснения остаются в потоке ошибок.
Ключи описывают то, что говорит текст, и **ни один из них не нужно извлекать из фразы**:

| Ключ | Содержимое |
| :-- | :------ |
| `format` | идентификатор формата, принимаемый `convert --to`: `srt`, `vtt`… |
| `encoding` | `{"charset", "origin", "byte_order_mark"}` — `origin` равен `byte-order-mark`, `asked` или `detected` |
| `line_endings` | `{"kind", "mixed_from_line"}` — `lf`, `crlf` или `cr`; строка, где появляется второй вид, или `null` |
| `subtitles` | число субтитров |
| `span_ms` | `{"start", "end"}` — первое начало и последний конец в миллисекундах |
| `frame_rate` | для файла, считаемого в кадрах: `{"rate", "origin"}` (`asked` или `assumed`); иначе `null` |
| `grid` | для остальных: выведенная сетка или `null` для файла, считаемого в кадрах |
| `anomalies` | массив из `{"subtitle", "kind"}` — `end-before-start`, `overlapping-subtitles`, `out-of-order` |
| `translation` | **только с `-t`**: `{"file", "method", "attached", "born", "untranslated", "out_of_order"}` — `method` равен `position` или `number`, а четыре числа — те, что в приведённой выше фразе |
| `warnings` | то, с чем столкнулось чтение, на любом уровне |

`grid` содержит `verdict` (`clean`, `partial` или `silent`), `enough_starts`, `rate` (строка
или `null`, если ничего не названо), `concentration_permille` (тысячные доли, `null` при нехватке
начал), `offset_ms`, `also_fits` (частота, целым делителем которой является данная, или
`null`), `not_separated` (частоты, которые слишком короткая протяжённость не позволяет различить), `strays`
(начала вне сетки) и `starts`.

<!-- example: printf '{25}{50}Un.\n{75}{100}Deux.\n' > f.sub; subedit-cli --format json inspect --frame-rate 25 f.sub 2>/dev/null -->
```console
$ printf '{25}{50}Un.\n{75}{100}Deux.\n' > f.sub; subedit-cli --format json inspect --frame-rate 25 f.sub 2>/dev/null
{"schema":1,"command":"inspect","file":"f.sub","ok":true,"format":"microdvd","encoding":{"charset":"UTF-8","origin":"detected","byte_order_mark":false},"line_endings":{"kind":"lf","mixed_from_line":null},"subtitles":2,"span_ms":{"start":1000,"end":4000},"frame_rate":{"rate":"25","origin":"asked"},"grid":null,"anomalies":[],"warnings":[]}
```

## Пояснения

В потоке ошибок, в зависимости от запрошенного уровня:

| Уровень | Что добавляется |
| :----- | :-------------- |
| 1 | `<path>: N subtitles` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings` |
| 3 | `<path>: N bytes read`, `<path>: N diagnostic(s) while reading`, затем **каждое из них** — см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

## Коды завершения

Коды самой программы: `0`, если прочитаны все файлы, `2`, если не прочитан ни один, `3`, если
прочитаны лишь некоторые, `1` при ошибке использования.

## Ошибки

Ошибки чтения (файла, а при указании `-t` и перевода) и
ошибки `-t`: см. выше. `inspect` ничего не записывает, так что отказывать нечему.

| Что её вызывает | Сообщение |
| :------------------ | :------ |
| путь не указан | `files is required`, затем указание на `--help` |
| отсутствующий файл | `<path>: does not exist` |
| нечитаемый файл | `<path>: cannot be opened: permission denied` |
| байты, которые не декодируются | `<path>: cannot be decoded in the chosen encoding` |
| формат не распознан | `<path>: is in no format this tool knows` |
| ничего, похожего на субтитр | `<path>: holds nothing recognisable as a subtitle` |

Эти сообщения одинаковы для всех семнадцати подкоманд: порядок открытия
файла записан один раз, в ядре.

## Пример с ошибкой

Пустой файл не соответствует ни одному формату. О нём не сообщается, что он пуст:
он отвергается и называется по имени.

<!-- example: : > vide.srt; subedit-cli inspect vide.srt; echo "code=$?" -->
```console
$ : > vide.srt; subedit-cli inspect vide.srt; echo "code=$?"
vide.srt: is in no format this tool knows
code=2
```
