# `pair`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli pair (--output FILE | --output-dir DIR | --in-place)
                 -t FILE [--align-method position|number]
                 [--dry-run]
                 <main>
```

Записывает **перевод, перетаймированный по позициям основного файла**, и сообщает, как его строки нашли свой
субтитр. Это `Open Translation…` окна — [то же сопоставление](../subedit-gui/files.md#открытие-перевода),
та же формулировка, — за которым следует запись результата; в окне её выполняет `Save Translation`.

**Это единственное, что делает сопоставление и чего не делает отдельно обработанный файл.** Остальные подкоманды,
принимающие `-t`, изменяют читаемый ими перевод — [`case`](case.md), [`replace`](replace.md) и другие; `pair` не меняет
в тексте ничего: он **накладывает** перевод на основной файл и записывает то, что получилось при наложении. Основной файл
читается, чтобы принять строки, и **никогда не записывается**.

- **Записывается перевод** — **по его собственному пути и в его собственном формате**: формат, кодировка и
  символы конца строки файла перевода. Его субтитры стоят **на позициях основного файла**: строка, которая
  упала мимо метки, возвращает себе границы субтитра, который она переводит.
- **Параметр `-t` обязателен.** Без перевода `pair` нечего накладывать: это ошибка использования, код `1`.
- **Один основной файл** и никакого `--recursive`: пара — это два файла, а дерево каталогов не
  может сказать, какой перевод относится к какому основному файлу. Для пакета — по одному запуску на пару.
- **`--output` задаёт файл записываемого перевода, `--output-dir` помещает туда его базовое имя, `--in-place`
  перезаписывает его** — как у любой подкоманды, принимающей `-t`; см. [Перевод](invocation.md#перевод).
- **Параметра `--document` не существует**: целевой документ только один — перевод.

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<main>` | да | **один** путь | — |
| `-t`, `--translation-file` | **да** | файл перевода | — |
| `--align-method` | нет | `position` или `number`; см. [Перевод](invocation.md#перевод) | `position` |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nHello.\n\n2\n00:00:03,000 --> 00:00:04,000\nBye.\n\n' > film.srt; printf '1\n00:00:01,300 --> 00:00:02,300\nBonjour.\n\n2\n00:00:03,300 --> 00:00:04,300\nAu revoir.\n\n' > film.fr.srt; subedit-cli pair film.srt -t film.fr.srt --output recale.fr.srt; cat recale.fr.srt

1
00:00:01,000 --> 00:00:02,000
Bonjour.

2
00:00:03,000 --> 00:00:04,000
Au revoir.
```

Перевод запаздывал на 0,3 с: каждая строка нашла субтитр, с которым пересекается её середина, и
записанный файл несёт позиции основного файла.

## Что сообщает выравнивание

Формулировка **та же, что и в окне** при открытии перевода; каждая часть приводится, только если она не
равна нулю; таблицу её частей см. в разделе [`inspect -t`](inspect.md#перевод--t). **Она выводится
начиная с уровня 1**, а не с уровня 2, как у других подкоманд: здесь выравнивание — не
подробность обработки, а результат.

**Что выравнивание делает с записываемым файлом**:

- **субтитр, который никто не переводил, записывается как блок без текста**, читаемый без аномалий;
- **субтитр, рождённый из строки** — строки, до которой ничто не дошло, — записывается **со своими собственными позициями** при любом
  методе: поэтому записанный файл может содержать больше субтитров, чем основной;
- **всё, что документ содержал в качестве перевода, очищается** перед наложением; в командной строке это неприменимо:
  основной файл читается один.

**Два метода** дают один и тот же файл, когда каждая строка попадает на свой субтитр, и не
дают, когда строки не хватает или перевод сдвинут, — поэтому метод выбирается, и поэтому
по умолчанию используется позиция. Восемь случаев из `src/test/data/paires/` перечисляют их вместе с файлом, ожидаемым для
каждого метода.

## Вывод

**Стандартный вывод** — пусто: результат — это записанный файл.

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<translation>: translation: N lines attached; … -> <destination>` — **путь принадлежит переводу**, то есть записываемому файлу; при `--dry-run` вместо `-> <destination>` выводится `(dry run, nothing written)` |
| 2 | `<translation>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки **перевода**, возвращённые как были |
| 3 | `<translation>: N bytes read, M written`, затем **все диагностические сообщения чтения** основного файла и перевода; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) — **один объект**, где `file` — это перевод, а
`destination` — записанный файл. `counts.subtitles` считает **субтитры записанного файла**, включая те, которым
дала жизнь строка. Ключ `alignment` — `{"file", "method", "attached", "born", "untranslated", "out_of_order"}` —
несёт те же числа, что и формулировка, как и ключ `translation` у [`inspect`](inspect.md#в-формате-json).

## Коды завершения

Те же, что у всего инструмента: `0`, если перевод записан (или вычислен, при `--dry-run`), `2`, если один из двух файлов не удалось
прочитать или не удалось записать место назначения, `1` при ошибке использования. **Плохо выровненный перевод не
является сбоем**: он записывается, а формулировка сообщает, что не нашло своего места.

## Ошибки

| Что их вызывает | Сообщение |
| :------------------- | :------ |
| нет `-t` | `pair needs the translation file to lay over the main one: use -t` |
| `--document` | `The following argument was not expected: --document` — для `pair` его не существует |
| больше одного основного файла | `The following argument was not expected: <path>` |
| перевод совпадает с основным файлом | `<translation>: the file is already open as the main document`, код `2` |
| один из файлов отсутствует, нечитаем или имеет неизвестный формат | то же, что везде, с путём к проблемному файлу |
