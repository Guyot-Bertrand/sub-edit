# `shift`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli shift (--by <time> | --to-grid)
                  (--output FILE | --output-dir DIR | --in-place)
                  [--dry-run]
                  [--recursive]
                  <file>...
```

Сдвигает **каждую** позицию файла на одну и ту же величину в ту или
другую сторону. Ни один субтитр не остаётся на экране ни дольше, ни короче:
именно это делает сдвиг сдвигом.

<!-- example: subedit-cli shift --help -->
```console
$ subedit-cli shift --help
Move every position of a file by a fixed amount
Usage: subedit-cli shift [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to shift

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --by TEXT                   Amount to move by: 2.999, -7.001, or 00:00:07.001
  --to-grid                   Move by the amount that puts the positions back on their frame grid
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выключен; см. [Обработка дерева каталогов](lots.md) |
| `--by` | **один из двух** | длительность со знаком, см. ниже | — |
| `--to-grid` | **один из двух** | флаг: величина измеряется, см. ниже | — |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

Формат читаемого файла **сохраняется**: смена формата — это дело
[`convert`](convert.md).

## `--to-grid`: величина измеряется, а не задаётся

Файл, позиции которого лежат на сетке кадров **с точностью до
константы**, был сдвинут, и эту константу можно измерить по самим позициям.
`--to-grid` измеряет её и применяет, не требуя, чтобы кто-либо её знал.

Величина **своя у каждого файла**: два файла, сдвинутых относительно одной и той же
сетки на две разные величины, возвращаются каждый на свою. Она
указывается в пояснениях вместе с найденной частотой кадров.

**Выбирается кратчайший путь.** Если превышена половина кадра, ближайшая линия сетки —
следующая: поправка идёт вперёд, а не назад почти на
целый кадр.

<!-- example: k=0; while [ $k -lt 12 ]; do s=$((1000 + k*47000 + (k%3)*40 + 7)); e=$((s+2000)); k=$((k+1)); printf '%d\n%02d:%02d:%02d,%03d --> %02d:%02d:%02d,%03d\nRéplique %d.\n\n' $k $((s/3600000)) $((s/60000%60)) $((s/1000%60)) $((s%1000)) $((e/3600000)) $((e/60000%60)) $((e/1000%60)) $((e%1000)) $k; done > decale.srt; subedit-cli shift --to-grid --output recale.srt decale.srt -->
```console
$ k=0; while [ $k -lt 12 ]; do s=$((1000 + k*47000 + (k%3)*40 + 7)); e=$((s+2000)); k=$((k+1)); printf '%d\n%02d:%02d:%02d,%03d --> %02d:%02d:%02d,%03d\nRéplique %d.\n\n' $k $((s/3600000)) $((s/60000%60)) $((s/1000%60)) $((s%1000)) $((e/3600000)) $((e/60000%60)) $((e/1000%60)) $((e%1000)) $k; done > decale.srt; subedit-cli shift --to-grid --output recale.srt decale.srt
decale.srt: 12 subtitles shifted by -0.007 s onto their 25 fps grid -> recale.srt
```

**Файл, не лежащий ни на одной известной сетке, отклоняется, и причина называется.**
Возвращать нечего, а фаза, измеренная по шуму, сдвинула бы файл
наугад. Чтобы узнать, что даёт файл, до того как пробовать операцию, см. [`inspect`](inspect.md#о-чём-сообщает-frame-rate-grid).

`--by` и `--to-grid` оба говорят, на сколько сдвигать: указать их вместе
— ошибка использования, и не указать ни одного — тоже.

**`--to-grid` — это не [`snap`](snap.md).** Он сдвигает весь файл
на одну и ту же величину и **точно** сохраняет относительный тайминг; `snap`
перемещает каждую позицию независимо и попутно поглощает те, что
были исправлены вручную. На чистом файле результат у обоих одинаков;
на частичном файле — нет.

## Запись длительности

Две формы, и только две:

| Форма | Примеры |
| :---- | :------- |
| секунды | `30`, `2.999`, `-7.001`, `+1.5` |
| тайм-код | `00:00:07.001`, `01:39:37.040`, `-00:00:07.001` |

Обе говорят одно и то же: `--by 7.001` и `--by 00:00:07.001` дают
один и тот же файл.

**Десятичный разделитель — точка**, поскольку командная строка говорит по-английски.
Запятая отклоняется, а не истолковывается: половина мира пишет `7,001`
для семи тысяч одного, и прочитать это как семь секунд было бы догадкой,
причём для этой половины неверной.

**Разрешение — миллисекунда.** Более мелкое отклоняется, а не округляется
молча: тихое округление дало бы результат, не соответствующий ничему из того,
что было запрошено.

<!-- example: printf '1\n00:00:10,000 --> 00:00:12,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by -7.001 --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:10,000 --> 00:00:12,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by -7.001 --output b.srt a.srt; cat b.srt
a.srt: 1 subtitle shifted by -7.001 s -> b.srt
1
00:00:02,999 --> 00:00:04,999
Bonjour.
```

## Сдвиг до начала отсчёта отклоняется

Сдвиг назад за нуль даёт код `2` и **ничего не записывает**. Сообщение называет
субтитр, который не смог принять сдвиг, и тем самым говорит,
как далеко можно зайти.

Причина не принципиальная: позиция до начала отсчёта записывается как
`-00:00:01,000`, а такой формы не определяет ни один из девяти форматов и ни один читатель
её не принимает. Ядро такие позиции допускает — отказ от них сделал бы
операцию редактирования особым случаем, — но файл — это нечто иное, чем
модель в памяти.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by -7.001 --output b.srt a.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli shift --by -7.001 --output b.srt a.srt; echo "code=$?"
a.srt: subtitle 1 would start before the origin, which no subtitle file can hold
code=2
```

## Вывод

**Стандартный вывод** — пусто: результат — это записанный файл. С параметром `--dry-run` тоже пусто: файла нет, и строка пояснений сообщает об этом; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles shifted by 2.999 s -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые как были |
| 3 | `<path>: N bytes read, M written`, затем **все диагностические сообщения чтения**; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит `counts.subtitles` (все субтитры файла) и `counts.shifted_by_ms` (сдвиг в целых миллисекундах, **со знаком**). Полная таблица находится в разделе [Запуск](invocation.md#что-каждая-подкоманда-помещает-в-counts).

## Коды завершения

Те же, что у всего инструмента: `0`, если записан каждый файл, `2`, если не записан ни один, `3`, если
записаны только некоторые, `1` при ошибке использования.

## Ошибки

| Что её вызывает | Сообщение |
| :------------------ | :------ |
| десятичная запятая | `"…" is not a time: use a decimal point and not a comma, in every language` |
| точнее миллисекунды | `"…" is not a time: positions are held to the millisecond, no finer` |
| текст, не являющийся длительностью | `"…" is not a time: expected seconds like 2.999, or a timestamp like 00:00:07.001` |
| сдвиг до начала отсчёта | `<path>: subtitle N would start before the origin, which no subtitle file can hold` |

**Без одного из трёх параметров места назначения ничего не записывается**, а
ошибки, связанные с ним, общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).
