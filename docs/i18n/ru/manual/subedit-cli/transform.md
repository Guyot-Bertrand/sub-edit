# `transform`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli transform --first <index>=<time> --last <index>=<time>
                      (--output FILE | --output-dir DIR | --in-place)
                      [--dry-run]
                      [--recursive]
                      <file>...
```

Исправляет **каждую** позицию файла по двум точкам, правильное значение которых
известно. Это операция, которой требует «плывущий» тайминг субтитров
— верный в начале, неверный в конце, — где [`shift`](shift.md), сдвигающий всё на
одну и ту же величину, бессилен.

Формат читаемого файла **сохраняется**: смена формата — это дело
[`convert`](convert.md).

<!-- example: subedit-cli transform --help -->
```console
$ subedit-cli transform --help
Correct every position from two points known to be right
Usage: subedit-cli transform [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to transform

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --first TEXT REQUIRED       Earlier reference, as <index>=<time>: 1=00:00:01.000
  --last TEXT REQUIRED        Later reference, as <index>=<time>: 3=00:00:10.000
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выключен; см. [Обработка дерева каталогов](lots.md) |
| `--first` | **да** | ссылка, `<index>=<time>` | — |
| `--last` | **да** | ссылка, `<index>=<time>` | — |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

Краткой формы нет: эти два параметра записываются только
полностью.

## Запись ссылки

Ссылка называет субтитр и указывает, где теперь должно оказаться его **начало**:

```
<index>=<time>
```

**Индекс считается с 1**, как он показан и как нумерует
файл SubRip. `0` отклоняется, как и индекс за последним
субтитром.

**Время записывается так же, как у [`shift`](shift.md)** — секунды или
тайм-код, десятичный разделитель — точка, разрешение — миллисекунда:

| Форма | Примеры |
| :---- | :------- |
| секунды | `10`, `2.999` |
| тайм-код | `00:00:10.000`, `01:39:37.040` |

`--first 3=10` и `--first 3=00:00:10.000` означают одно и то же.

`--first` и `--last` называют две точки, а не интервал. Их имена
указывают на ожидаемое использование — одна ссылка в начале файла, другая в конце, — а не на
ограничение: если их поменять местами, результат будет тем же, а **всё, что находится вне
двух ссылок, следует за тем, что находится между ними**.

## Во что превращаются остальные позиции

Две ссылки задают масштабный коэффициент, и каждая позиция ему следует:

```
t′ = y₁ + (t − x₁) × r      with r = (y₂ − y₁) / (x₂ − x₁)
```

`x₁`, `x₂` — текущие начала двух названных субтитров, `y₁`, `y₂` —
запрошенные моменты времени. Коэффициент хранится как точное рациональное число, а **округление
выполняется только один раз**, до миллисекунды; благодаря этому обе
ссылки попадают **точно** на запрошенные моменты, а не с точностью до тысячной
(см. [ADR 0013](../../../../adr/0013-mise-a-l-echelle-exacte-des-positions.md)).

Каждый субтитр остаётся на экране **пропорционально** тому, как долго он там
был: конец следует тому же масштабу, что и начало. Преобразование — это не
сдвиг, и свойства сдвига у него нет.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n2\n00:00:05,001 --> 00:00:07,000\nDeux.\n\n3\n00:00:09,000 --> 00:00:11,000\nTrois.\n\n' > a.srt; subedit-cli transform --first 1=00:00:01.000 --last 3=00:00:10.000 --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n2\n00:00:05,001 --> 00:00:07,000\nDeux.\n\n3\n00:00:09,000 --> 00:00:11,000\nTrois.\n\n' > a.srt; subedit-cli transform --first 1=00:00:01.000 --last 3=00:00:10.000 --output b.srt a.srt; cat b.srt
a.srt: 3 subtitles transformed onto 1=00:00:01.000 and 3=00:00:10.000 -> b.srt
1
00:00:01,000 --> 00:00:03,250
Un.

2
00:00:05,501 --> 00:00:07,750
Deux.

3
00:00:10,000 --> 00:00:12,250
Trois.
```

Первая ссылка не сдвигается, третья переходит с 9 с на 10 с: коэффициент равен
`9/8`, а второй субтитр, который никто не называл, переходит с
`5,001` на `5,501`, то есть `1000 + 4001 × 9/8`, округлённое один раз.

## Две ссылки, которые таковыми не являются

| Ситуация | Когда обнаруживается | Код |
| :-------- | :------------- | :--- |
| `--first` и `--last` называют один и тот же индекс | до любого чтения | `1` |
| индекс выходит за последний субтитр | при открытии файла | `2` или `3` |
| два названных субтитра начинаются в один и тот же момент | при открытии файла | `2` или `3` |

Все три случая отклоняются по одной причине: `x₂ − x₁` равно нулю, а две
совпадающие точки не задают прямой. Вернуть деление на нуль, выдав его за
результат, было бы хуже, чем отказать.

Первый случай — **ошибка использования**: виноваты два параметра независимо от
файлов, поэтому нужно одно сообщение, а не по одному на файл. Два
других зависят от открытого файла и потому считаются
сбоем обработки.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n' > a.srt; subedit-cli transform --first 2=1.000 --last 2=4.000 --output b.srt a.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n' > a.srt; subedit-cli transform --first 2=1.000 --last 2=4.000 --output b.srt a.srt; echo "code=$?"
--first and --last both name subtitle 2, and two references on one subtitle define no transform
code=1
```

Индекс за пределами допустимого отклоняется **с указанием границы**, что говорит заодно
и о том, что можно было написать:

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n2\n00:00:05,000 --> 00:00:07,000\nDeux.\n\n' > a.srt; subedit-cli transform --first 1=1.000 --last 9=10.000 --output b.srt a.srt; echo "code=$?" -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nUn.\n\n2\n00:00:05,000 --> 00:00:07,000\nDeux.\n\n' > a.srt; subedit-cli transform --first 1=1.000 --last 9=10.000 --output b.srt a.srt; echo "code=$?"
a.srt: subtitle 9 is past the end: the file holds 2 subtitles
code=2
```

## Позиция до начала отсчёта отклоняется

Как и у [`shift`](shift.md), и по той же причине: отрицательная позиция
записывается как `-00:00:01,000`, а такой формы не определяет ни один из девяти форматов и ни один
читатель её не принимает. Здесь это случается, когда субтитр лежит **до
первой ссылки**, а масштаб отодвигает его за нуль. Ничего не
записывается, код равен `2`, а сообщение называет проблемный субтитр.

## Вывод

**Стандартный вывод** — пусто: результат — это записанный файл. С параметром `--dry-run` тоже пусто: файла нет, и строка пояснений сообщает об этом; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles transformed onto 1=00:00:01.000 and 3=00:00:10.000 -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые как были |
| 3 | `<path>: N bytes read, M written`, затем **все диагностические сообщения чтения**; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

Ссылки записываются обратно с десятичной точкой, как бы они ни были набраны.

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит `counts.subtitles` (все субтитры файла). Полная таблица находится в разделе [Запуск](invocation.md#что-каждая-подкоманда-помещает-в-counts).

## Коды завершения

Те же, что у всего инструмента: `0`, если записан каждый файл, `2`, если не записан ни один, `3`, если
записаны только некоторые, `1` при ошибке использования.

## Ошибки

| Что её вызывает | Сообщение |
| :------------------ | :------ |
| ссылка без `=` | `"…" is not a reference: write it <index>=<time>, as in 3=00:00:10.000` |
| в ссылке нет одной из двух половин | `"…" is missing one of its two halves: write it <index>=<time>, as in 3=00:00:10.000` |
| индекс `0` | `"0" is not a subtitle number: subtitles are counted from 1, as the file shows them` |
| индекс не является целым числом | `"…" is not a subtitle number: expected a whole number, counted from 1 as the file shows them` |
| неверное время | те же, что у [`shift`](shift.md) |
| `--first` и `--last` с одним и тем же индексом | `--first and --last both name subtitle N, and two references on one subtitle define no transform` |
| индекс за пределами допустимого | `<path>: subtitle N is past the end: the file holds M subtitles` |
| два субтитра, начинающиеся одновременно | `<path>: subtitles N and M start at the same moment, so they define no transform` |
| позиция до начала отсчёта | `<path>: subtitle N would land before the origin, which no subtitle file can hold` |

**Без одного из трёх параметров места назначения ничего не записывается**, а
ошибки, связанные с ним, общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).
