# `disjoint`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli disjoint (--output FILE | --output-dir DIR | --in-place)
                     [--minimum TIME] [--max-lines N] [--dashes] [--sort]
                     [--dry-run] [--recursive]
                     <file>...
```

Разрезает перекрывающиеся субтитры так, чтобы **ни один диапазон `[start, end]` больше
не перекрывал другой**. Это `Make Ranges Disjoint…` из окна — [тот же движок](../subedit-gui/lines.md#устранение-перекрытий-диапазонов).

**Ничего не укорачивается и не удлиняется**: в любой момент файл показывает те же тексты, что и прежде. Меняется
только то, как разрезана шкала времени:

- она режется по **каждому началу и каждому концу** субтитров перекрывающейся группы;
- интервал, покрытый **одним** субтитром, остаётся этим субтитром;
- интервал, покрытый **несколькими**, становится **одним** субтитром, строки которого — их строки, **в
  порядке их начал**: самый ранний в строке 1, следующий в строке 2;
- субтитр, который ничего не перекрывает, не затрагивается, а порядок остальных сохраняется.

<!-- example: subedit-cli disjoint --help -->
```console
$ subedit-cli disjoint --help
Cut overlapping subtitles so that no range overlaps another, merging what overlaps
Usage: subedit-cli disjoint [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to make disjoint

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --minimum TIME              Shortest interval kept; a shorter one is taken over by a neighbour (default 0.08)
  --max-lines N               Most lines of a merged subtitle; more are shown in windows, 0 for no limit (default 2)
  --dashes                    Put a dash before the text of each merged subtitle
  --sort                      Put the subtitles in order of their start first; without it, a file out of order is refused
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--minimum` | нет | длительность: `0.08`, `1.5`, `00:00:00,080`. При нуле сохраняется каждый интервал | `0.08` (около двух кадров) |
| `--max-lines` | нет | целое число: наибольшее число строк объединённого субтитра; `0` снимает предел | `2` |
| `--dashes` | нет | флаг: тире перед текстом, который каждый субтитр вносит в объединённый субтитр | выключен |
| `--sort` | нет | флаг: **сначала** расставляет субтитры в порядке их начал — см. [Нужен файл с правильным порядком](#нужен-файл-с-правильным-порядком) | выключен |
| `--recursive`, `-r` | нет | флаг | выключен — см. [Обработка дерева каталогов](lots.md) |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

<!-- example: printf '1\n00:00:00,000 --> 00:00:05,000\nA\n\n2\n00:00:03,000 --> 00:00:08,000\nB\n\n' > chevauche.srt; subedit-cli disjoint --output disjoint.srt chevauche.srt; cat disjoint.srt -->
```console
$ printf '1\n00:00:00,000 --> 00:00:05,000\nA\n\n2\n00:00:03,000 --> 00:00:08,000\nB\n\n' > chevauche.srt; subedit-cli disjoint --output disjoint.srt chevauche.srt; cat disjoint.srt
chevauche.srt: 2 subtitles split, 1 merged -> disjoint.srt
1
00:00:00,000 --> 00:00:03,000
A

2
00:00:03,000 --> 00:00:05,000
A
B

3
00:00:05,000 --> 00:00:08,000
B
```

`A [0, 5]` и `B [3, 8]` дают три непересекающихся субтитра: `A` отдельно, `A` и `B` вместе, `B` отдельно. Ни один
момент не теряется и не добавляется.

## Что решает операция

**Строка никогда не дублируется.** Два субтитра с одинаковым текстом дают одну строку там, где они
перекрываются, а две соседние части, показывающие одно и то же, образуют лишь один субтитр. В остальном текст
субтитра, разрезанного на несколько частей, **повторяется в каждой из них**: это то, что находится на экране в
данный момент.

**Очень короткий интервал поглощается соседом.** Интервал короче значения `--minimum` исчезает: сосед
**расширяет свой диапазон, чтобы покрыть его**, так что ни один момент не остаётся пустым и ничто не сдвигается больше, чем на
этот порог. Выбирается тот сосед, строки которого **уже содержат** строки интервала, а при отсутствии такого —
более длинный. Текст интервала теряется, только если его не несёт ни один сосед, и тогда менее чем на длительность порога.
**Целый субтитр короче порога никогда не поглощается**: он остаётся на месте и учитывается в счётчике.

**Строк больше предела: окна.** Объединённый субтитр, в котором оказалось бы больше строк, чем задано `--max-lines`,
показывается **в последовательных окнах** этого размера, равными долями длительности. Три строки на протяжении трёх
секунд:

<!-- example: printf '1\n00:00:00,000 --> 00:00:03,000\nA\n\n2\n00:00:00,000 --> 00:00:03,000\nB\n\n3\n00:00:00,000 --> 00:00:03,000\nC\n\n' > trois.srt; subedit-cli disjoint --output fenetres.srt trois.srt; cat fenetres.srt -->
```console
$ printf '1\n00:00:00,000 --> 00:00:03,000\nA\n\n2\n00:00:00,000 --> 00:00:03,000\nB\n\n3\n00:00:00,000 --> 00:00:03,000\nC\n\n' > trois.srt; subedit-cli disjoint --output fenetres.srt trois.srt; cat fenetres.srt
trois.srt: 0 subtitles split, 1 merged; 1 shown in windows for holding too many lines -> fenetres.srt
1
00:00:00,000 --> 00:00:01,500
A
B

2
00:00:01,500 --> 00:00:03,000
B
C
```

Четыре строки дают три окна и так далее: окно сдвигается на одну строку за раз. Ничего не
усекается и не режется повторно.

**Перевод следует тем же разрезам**, поскольку субтитр несёт оба текста. **Всё, что формат хранит
сверх этого** (стиль, позиция), берётся от первого из покрывающих субтитров; потеря учитывается, когда
объединяемые субтитры различаются.

**Субтитр, конец которого раньше начала,** не угадывается: он остаётся как есть и учитывается в счётчике.

## Нужен файл с правильным порядком

Группы — это серии соседних субтитров: при нарушенном порядке соседи — не те, что перекрываются. Файл,
в котором начала идут не по порядку, поэтому **отвергается**, и сообщение говорит об этом:

<!-- example: printf '1\n00:00:03,000 --> 00:00:08,000\nB\n\n2\n00:00:00,000 --> 00:00:05,000\nA\n\n' > desordre.srt; subedit-cli disjoint --output x.srt desordre.srt; echo "code $?" -->
```console
$ printf '1\n00:00:03,000 --> 00:00:08,000\nB\n\n2\n00:00:00,000 --> 00:00:05,000\nA\n\n' > desordre.srt; subedit-cli disjoint --output x.srt desordre.srt; echo "code $?"
desordre.srt: The subtitles are not in the order of their start: sort them first. Use --sort to do that here.
code 2
```

`--sort` сначала выполняет сортировку (такую же, как [`sort`](sort.md)) и сообщает об этом. Ядро никогда не сортирует само.

Второй проход ничего не меняет: когда диапазоны уже не пересекаются, резать больше нечего, и в
сообщении говорится `already disjoint`.

## Вывод

**Стандартный вывод** — пуст: результат — это записанный файл.

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles split, M merged -> <destination>`, затем после `;` то, что не удалось выполнить полностью: `K shown in windows for holding too many lines`, `K very short taken over by a neighbour`, `K subtitles shorter than the limit left whole`, `K merged with styles or positions that differ, the first kept`, `K subtitles ending before the start left alone`; либо `<path>: already disjoint -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` |
| 3 | `<path>: N bytes read, M written`, затем **каждое диагностическое сообщение чтения** |

`N subtitles split` — число исходных субтитров, разрезанных на несколько частей, `M merged` — число частей,
которые показывают сразу несколько субтитров.

### В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) в `counts` каждого файла записываются:

| Число | Что сообщает |
| :----- | :----------- |
| `subtitles` | субтитры записанного файла |
| `split`, `merged` | как в сообщении |
| `windowed` | части, показанные в окнах |
| `absorbed` | интервалы, поглощённые соседом |
| `too_short` | субтитры короче порога, оставленные целыми |
| `ending_before_start` | субтитры, конец которых раньше начала, оставленные как есть |
| `extras_dropped` | объединённые части с различающимися стилем или позицией |
| `moved` | только с `--sort`: места, которые изменились |

## Коды завершения

Коды самой программы: `0`, если обработаны все файлы (файл без перекрытий считается обработанным), `2`, если
не обработан ни один, `3`, если обработаны лишь некоторые, `1` при ошибке использования.

## Ошибки

| Что их вызывает | Сообщение |
| :------------------- | :------ |
| файл с нарушенным порядком без `--sort` | `<path>: The subtitles are not in the order of their start: sort them first. Use --sort to do that here.` |
| `--minimum` не является длительностью или отрицателен | `--minimum: …` |
| `--max-lines` не является целым числом | `--max-lines: "…" is not a number of lines: expected a whole number, 0 for no limit` |

Нечитаемый файл вызывает отказ, как у любой подкоманды; ошибки места назначения общие для
подкоманд, которые записывают: см. [Запуск](invocation.md#место-назначения).

## В других командах

[`convert`](convert.md#устранение-перекрытий-диапазонов), [`append`](append.md#устранение-перекрытий-диапазонов) и
[`split-file`](split-file.md#устранение-перекрытий-диапазонов) принимают `--disjoint`, который перед записью делает то же самое
с настройками по умолчанию.

На плохо сегментированном файле (текст, разрезанный на следующие друг за другом части и выданный не по порядку) одни
сортировка и обрезка дают строки, которые перескакивают от одной части к другой: сначала выполните [`join-repeats`](join-repeats.md) или
[`repair`](repair.md), который выполняет все три действия подряд.
