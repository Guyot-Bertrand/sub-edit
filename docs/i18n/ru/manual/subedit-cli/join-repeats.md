# `join-repeats`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli join-repeats (--output FILE | --output-dir DIR | --in-place)
                         [--dry-run]
                         [--recursive]
                         <file>...
```

Превращает в **один субтитр** субтитры, которые подряд показывают одно и то же: текст, разрезанный на следующие друг за другом
части, как его оставляют некоторые средства сегментации. Это `Join Repeated Subtitles` из окна —
[тот же движок](../subedit-gui/lines.md#объединение-повторяющихся-субтитров).

**Повтор** — это субтитр, у которого **тот же текст, тот же перевод и те же параметры формата** (стиль,
позиция, параметры реплики), что и у другого, **и который начинается не позже, чем заканчивается тот**: они
соприкасаются или перекрываются. Серия повторов превращается в **тот субтитр, который начинается первым**, а его конец
переносится на самый поздний конец серии; остальные исчезают.

- **Порядок субтитров в файле не имеет значения и не меняется**: сохраняется тот субтитр, который начинается первым,
  где бы ни находились остальные. Файл с правильным порядком остаётся с правильным порядком.
- **Ничего не объединяется по ошибке**: другой текст, другой перевод, другие параметры, промежуток между двумя
  частями, субтитр без текста или с концом раньше начала — во всех этих случаях они остаются раздельными.
- **Выполнять до всего остального**: сортировка и [обрезка перекрывающихся частей](disjoint.md) лучше работают с чистой серией.
  [`repair`](repair.md) выполняет все три действия подряд, а [`convert`](convert.md#устранение-перекрытий-диапазонов) принимает их как параметры (`--join-repeats`, `--repair`).

<!-- example: subedit-cli join-repeats --help -->
```console
$ subedit-cli join-repeats --help
Join the subtitles that repeat each other, one after the other, into one
Usage: subedit-cli join-repeats [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to join the repeats of

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выключен — см. [Обработка дерева каталогов](lots.md) |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nAlpha\n\n2\n00:00:02,000 --> 00:00:04,000\nAlpha\n\n3\n00:00:04,000 --> 00:00:06,000\nAlpha\n\n4\n00:00:08,000 --> 00:00:09,000\nBeta\n\n' > morceaux.srt; subedit-cli join-repeats --output joint.srt morceaux.srt; cat joint.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nAlpha\n\n2\n00:00:02,000 --> 00:00:04,000\nAlpha\n\n3\n00:00:04,000 --> 00:00:06,000\nAlpha\n\n4\n00:00:08,000 --> 00:00:09,000\nBeta\n\n' > morceaux.srt; subedit-cli join-repeats --output joint.srt morceaux.srt; cat joint.srt
morceaux.srt: 2 repeated subtitles joined -> joint.srt
1
00:00:01,000 --> 00:00:06,000
Alpha

2
00:00:08,000 --> 00:00:09,000
Beta
```

Три части `Alpha`, следующие друг за другом с 1 с по 6 с, теперь образуют только одну. `Beta`, отделённая промежутком,
осталась на месте. Второй проход ничего не меняет и сообщает об этом: `no repeated subtitles`.

## Вывод

**Стандартный вывод** — пуст: результат — это записанный файл.

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N repeated subtitles joined -> <destination>`, или `<path>: no repeated subtitles -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` |
| 3 | `<path>: N bytes read, M written`, затем **каждое диагностическое сообщение чтения** |

### В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) в `counts` каждого файла записываются: `subtitles` (субтитры записанного
файла), `joined` (субтитры, удалённые, потому что их покрывает другой) и `chains` (объединённые серии).

## Коды завершения

Коды самой программы: `0`, если обработаны все файлы (файл без повторов считается обработанным), `2`, если не обработан ни один, `3`, если
обработаны лишь некоторые, `1` при ошибке использования.

## Ошибки

Собственных ошибок у `join-repeats` нет: нечитаемый файл вызывает отказ, как у любой подкоманды, а ошибки
места назначения общие для подкоманд, которые записывают: см. [Запуск](invocation.md#место-назначения).
