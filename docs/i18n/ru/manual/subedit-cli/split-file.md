# `split-file`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli split-file --at N --head FILE --tail FILE
                       [--dry-run] [--sort] [--disjoint]
                       <file>
```

Разрезает файл **на две части**: начало и конец. Это `Split Project…` из окна — [тот же движок](../subedit-gui/operations.md#split-project),
те же счётчики, тот же отказ — и **точная обратная операция к [`append`](append.md)**: если добавить конец к
началу, получится исходный файл.

- **Параметр `--at N` — это номер первого субтитра конца**, нумерация та же, что в таблице окна:
  с 1. `--at 3` помещает субтитры 1 и 2 в начало, а третий и остальные — в
  конец. Допустимые значения — **от второго до последнего**: для разреза нужен субтитр с каждой стороны.
- **Конец возвращается к началу отсчёта**: он сдвигается на минус конец последнего субтитра, оставшегося в начале,
  а его позиции сохраняют порядок и промежутки. Именно поэтому `split-file` обратна `append`.
- **Обе части сохраняют формат, кодировку, метку порядка байтов и символы конца строки читаемого файла** и
  при записи нумеруются заново с 1, как любой файл, записываемый обратно.
- **Два выхода, значит, собственное место назначения у каждого**: `--head` и `--tail`, **оба обязательны**. Параметров `--output`,
  `--output-dir`, `--in-place` и `--recursive` у `split-file` нет, и они отклоняются как любой неизвестный
  параметр, код `1`: здесь нет ни каталога, в котором делятся два именованных файла, ни входного файла, который можно перезаписать.

<!-- example: subedit-cli split-file --help -->
```console
$ subedit-cli split-file --help
Cut a subtitle file in two, a head and a tail
Usage: subedit-cli split-file [OPTIONS] file

Positionals:
  file TEXT REQUIRED          Subtitle file to cut

Options:
  -h,--help                   Print this help message and exit
  --at N                      Number of the first subtitle of the tail, as the table numbers them
  --head FILE                 File to write the subtitles before the cut to
  --tail FILE                 File to write the subtitles from the cut on to
  --dry-run                   Work out and say what would be written, and write nothing
  --sort                      Put the subtitles in order of their start before cutting; --at counts in that order
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before cutting
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>` | да | **один** путь | — |
| `--at` | да | целое число от 2 до числа субтитров файла | — |
| `--head`, `--tail` | **да, оба**, кроме случая `--dry-run` | пути файлов; их каталог создаётся, если его нет | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |
| `--sort` | нет | флаг: ставит субтитры в порядок их начал **перед разрезанием**; `--at` считает в этом порядке | выключен |
| `--disjoint` | нет | флаг: обрезает перекрывающиеся субтитры **перед разрезанием**; `--at` считает в том, что осталось, см. [Устранение перекрытий диапазонов](#устранение-перекрытий-диапазонов) | выключен |

**С параметром `--dry-run` место назначения не требуется**: ни одно не должно задаваться, но нельзя задать только одно из двух —
`--head` и `--tail` идут вместе. Заданные проверяются так же, как без `--dry-run`.

**Оба места назначения не могут быть ни входным файлом, ни одним и тем же файлом**: запись поверх читаемого
или запись конца поверх начала отклоняется до начала чтения, код `1`.

<!-- example: printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n3\n00:00:06,000 --> 00:00:07,000\ntrois\n\n4\n00:00:08,000 --> 00:00:09,000\nquatre\n\n' > film.srt; subedit-cli split-file --at 3 --head tete.srt --tail queue.srt film.srt; cat queue.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:02,000\nun\n\n2\n00:00:03,000 --> 00:00:04,000\ndeux\n\n3\n00:00:06,000 --> 00:00:07,000\ntrois\n\n4\n00:00:08,000 --> 00:00:09,000\nquatre\n\n' > film.srt; subedit-cli split-file --at 3 --head tete.srt --tail queue.srt film.srt; cat queue.srt
```

Второй субтитр, оставшийся в начале, заканчивается на 4 с: конец сдвигается назад на 4 с, а третий субтитр,
начинавшийся на 6 с, начинается на 2 с.

## Разрезание в порядке времени

`--at` нумерует субтитры **так, как их даёт файл**. Поэтому в файле с нарушенным порядком начало — это не та половина, что раньше
по времени. `--sort` ставит субтитры в порядок их начал **до оценки разреза** (устойчиво, как это делает [`sort`](sort.md)), и
`--at` затем считает в этом порядке.

По умолчанию — никогда. С этим параметром файл сообщает на первом уровне пояснений, сколько субтитров переместилось (`<path>: N subtitles moved`
или `<path>: already in order`), а запись `--format json` содержит счётчик `moved`, **отсутствующий без параметра**.

## Устранение перекрытий диапазонов

По умолчанию — никогда. Параметр делает то же, что [`disjoint`](disjoint.md), **с его настройками по умолчанию**, до оценки разреза, после сортировки: `--at` считает в том, что получилось. Нужен файл с правильным порядком, иначе параметр отклоняется, а `--sort`, который выполняется первым, предварительно наводит порядок. Файл сообщает об этом на первом уровне пояснений (`<path>: N subtitles split, M merged`), а запись `--format json` содержит счётчики `split` и `merged`, **отсутствующие без параметра**.

## Когда разрез отклоняется

**Две половины, перекрывающиеся в месте разреза, не разрезаются.** Если субтитр конца начинался до
конца последнего оставленного субтитра, сдвиг унёс бы его до начала видео — в отрицательную позицию,
которую не записывает ни один формат. `split-file` отклоняет разрез, **называя субтитр**, словами окна:

```text
o.srt: Cannot split at subtitle 3: subtitle 3 would fall before the start of the video. Cut somewhere else.
```

Код — `2`, и **ничего не записывается**. Разрежьте в другом месте. Попасть точно на начало допускается: нуль — это
позиция.

**`--at` за пределами файла отклоняется так же**, после чтения файла: `--at 1` (первый субтитр не может
начинать конец, ничего не осталось бы) и `--at` за последним субтитром, который оставил бы пустой
конец. Файл из одного субтитра разрезать нельзя.

## Вывод

**Стандартный вывод** — пусто: результат — это два записанных файла.

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: split at subtitle N: H subtitles in the head, T subtitles in the tail -> <head>, <tail>`; при `--dry-run` вместо `-> …` выводится `(dry run, nothing written)` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые как были |
| 3 | `<path>: N bytes read, H and T written`, затем **все диагностические сообщения чтения**; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) — **один объект**, где `file` — разрезаемый файл.
**`destination` — это начало**, то есть файл, которым становится входной, а **`tail` — конец**: путь или `null` при
`--dry-run`, как и у `destination`. Счётчики `counts`: `subtitles` (субтитры прочитанного файла), `head` и `tail` (субтитры каждой
половины).

## Коды завершения

| Код | Когда |
| :--- | :---- |
| `0` | оба файла записаны (или вычислены, при `--dry-run`) |
| `1` | ошибка использования: нет `--head` и `--tail`, параметр, которого у `split-file` нет, место назначения, совпадающее с входным файлом или с другим местом назначения, `--at` не является положительным целым числом |
| `2` | файл не удалось прочитать, **разрез отклонён** (за пределами файла или перекрытие), или место назначения не удалось записать. Кода `3` нет: обрабатывается единственный файл |

**Начало записывается первым**: если диск отказывает в записи конца, начало остаётся, а код равен `2`.

## Ошибки

| Что их вызывает | Сообщение |
| :------------------- | :------ |
| нет ни `--head`, ни `--tail` | `no destination given: split-file writes two files, use --head and --tail` |
| только один из двух, при `--dry-run` | `--head and --tail go together: give both, or neither with --dry-run` |
| оба места назначения — один и тот же файл | `<path>: named as both the head and the tail` |
| место назначения — входной файл | `<path>: would be written over the input <input>` |
| `--at` за пределами файла | `<file>: --at 9: the file holds 3 subtitles, and the tail can start from 2 to 3` |
| файл из одного субтитра | `<file>: a file of 1 subtitle cannot be split: a cut needs a subtitle on each side` |
| перекрытие | `<file>: Cannot split at subtitle N: subtitle M would fall before the start of the video. Cut somewhere else.` |
| файл отсутствует, нечитаем или имеет неизвестный формат | `<path>: does not exist`… — то же, что везде |
