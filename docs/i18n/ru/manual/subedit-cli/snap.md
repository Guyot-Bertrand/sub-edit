# `snap`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli snap --rate <rate>
                 (--output FILE | --output-dir DIR | --in-place)
                 [--dry-run]
                 [--recursive]
                 <file>...
```

Ставит **каждую метку времени**, начало и конец, на ближайший кадр заданной
частоты кадров. Тайминг не пересчитывается: каждая позиция сдвигается не более чем на
полкадра.

## `snap` — это не `framerate`, и путаница между ними незаметна

У двух команд одинаковая форма — файлы, место назначения, частота кадров, — а делают они противоположное.

| | [`framerate`](framerate.md) | `snap` |
| :--- | :-------------------------- | :----- |
| что вычисляет | `t' = t x input rate / output rate` | ближайший кадр на сетке `--rate` |
| на сколько сдвигает | пропорционально времени — **на несколько секунд** в полнометражном фильме | не более чем на полкадра, **везде** |
| для какого файла | файла, у которого **неверный тайминг** | файла, у которого тайминг **верный**, а сетка неверная |

**Сфера применения `snap`**, если говорить прямо: фильм с частотой 25 кадр/с,
файл субтитров, записанный на сетке 24, строки уже
более или менее на своих местах с точностью до нескольких миллисекунд. Пересчитывать тайминг
не нужно — нужно лишь вернуть метки времени на правильные кадры.

**Сфера применения `framerate`** — другая: файл, рассчитанный по мастеру с частотой
25, который хотят воспроизводить на копии с частотой 23,976 и у которого тайминг к концу фильма расходится на
несколько секунд.

Принять одно за другое **не вызывает ошибки**: обе команды
принимают файл и записывают результат. Отличить их позволяет строка
пояснений: `snap` всегда сообщает, насколько он сдвинул позиции.

<!-- example: subedit-cli snap --help -->
```console
$ subedit-cli snap --help
Move every position onto the nearest frame of a frame rate (see framerate)
Usage: subedit-cli snap [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to align

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --rate TEXT REQUIRED        Frame rate to align on: 25, 23.976
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выключен; см. [Обработка дерева каталогов](lots.md) |
| `--rate` | **да** | частота кадров в кадрах в секунду, записываемая так же, как для [`framerate`](framerate.md#запись-частоты-кадров) | — |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выключен |

`--rate` принимает **любую допустимую частоту кадров**, а не только восемь
стандартных: выбор остаётся за пользователем, как и у `framerate`. Нулевая или отрицательная
частота кадров отклоняется.

Формат читаемого файла **сохраняется**: смена формата — это дело
[`convert`](convert.md).

## Вывод

**Стандартный вывод** — пусто: результат — это записанный файл. С параметром `--dry-run` тоже пусто: файла нет, и строка пояснений сообщает об этом; см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

| Уровень | Что добавляется в поток ошибок |
| :----- | :------------------------------------- |
| 1 | `<path>: N subtitles aligned on 25 fps, M positions moved, by at most 20 ms -> <destination>` |
| 2 | `<path>: SubRip, UTF-8, no BOM, LF line endings kept` — формат, кодировка, метка и символы конца строки прочитанного файла, возвращённые как были |
| 3 | `<path>: N bytes read, M written`, затем **все диагностические сообщения чтения**; см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

**Суть строки — в двух числах.** Полкадра при 25 кадр/с — это двадцать миллисекунд,
и ничего большего там записать нельзя. Тот, кто
хотел `framerate`, а набрал `snap`, читает «by at most 20 ms» там, где ожидал
секунды, и сразу всё понимает.

## Пример

Строка в `00:00:01,010`, выровненная по 25 кадр/с, то есть по
числу, кратному сорока миллисекундам:

<!-- example: printf '1\n00:00:01,010 --> 00:00:03,020\nUn.\n\n' > a.srt; subedit-cli snap --rate 25 --output b.srt a.srt; cat b.srt -->
```console
$ printf '1\n00:00:01,010 --> 00:00:03,020\nUn.\n\n' > a.srt; subedit-cli snap --rate 25 --output b.srt a.srt; cat b.srt
a.srt: 1 subtitle aligned on 25 fps, 2 positions moved, by at most 20 ms -> b.srt
1
00:00:01,000 --> 00:00:03,040
Un.
```

## Два свойства

**Повторное выравнивание во второй раз ничего не меняет.** Позиция, уже стоящая на
кадре, остаётся там: это та же операция, применённая к тому же результату.

**Порядок субтитров сохраняется.** Округление до ближайшего кадра
монотонно, поэтому два начала, разделённые не менее чем одним кадром, такими и остаются. Если
они ближе, они могут слиться, а это аномалия, которую
[`inspect`](inspect.md#о-чём-сообщает-anomalies) умеет назвать, и не
инверсия.

### В формате JSON

С параметром [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит `counts.subtitles`, `counts.moved` (сдвинутые позиции) и `counts.furthest_ms` (наибольший сдвиг в миллисекундах). Полная таблица находится в разделе [Запуск](invocation.md#что-каждая-подкоманда-помещает-в-counts).

## Коды завершения

Те же, что у всего инструмента: `0`, если записан каждый файл, `2`, если не записан ни один, `3`, если
записаны только некоторые, `1` при ошибке использования.

## Ошибки

Ошибки частоты кадров — слово в слово те же, что у [`framerate`](framerate.md#ошибки):
обе команды читают одно и то же значение одним и тем же путём:

| Что её вызывает | Сообщение |
| :------------------ | :------ |
| нулевая или отрицательная частота кадров | `"…" is not a frame rate: a frame rate must be strictly positive; nothing runs at that speed` |
| десятичная запятая | `"…" is not a frame rate: use a decimal point and not a comma, in every language` |
| текст, не являющийся числом | `"…" is not a frame rate: expected frames per second, like 25 or 23.976` |
| частота кадров несоразмерно велика | `"…" is not a frame rate: no video runs at that many frames per second` |

**Без одного из трёх параметров места назначения ничего не записывается**, а их ошибки
общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).
