# `convert`

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-cli convert --to <format>
                    [--line-endings unix|windows|mac] [--to-encoding NAME]
                    [--bom | --no-bom] [--sort] [--disjoint]
                    [--join-repeats] [--repair]
                    (--output FILE | --output-dir DIR | --in-place)
                    [--dry-run]
                    [--recursive]
                    <file>...
```

Записывает каждый файл в запрошенном формате и виде. **Входной файл никогда
не изменяется**, если только `--in-place` явно этого не требует.

<!-- example: subedit-cli convert --help -->
```console
$ subedit-cli convert --help
Write a subtitle file out in another format or shape
Usage: subedit-cli convert [OPTIONS] files...

Positionals:
  files TEXT ... REQUIRED     Subtitle files to convert

Options:
  -h,--help                   Print this help message and exit
  -r,--recursive              Take directories as inputs, and every subtitle file in them
  --to TEXT:{srt,vtt,subviewer2,ssa,ass,microdvd,mpl2,tmplayer,lrc} REQUIRED
                              Format to write
  --line-endings TEXT:{unix,windows,mac}
                              Line endings to write; the source's by default
  --to-encoding NAME          Encoding to write; the source's by default
  --frame-rate RATE           Frame rate of a file counted in frames: 25, 23.976
  --bom                       Write a byte order mark
  --no-bom                    Write no byte order mark
  --sort                      Put the subtitles in order of their start before writing
  --disjoint                  Cut overlapping subtitles so that no range overlaps another, before writing
  --join-repeats              Join the subtitles that repeat each other into one, before writing
  --repair                    Join the repeats, sort, then make the ranges disjoint, before writing
  --output TEXT               File to write, for a single input
  --output-dir TEXT           Directory to write into
  --in-place                  Write back over the inputs
  --dry-run                   Work out and say what would be written, and write nothing
```

## Аргументы и параметры

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `<file>...` | да | один или несколько путей | — |
| `--recursive`, `-r` | нет | флаг | выкл. — см. [Обработка дерева каталогов](lots.md) |
| `--to` | **да** | имя из таблицы ниже и ничто другое | — |
| `--line-endings` | нет | `unix`, `windows` или `mac` | как у прочитанного файла |
| `--to-encoding` | нет | любая кодировка, которую ICU умеет записывать, кроме тех, что записывают собственную метку | как у прочитанного файла |
| `--bom` / `--no-bom` | нет | флаги, исключающие друг друга | то, что нёс прочитанный файл |
| `--sort` | нет | флаг: упорядочивает субтитры по началу **перед записью**, см. [Сортировка при записи](#сортировка-при-записи) | выкл. |
| `--join-repeats` | нет | флаг: делает один субтитр из нескольких подряд идущих частей одного текста, **прежде всего остального**, см. [Устранение перекрытий диапазонов](#устранение-перекрытий-диапазонов) | выкл. |
| `--repair` | нет | флаг: то же, что `--join-repeats --sort --disjoint`, в этом порядке | выкл. |
| `--disjoint` | нет | флаг: обрезает перекрывающиеся субтитры **перед записью**, см. [Устранение перекрытий диапазонов](#устранение-перекрытий-диапазонов) | выкл. |
| `--output` / `--output-dir` / `--in-place` | **один из трёх**, кроме случая с `--dry-run` | см. [Запуск](invocation.md#место-назначения) | — |
| `--dry-run` | нет | флаг: вычисляет и сообщает, ничего не записывает — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью) | выкл. |

`mac` обозначает один возврат каретки (`\r`), символ конца строки классической Mac OS.

## Форматы, которые принимает `--to`

| Имя | Формат | Записываемое расширение |
| :-- | :----- | :--------------- |
| `srt` | SubRip | `.srt` |
| `vtt` | WebVTT | `.vtt` |
| `subviewer2` | SubViewer 2.0 | `.sub` |
| `ssa` | Sub Station Alpha | `.ssa` |
| `ass` | Advanced SSA | `.ass` |
| `mpl2` | MPL2 | `.txt` |
| `microdvd` | MicroDVD | `.sub` |
| `tmplayer` | TMPlayer | `.txt` |
| `lrc` | LRC | `.lrc` |

**Имя, а не расширение.** Два расширения обозначают по два формата:
`.sub` — это ещё и MicroDVD, `.txt` — и MPL2, и
TMPlayer, — поэтому параметр, принимающий расширения, не знал бы, какой именно
формат запрошен. Приведённые выше имена однозначны и совпадают с
расширением везде, где однозначно и расширение.

**Список закрыт.** Это список Gaupol, и все девять форматов в нём есть.

## Два формата, у которых нет конца

**TMPlayer и LRC записывают только одну позицию на строку** — её начало. Это
заметно с обеих сторон.

**При чтении** концы выводятся: конец строки — это начало
следующей, а последней дают пять секунд. Так делает Gaupol.
Мы тоже об этом сообщаем диагностическим сообщением, которое `--verbose` показывает во всех трёх
подкомандах:

```
file.lrc: carries no end times; each one was taken from the next start, settled by the reader
```

**При записи** концы не записываются, поскольку им некуда деться.
Поэтому преобразование в один из этих двух форматов их теряет, и двойное преобразование туда и обратно
их не возвращает — оно выводит их заново.

**LRC теряет ещё кое-что**: он не умеет хранить перевод строки.
Реплика диалога в две строки записывается в одну, две строки соединяются
пробелом. Эту потерю тоже нельзя исправить.

Ни тот ни другой формат не имеет средств для курсива.

## `--frame-rate` и единственный формат, который считает в кадрах

**MicroDVD считает не в секундах**: его позиции *и есть* номера
кадров, и ни один файл MicroDVD не объявляет частоту, с которой они были
посчитаны. `--frame-rate` её задаёт и служит с обеих сторон: это
частота, с которой читается `.sub` в кадрах, и та, с которой
преобразование в MicroDVD считает кадры.

| Параметр | Обязательный | Значения | По умолчанию |
| :----- | :----- | :------ | :----- |
| `--frame-rate` | нет | частота в кадрах в секунду: `25`, `23.976`, `29.97` | см. ниже |

**При чтении без `--frame-rate` файл читается с частотой 23,976** — значением
Gaupol, — и уровень `-vvv` сообщает об этом:
`counts in frames and states no rate; it was read at`. Это единственное место в программе, где каждая показанная
позиция опирается на предположение, которое файл не может подтвердить.

**При записи без `--frame-rate` — три случая и три ответа:**

| Исходный файл | Что происходит |
| :------------------- | :-------------- |
| уже в формате MicroDVD | частота, с которой он был прочитан, записывает его обратно, и кадры возвращаются прежними |
| основан на времени, а его позиции ложатся на сетку | берётся эта сетка, а `-vv` сообщает, какая именно |
| основан на времени, без сетки | **отказ**, код 2: `writing frames needs a frame rate, and the positions fall on no grid to take one from — give --frame-rate` |

Отказ намеренный. Единственный оставшийся жест — выдумать число, и
каждая строка файла сместилась бы на величину этой ошибки.

## Что теряет преобразование

**Преобразование в другой формат никогда не обходится без потерь**, а что не
сохранится, зависит от пары форматов:

| Что не проходит | Почему |
| :--------------------- | :------- |
| заголовок | он имеет смысл только в своём формате: `[INFORMATION]` — это не заголовок WebVTT |
| данные, специфичные для формата | координаты SubRip, идентификатор и настройки реплики WebVTT не имеют аналога в других форматах |
| точность | SubViewer 2, оба Sub Station Alpha и LRC записывают до сотых долей, MPL2 — до десятых, TMPlayer — до секунды, MicroDVD — до кадра; `01:00:00,017` возвращается как `01:00:00,020` |
| конец строки | у TMPlayer и LRC для него нет поля; следующее чтение выводит его заново |
| переводы строк | только LRC: его строки укладываются в одну строку, и две склеиваются обратно пробелом |
| теги, которые целевой формат записать не может | в WebVTT нет `<font color>`, в TMPlayer и LRC нет ничего |
| расположение | `{\pos(x,y)}`, `{\an8}`, `<v Marie>`, `<ruby>`: они переживают двойное преобразование в своём формате и исчезают при преобразовании в другой |

**Запись файла обратно в его собственном формате ничего не теряет** — это гарантия,
на которой держится всё остальное, и `--to srt` для `.srt` возвращает те же байты. Ничего
даже не декодируется: текст остаётся той самой исходной строкой, которая была прочитана.

## Теги преобразуются, а не копируются

**Каждый формат записывает курсив по-своему**, и преобразование без перевода
оставило бы `{\i1}` в `.srt`: текст, который видит пользователь, в
файле, который никогда не сумеет его интерпретировать. Проходят **шесть
вещей** — полужирный, курсив, подчёркивание, цвет, шрифт и размер:

| Формат | Полужирный | Курсив | Подчёркивание | Цвет | Шрифт | Размер |
| :----- | :--: | :------: | :------: | :-----: | :----: | :----: |
| SubRip | `<b>` | `<i>` | `<u>` | `<font color="#RRGGBB">` | — | — |
| WebVTT | `<b>` | `<i>` | `<u>` | — | — | — |
| SubViewer 2 | `<b>` | `<i>` | `<u>` | `<font color="#RRGGBB">` | — | — |
| Sub Station Alpha | `{\b1}` | `{\i1}` | — | `{\c&HBBGGRR&}` | `{\fnNAME}` | `{\fsN}` |
| Advanced SSA | `{\b1}` | `{\i1}` | `{\u1}` | `{\c&HBBGGRR&}` | `{\fnNAME}` | `{\fsN}` |
| MicroDVD | `{Y:b}` | `{Y:i}` | `{Y:u}` | `{C:$BBGGRR}` | `{F:NAME}` | `{S:N}` |
| MPL2 | `\` | `/` | `_` | `{C:$BBGGRR}` | `{F:NAME}` | `{S:N}` |
| TMPlayer | — | — | — | — | — | — |
| LRC | — | — | — | — | — | — |

**Прочерк — это объявленная потеря.** Преобразование цветного `.srt` в WebVTT убирает
цвет и сообщает об этом; получившийся файл — это WebVTT, а не SubRip под чужой личиной.

**MicroDVD и MPL2 не умеют оформлять часть строки.** Их теги
не имеют конца: `{y:i}` делает курсивом всё до конца строки, а
`{Y:i}` — до конца субтитра. Поэтому строка, лишь половина которой была
полужирной, записывается без полужирного вообще, а не с полужирным, который вылезает за пределы.

## О чём преобразование сообщает как об утраченном

**Оно сообщает, когда что-то теряет, и молчит, когда ничего не теряет.** Отчёт,
который появляется при каждом вызове, — это отчёт, который никто не читает.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,500\n<i>sur deux</i>\nlignes\n\n' > a.srt; subedit-cli convert --to lrc --output b.lrc a.srt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,500\n<i>sur deux</i>\nlignes\n\n' > a.srt; subedit-cli convert --to lrc --output b.lrc a.srt
a.srt: 1 subtitle written as LRC -> b.lrc
a.srt: ends are not carried by LRC, line breaks were joined in 1 subtitle, 1 tag dropped
```

Строка выводится на уровне подробности по умолчанию и на каждом уровне выше.
Пункты идут в таком порядке:

| Пункт | Что он сообщает |
| :---- | :----------- |
| `ends are not carried by <format>` | целевой формат не записывает конец |
| `line breaks were joined in N subtitles` | только LRC: N субтитров были в несколько строк |
| `N tags dropped` | N тегов не удалось записать, включая расположение |
| `the header was dropped` | заголовок не переходит границу между форматами |
| `the <format> fields of N subtitles were dropped` | N субтитров несли данные, специфичные для их формата |
| `positions moved by up to N ms` | наибольшее расстояние, на которое сместилась позиция |

## Смена кодировки

**`--to-encoding` выбирает кодировку записи, а `--encoding` задаёт ту, в которой
файл читается.** Вместе они перекодируют файл:

```console
$ subedit-cli convert --to srt --encoding cp1252 --to-encoding utf-8 \
      --output-dir sortie film.srt
```

Без `--to-encoding` файл записывается в **той кодировке, в которой был прочитан**,
как и с символами конца строки и меткой: файл, преобразованный без
указаний о кодировке, возвращает те же символы в тех же байтах.

**Символ, который целевая кодировка записать не может, останавливает обработку файла**, и
ничего не записывается. Символу `ł` нет места в Latin-1; замена его на `?`
привела бы к потере текста между чтением и записью, и никто бы этого не заметил.

**Метка порядка байтов существует только для кодировок Unicode.**
`--bom` с `--to-encoding`, у которой метки нет, отклоняется, а не игнорируется
— см. таблицу ошибок ниже.

**И кодировка должна называть порядок байтов.** `UTF-16` и `UTF-32` — это
имена, известные ICU, чей преобразователь записывает **собственную метку**, о чём бы его
ни просили: `--no-bom` тогда был бы принят и не выполнен. Поэтому оба
отклоняются, а сообщение называет вывод:

```console
$ subedit-cli convert --to srt --to-encoding UTF-16 --output copie.srt film.srt
"UTF-16" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do
```

`UTF-16LE`, `UTF-16BE`, `UTF-32LE` и `UTF-32BE` записывают в точности те же
байты, включая метку, — но под управлением `--bom` и `--no-bom`. Поэтому
отказ не стоит ничего, кроме более точного имени, и он действует как при чтении,
так и при записи: `--encoding UTF-16` получает тот же ответ.

## Место назначения

Три параметра и их правила общие для подкоманд, которые
записывают: см. [Запуск](invocation.md#место-назначения). Без
одного из них ничего не записывается.

Специфично для `convert`: **`--output-dir` меняет расширение в зависимости от
формата.** `convert --to vtt` для `a.srt` записывает `a.vtt`, а не `a.srt` с
WebVTT внутри: файл, имя которого лжёт, сбивает с толку все остальные программы.

## Преобразование на месте отклоняется

`--in-place` с `--to`, меняющим формат, даёт код `1` и ничего
не записывает: на месте нет второго имени, которое могло бы нести новый формат, и
файл остался бы с расширением, которого его содержимое больше не оправдывает.

`--in-place` по-прежнему можно использовать, чтобы изменить **вид без формата** —
например, записать `.srt` обратно как `.srt` с другими символами конца строки.

Отказ определяется **только по расширению**, до любого чтения: ошибка использования
не должна оставлять пакет записанным наполовину.

## Символы конца строки и метка порядка байтов

По умолчанию **записанный файл повторяет то, что нёс прочитанный**. Модель
сохраняет и то и другое при чтении; навязывать их по умолчанию означало бы терять при каждом
преобразовании сведения, сохранённые намеренно.

<!-- example: printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli convert --to vtt --output b.vtt a.srt; cat b.vtt -->
```console
$ printf '1\n00:00:01,000 --> 00:00:03,000\nBonjour.\n\n' > a.srt; subedit-cli convert --to vtt --output b.vtt a.srt; cat b.vtt
a.srt: 1 subtitle written as WebVTT -> b.vtt
WEBVTT

00:01.000 --> 00:03.000
Bonjour.
```

## Сортировка при записи

`--sort` записывает файл **в порядке начал**, каким бы ни был целевой формат. Сортировка выполняется **над копией**: прочитанный файл
не затрагивается, а записывается то, что получилось бы у [`sort`](sort.md) — устойчиво, два субтитра, начинающиеся одновременно, сохраняют свой порядок.

**Никогда по умолчанию**: порядок файла — это порядок его автора, пока не запрошено иное. С параметром каждый файл сообщает об этом на
первом уровне пояснений: `<path>: N subtitles moved` или `<path>: already in order`, а запись `--format json` содержит счётчик
`moved` — **отсутствующий без параметра**, чтобы не менять форму того, что читают существующие скрипты.

## Устранение перекрытий диапазонов

`--disjoint` обрезает перекрывающиеся субтитры, чтобы ни один диапазон больше не перекрывал другой, **над той же копией, что и сортировка**: прочитанный файл не затрагивается.

Никогда по умолчанию. Параметр делает то, что делает [`disjoint`](disjoint.md), **с его настройками по умолчанию**, перед записью, после сортировки. Ему нужен упорядоченный файл: иначе он отклоняется, а `--sort`, который выполняется первым, предварительно наводит порядок. Файл сообщает об этом на первом уровне пояснений (`<path>: N subtitles split, M merged`), а запись `--format json` содержит счётчики `split` и `merged`, **отсутствующие без параметра**.

**`--join-repeats` выполняется до сортировки и обрезки**: текст, разрезанный на идущие подряд части, сначала собирается заново (см.
[`join-repeats`](join-repeats.md)), затем субтитры сортируются, затем диапазоны делаются непересекающимися. **`--repair` — это все три сразу**,
как [`repair`](repair.md), с настройками обрезки по умолчанию. С `--join-repeats` каждый файл сообщает
`<path>: N repeated subtitles joined` на первом уровне пояснений, а запись `--format json` содержит `counts.joined` — **отсутствующий без параметра**.

## Вывод

**Стандартный вывод** — пусто: результат — записанный файл. С `--dry-run` тоже пусто: файла нет, и об этом говорит строка пояснений — см. [Просмотр перед записью](invocation.md#просмотр-перед-записью).

В потоке ошибок, в зависимости от уровня:

| Уровень | Что добавляется |
| :----- | :-------------- |
| 1 | `<path>: N subtitles written as WebVTT -> <destination>` |
| 2 | `<path>: SubRip -> WebVTT, UTF-8, no BOM, LF line endings` — названная кодировка — это та, в которой записано |
| 3 | `<path>: N bytes read, M written`, затем **все диагностические сообщения чтения** — см. [Запуск](invocation.md#чтение-диагностических-сообщений) |

### В формате JSON

С [`--format json`](invocation.md#вывод-пригодный-для-чтения-скриптом) объект каждого файла содержит `counts.subtitles`, затем то, что потеряло преобразование: `lost_ends` и `lost_header` (`0` или `1`), `joined_lines`, `lost_tags`, `lost_fields` и `furthest_ms` — пункты [фразы о потерях](#о-чём-преобразование-сообщает-как-об-утраченном). Полная таблица приведена в разделе [Запуск](invocation.md#что-каждая-подкоманда-помещает-в-counts).

## Коды завершения

Те же, что у программы: `0`, если записан каждый файл, `2`, если не записан ни один, `3`, если
записаны только некоторые, `1` при ошибке использования.

## Ошибки

| Что их вызывает | Сообщение |
| :------------------ | :------ |
| `--bom` с `--no-bom` | `--bom and --no-bom ask for opposite things; give one or the other` |
| `--in-place`, меняющий формат | `--in-place cannot change the format: the file would keep a name its content no longer matches` |
| `--bom` для кодировки, у которой метки нет | `<path>: <encoding> has no byte order mark to write` |
| `--to-encoding` называет неизвестную кодировку | `no encoding is named "<name>"` |
| `--to-encoding` называет кодировку, которая записывает собственную метку | `"<name>" writes a byte order mark of its own; name the byte order, as UTF-16LE and UTF-16BE do` |
| символ, отсутствующий в кодировке записи | `<path>: holds a character the chosen encoding cannot write` |

**Отказ в `--bom` для кодировки, у которой метки нет, — это не
педантизм.** Метка порядка байтов существует для кодировок Unicode и
ни для каких других: просить её для файла в Windows-1252 — значит просить о
том, чего не существует. Файл был бы записан без неё, и никто бы не
узнал, что просьба не выполнена.

Ошибки места назначения общие для подкоманд, которые записывают:
см. [Запуск](invocation.md#место-назначения).

Ошибки чтения — те же, что у [`inspect`](inspect.md): они относятся
ко входному файлу и имеют те же сообщения.
