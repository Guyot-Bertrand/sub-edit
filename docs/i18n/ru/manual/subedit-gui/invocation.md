# Запуск

<!-- machine-translated -->
> Эта страница переведена машинным способом и ещё не проверена носителем языка.

```
subedit-gui [--version] [<file>]
```

| Аргумент | Обязательный | Значение | По умолчанию |
| :------- | :------- | :---- | :------ |
| `<file>` | нет | путь к файлу субтитров, который нужно открыть | нет — окно открывается пустым |
| `--version` | нет | — | — |

**Один файл.** Последующие аргументы игнорируются: окно содержит
только один проект одновременно.

## `--version`

Выводит в стандартный вывод блок, который выводит `--version` командной строки, и
сразу завершается, не открывая окно. Код завершения `0`.

**`subedit <version>` отдельно в первой строке**, затем по одной строке на каждую библиотеку, с которой
работает окно, с версией, найденной во время выполнения, и в скобках — той,
с которой оно было собрано; затем установленные языки интерфейса по их кодам. На
машине с Qt 6.4.2:

```console
$ subedit-gui --version
subedit <version>
  ICU      74.2 (built with 74.2)
  Enchant  2.3.3 (built with 2.3.3)
  Qt       6.4.2 (built with 6.4.2)
  libmpv   2.2 (built with 2.2)
  Languages: en, fr
```

Номера здесь не скопированы: это номера конкретной машины, а в этом руководстве нет
создаваемого автоматически блока, который поддерживал бы в актуальном состоянии вывод самой программы. Библиотеки —
те же, что у командной строки, ICU и Enchant, и две, с которыми связано только окно, — Qt и
libmpv, проигрыватель, версия которого сообщается версией его клиентского API, той, которую
объявляет `mpv.pc`. Остальное описано в
[руководстве по командной строке](../subedit-cli/invocation.md#--version). Слова
`built with` и `Languages` следуют языку окна; больше ничто.

`Справка ▸ О программе subedit` показывает те же библиотеки, из того же списка, в таблице —
название, загруженная версия, версия, с которой выполнена сборка, по строке на каждую, — а под ней
языки; её заголовки следуют языку окна.

## Открытие файла

```console
$ subedit-gui film.srt
```

Читаются **девять форматов**, которые перечисляет фильтр открытия, — см.
[Открытие и сохранение](files.md#открытие). Формат определяется по содержимому, а
не по расширению, **как и кодировка**: по BOM,
если он есть в файле, иначе — по кодировке, на которую указывают его байты.

## Когда открытие не удаётся

Файл отсутствует, не читается, его байты не декодируются ни в одной
кодировке или его содержимое не распознаёт ни один формат: **окно всё равно
открывается, пустым**, а сбой записывается в поток ошибок.

**Сообщение называет причину** теми же словами, что и командная строка:

| Сообщение | Что произошло |
| :------ | :------------ |
| `does not exist` | путь не указывает ни на какой файл |
| `cannot be opened: permission denied` | система отказывает в открытии |
| `cannot be read` | система отказала по другой причине |
| `cannot be decoded in the chosen encoding` | байты не читаются в выбранной кодировке |
| `is in no format this tool knows` | содержимое не распознаёт ни один формат |
| `holds nothing recognisable as a subtitle` | формат распознан, но в файле нет ничего, что было бы субтитром |

```console
$ subedit-gui notes.txt
subedit-gui: notes.txt: is in no format this tool knows
```

Открыть пустое окно, а не отказаться запускаться: программа всё ещё на что-то
годна, и сбой аргумента — не повод её не запускать.

**Файл с ошибками в разметке, но читаемый, открывается**, а то, что чтение подобрало
по ходу дела, можно прочитать на кнопке строки состояния — см.
[диагностические сообщения чтения](files.md#диагностические-сообщения-чтения).

## Коды завершения

| Код | Когда |
| :--- | :--- |
| `0` | окно открылось и затем было закрыто обычным образом либо ответил `--version` |
| `2` | непредвиденная ошибка до открытия — нет Qt, дисплей недоступен |

Сбой открытия файла **не меняет код завершения**: окно
открылось, и именно это сообщает код.

## Страница руководства man

Установка кладёт `subedit-gui(1)` в `share/man/man1`:

```console
$ man subedit-gui
```

Она описывает форму вызова, `--version`, сообщения о сбое открытия, коды
завершения, две переменные окружения и файл настроек.
**Окно она не описывает** — это делает данное руководство, и страница
отсылает сюда.

## Платформа Qt

`QT_QPA_PLATFORM` выбирает, на чём работает окно. **Если переменная
задана, `subedit-gui` соблюдает её без всякого аргумента.**

Если она не задана, выбор остаётся за Qt: встроенный проигрыватель рисует изображение
в самом окне и ничего не требует от платформы — см.
[Проигрыватель](player.md).

`QT_QPA_PLATFORM=offscreen` запускает окно там, где нет
графического сервера, — так работают система непрерывной интеграции и тесты.

## Язык

Окно говорит на языке своего окружения, **выбранном один раз, при запуске**: изменение
переменных уже работающего окна ничего не меняет до следующего запуска. Переменные и правила
те же, что у командной строки — `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`, `LC_ALL=C` для
английского, английский **без единого слова**, если запрошенный язык не установлен, — описанные в
[руководстве по командной строке](../subedit-cli/invocation.md#язык). Каталоги — те же
файлы, они устанавливаются в `<prefix>/share/subedit/locale`.

**Язык, выбранный в `Правка ▸ Настройки…`, имеет приоритет**, а окружение читается, только
если выбрано `System default`, что и остаётся так, пока язык не выбран: установленный язык, выбранный там,
перекрывает любую переменную, включая `LC_ALL=C`. Выбор тоже применяется
при следующем запуске. См.
[Язык интерфейса](preferences.md#язык-интерфейса).

| Что | Следует ли языку |
| :--- | :------------------- |
| меню и их пункты с подчёркнутыми буквами; панель инструментов; подсказки | да |
| столбцы таблицы и `Вид ▸ Столбцы`, вкладки, строка состояния, полоса воспроизведения | да |
| стандартные кнопки, которые рисует сам Qt (`OK`, `Cancel`) | да, если установлен собственный каталог Qt для этого языка (`qtbase_<language>.qm`); иначе английский |
| диалоги, страницы `Correct Texts…`, заголовки и фильтры файловых диалогов, окна сообщений и то, что они говорят | да |
| строки, которые окно пишет в поток ошибок, `subedit-gui: …` | да, кроме названия программы |
| названия шаблонов исправления в `Correct Texts…` и их описания в подсказках | да, для шаблонов, поставляемых с программой; собственный шаблон показывается так, как его пишет его файл |
| названия кодировок, окончаний строк и языков проверки орфографии (`UTF-8`, `CRLF`, `en_US`) | никогда: это названия, а не слова |
| комбинации клавиш | никогда: `Ctrl+S` — это `Ctrl+S` во всех языках |
| сообщение, которое каталог не переводит | показывается на английском |

Эта версия устанавливает `ca`, `cs`, `de`, `es`, `fi`, `fr`, `gl`, `he`, `hu`, `ie`, `is`, `it_IT`, `nl`, `pl`, `pt`, `pt_BR`, `ru`, `sr`, `tr` и `zh_CN` — каталанский, чешский, немецкий,
испанский, финский, французский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий и китайский (упрощённый), — переведённые полностью. Французский перевод проверен носителем
языка; каталанский, чешский, немецкий, испанский, финский, галисийский, иврит, венгерский, интерлингве, исландский, итальянский, нидерландский, польский, португальский, бразильский португальский, русский, сербский, турецкий и китайский (упрощённый) переведены машинным способом и ещё не проверены
