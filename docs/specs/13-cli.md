# Phase 13 — Complete CLI

Framing of issue [#542](https://github.com/Guyot-Bertrand/sub-edit/issues/542),
after the initialisation [#541](https://github.com/Guyot-Bertrand/sub-edit/issues/541).

## What the roadmap promises, and what is already there

"Subcommands meant for real use: conversion, shifting, transformation, snapping
to a grid, duration adjustment, correction, inspection. Batch processing,
human-readable output and script-readable output." Plus three deferrals that
land here: duration adjustment, to be cross-checked with
`measure-duration-constraints.py` (phase 10, [#407](https://github.com/Guyot-Bertrand/sub-edit/issues/407));
translation on the command line (phase 11, D9); correction on the command line, and
the question of what replaces its confirmation (phase 12, D8).

**Gaupol has no equivalent**: its command line only opens the window
(`FILE…`, `-e/--encoding`, `--list-encodings`, `-t/--translation-file`, `-a/--align-method`,
`-v/--video-file`, `+NUM`). **This is a new design**: no oracle, no table of
a hundred lines of deviations — what the spec confronts is what the core can do and
what the command line shows of it.

**Half of the work is already done**, and it is what makes this phase honest:

| What is already there | Where |
| :-------------------- | :---- |
| **seven subcommands**: `inspect`, `convert`, `shift`, `transform`, `framerate`, `snap`, `hearing-impaired` — the conversion, shifting, transformation, snapping to a grid and inspection of the promise | phases 3, 4 and 16 |
| a common grammar — times, indices, frame rate, encoding, destination, verbosity — and **four exit codes** | `src/lib/subedit/cli/`, [spec 03](03-cli.md) |
| `--help` generated by CLI11, and **a check that the manual and the help say the same thing** | [#546](https://github.com/Guyot-Bertrand/sub-edit/issues/546) |
| a comparator of **versioned expected files**, which shows the first diverging line | [#543](https://github.com/Guyot-Bertrand/sub-edit/issues/543), `MatchesFile` |
| a **generated batch** in a test's `Scratch`, and the e2e cases of a batch that writes — **which pin down the current behaviour, collision included** | [#544](https://github.com/Guyot-Bertrand/sub-edit/issues/544) |
| the shared sentences of `core/wording/`, **split into families** (`analysis`, `conversion`, `counts`, `editing`, `formats`, `settings`, `translation`, `video`) | [#545](https://github.com/Guyot-Bertrand/sub-edit/issues/545), #549 |
| in the core, **everything phases 10 to 12 wrote**: duration adjustment, search and replace, case, italics, dialogue dashes, merging and splitting, sorting, appending a file, splitting a project, opening a translation, correction (patterns, line breaking, joining and splitting words), their reports | phases 10, 11, 12 |

**What is not there.** No structured output; no directory walk; no
guard on a batch that writes; **none of the operations of the last row is exposed** — except
part of the removal of mentions, which `hearing-impaired` has done since phase 4.

## Preliminary analysis — the real state of the code

Read in `src/exe/cli/application.cpp`, `src/lib/subedit/cli/`, `core/edit/`,
`core/text/correction_run.hpp`, `core/config/`, `core/wording/`, `docs/manual/subedit-cli/`
and `docs/specs/03-cli.md`. What follows corrects or refines what the bodies of #541 and
#542 assumed; each point governs a decision.

**The CLI does not need Qt, except for two things, and both can be worked around.**
`subedit_cli` links only `subedit::core`; the core knows neither Qt nor any interface
(invariant 1 of `check-architecture.sh`); CLI11 stays in the executable. The only two
dependencies on Qt the phase meets are:

- **the measure in *ems*** — `EmsLineMeasure`, `QFontMetricsF`, in `gui/`. The command
  line sticks to **characters** (`CharacterLineMeasure`, in the core), as the
  roadmap says: it is not a compromise, it is the only measure that exists without a
  font.
- **the resolution of the pattern locations**, which ADR 0037 had promised "outside
  `gui`" and which **was not there**: `installedPatternsPath()` and `resolvedUserPatternsPath()`
  were in `gui/patterns_path.cpp` and called `QCoreApplication::applicationDirPath()` and
  `qgetenv`. The core provides the pure part (`shippedPatternsPath`, `userPatternsPath`);
  **the call, without Qt, has lived since [#566](https://github.com/Guyot-Bertrand/sub-edit/issues/566)
  in `subedit::platform`**, which the window and the command line both link.

**Everything else is in the core and plugs in as it is**: `proposeCorrections` and
`applyCorrections`, `readPatternCatalogue`, `openSpellChecker` and `EnchantSpellProvider`
(the dependency on Enchant is **already** pulled in by `subedit-cli`), `adjustDurations`,
`SearchPattern`, `replaceAll`, `setLetterCase`, `setItalics`, `setDialogueDashes`,
`openTranslation` and `attachTranslation`, `SortCommand`, `appendFile`, `splitProject`.

**One more subcommand costs ten to twenty-one files** (conclusion of #541):
options structure, description, execution, module function, two tests, manual page,
table of `invocation.md`, two lists of the `subedit-cli(1)` page, `CLI-*` requirements. And
**everything lives in a single file**, `application.cpp`: 575 lines for seven subcommands,
a chain of `if (…->parsed())`, no table. **At seventeen, this file would be on the order of
fourteen hundred lines** (eighty per subcommand) — the story of `MainWindow`, which had taken four issues
to slim down after the fact (ADR 0034, 0035). The extraction comes before the first
new subcommand ([#553](https://github.com/Guyot-Bertrand/sub-edit/issues/553)).

**`Operation` returns a sentence, and a count cannot be recovered from a sentence.** `rewriteAll`
takes a `std::function<std::expected<std::string, std::string>(Session&)>`: "4000
subtitles shifted by 2.999 s". A structured output cannot be derived from that
string; **the result of an operation must become an object**, of which the sentence is one
reading. That is the substantive change of slice 1 — and the guarantee that the text and the
JSON will not diverge.

**The sentences of phases 10 to 12 are not yet consumed by `cli/`.**
`noticeOfAdjustment`, `noticeOfCorrection`, `noticeOfReplaceAll`, `noticeOfItalics`,
`noticeOfRecase`, `noticeOfDialogueDashes`, `noticeOf(TranslationOutcome)`,
`noticeOfSplit`, `noticeOfAppend`, `noDictionaryFor`, `reasonOf(PatternError)` exist and
wait for their subcommand. Only `noMentionToRemove`, `noticeOfMentionsRemoved` and
`shiftBeforeTheOrigin` are read on both sides (#545). **The sentences specific to the command
line** — "4000 subtitles shifted by…", "retimed from…" — stay in `cli/`: the
rule of `CLAUDE.md` is about the words that **both** surfaces say, not those of
only one.

**A batch is a loop, and its three implicit behaviours are in the manual.** See
ADR 0039: collision without a guard, folder not created, destination overwritten; and a fourth,
found by reading `Destination::pathFor`: **`--output-dir .` overwrites the inputs without
`--in-place`**. The label of a failed write says "`cannot be read`", because
`reasonOf(FileErrorKind)` is the sentence of reading.

**A translation is a subtitle file like any other** — this is the most disconcerting thing
the analysis brings. `subedit-cli correct x.fr.srt` handles that file as a
main file, with nothing new. What pairing adds is therefore narrow: the
**alignment report** (lines attached, subtitles born, without translation, out
of order), and the gesture that **no file alone makes** — writing the translation retimed onto
the positions of the main file. D10 draws the consequences.

**The counts of `adjustDurations` and of the script cannot be compared directly**: see
D7, where what the cross-check requires of the output is written.

**The private corpus**, stated globally: seventy-nine files, mostly WebVTT, in one
root and six directories — enough to make a realistic batch, not enough to test
translation. No test reads it, no measurement is attributed to it; **the test batches
are generated** (#544).

## D1 — The scope: everything the core exposes that makes sense on the command line

**Criterion: a subcommand is justified by real use, that is, by a script, a
batch or a file one does not open.** A mirror of the window that would only make sense
with a table in front of you, a clipboard or a mouse selection is
not one.

| Core operation | Verdict | Subcommand, or reason |
| :------------- | :------ | :-------------------- |
| duration adjustment | **kept** | **`adjust`** — D7 |
| correction (patterns, line breaking, joining and splitting words) | **kept** | **`correct`** — D8 |
| search and replace | **kept** | **`replace`** — D9. There is no `find`: `replace --dry-run` lists the matches with what they would become, which is what a `find` would return, and more |
| case (title, sentence, upper, lower) | **kept** | **`case`** — D9 |
| italics | **kept** | **`italics`** — D9. Putting a whole file in italics is not the use; **removing them**, and doing it on a range, is |
| dialogue dashes | **kept** | **`dialogue-dashes`** — D9 |
| sorting subtitles | **kept** | **`sort`** — D9. The core never sorts on its own (ADR 0012): `sort` is the gesture made **on purpose**, and one that a batch of unordered files calls for |
| translation | **kept, as options** | `-t/--translation-file`, `--document`, `--align-method` on `inspect` and the text subcommands — D10 |
| list of encodings | **kept** | `--list-encodings`, iso-functional with Gaupol; ICU enumerates them ([#564](https://github.com/Guyot-Bertrand/sub-edit/issues/564)) |
| appending a file after another | **kept, gate passed** (#570) | **`append`** — D12. The use is real (a film in two parts), the arity is not: N inputs, one output |
| splitting a project | **kept, gate passed** (#571) | **`split-file`** — D12: the exact inverse of `append` |
| a translation retimed onto the main file | **kept, gate passed** (#572) | **`pair`** — D10, D12: the only thing pairing does that a file alone does not |
| merging subtitles | **set aside** | a range of numbers read in a table; the command line has no table in which to see it, and a script does not know which line to merge. Trigger: a caller who knows which line |
| splitting a subtitle in two | **set aside** | the second half is born **empty**: the operation expects a text to be typed into it, and the command line has no "afterwards". Same trigger |
| clipboard (copy, cut, paste) | **set aside** | a gesture of the window: there is no clipboard for a process that terminates |
| inserting, deleting subtitles by hand; entering a text, a position, a duration | **set aside** | editing a subtitle that is in front of you; `replace` and `adjust` cover what is automatic |
| interactive spell checking (`Check Spelling…`) | **set aside** | a walk through unknown words accepted one by one; **automatic joining and splitting** are in `correct`. A list of unknown words (`misspelledSpellRanges` exists) is a candidate: no caller has asked for it |
| undo, redo | **set aside** (phase 3) | a process that terminates has nothing to undo |
| running past the end of the video (`BeyondEnd`) | **set aside** | the command line associates no video with a file; it would need `--video-duration`, and nobody has asked for it. Trigger: a request |
| `Preview`, built-in player, thumbnail | **set aside** | the window |

**Seven more subcommands, three behind a gate.** What is set aside is set aside with its
trigger: a tool set aside without a trace comes back at every phase.

**The existing seven do not move.** The six that write gain the three foundations —
`--format json`, `--dry-run`, the safe batch —, and `inspect` gains `--format json`: **the batch
loop, that of `rewriteAll` as well as that of `convert`, carries them for them**, as soon as the operation
returns an object and not a sentence (slice 1).

## D2 — An invocation is self-sufficient: no setting is read

**The command line reads no settings file, writes none, and retains
nothing from one invocation to the next.** The result of a run depends only on its
arguments, on the files it is given, and on what the installation provides. The configuration
folder of ADR 0022 remains **the window's**; `gui::userSettingsPath()` remains the
only code that resolves one, and nothing in `cli/` calls it.

**What is an exception, and is only ever read**:

| Read | Why |
| :--- | :-- |
| **the shipped patterns**, `share/subedit/patterns`, found from the executable | they *are* the correction; an installation without them says so (diagnostic of the catalogue) |
| **the user's patterns**, `$XDG_DATA_HOME/subedit/patterns` | the iso-functionality of ADR 0037: they are dropped in, they apply. A test never resolves it: the harness moves `XDG_DATA_HOME` |
| **the system dictionary and Enchant's personal word list** | that is the spell checker (D6 of spec 12); the tests move `ENCHANT_CONFIG_DIR` |

**What is not read, and why.**

- **The activation overrides** (`correction.activations`): the command line starts
  from the shipped `.conf` files and is set by `--enable` / `--disable` (D8). Reading the
  window's overrides would make a script depend on what its author once ticked there — and a
  test on what its author once ticked there, which `check-config-home.sh` exists
  to prevent.
- **The replacement list** `spell-check/<language>.repl`: it is *filled* by the
  gestures of the window. The command line passes an **empty** configuration directory to
  `spellReplacementFile`, which then returns an empty path, **which is neither read nor written**
  (#530). It is not an oversight: it is the only difference in result between the two
  surfaces for the same correction, and it is recorded among the deviations.
- **The assistant's defaults** — checked tasks, language, line breaking —: **the window's
  settings are not the command line's defaults**, and several could not
  be (D8: 24 and 3 are *ems*).

**There is no ambient language either.** For the spell checker, the window takes the
system language when nothing is chosen; a command line that inferred one from it
would answer differently on two machines. **The language is named.**

## D3 — Script-readable output: `--format json`

**Settled by [ADR 0038](../adr/0038-sortie-json-lines-versionnee.md)**, and it is the
user's decision: **`--format json`, opt-in, global option**. On standard
output, **one JSON object per input file** (JSON Lines): for `inspect`, the
description of the file; for each subcommand that rewrites, **the report** — the
file, `ok`, the counts, the warnings, the destination. Text remains the default;
the narration (`-q`, `-v`, `-vv`, `-vvv`) remains on standard error.

**Why a structured format and not stable lines**: a promise of stability on
sentences forbids correcting a sentence, and `wording/` must be able to do so. **Why
JSON Lines and not an array**: a batch flows, an array can only be read at the end.
The ADR states the alternatives and what is promised stable.

**Three properties hold the promise**, and each is a requirement:

1. **One object per input, never zero, never two**, failure included: the reader counts the
   lines and finds its files again. **The three subcommands with their own arity make one object per
   run** — `append` reads N files for one output, `split-file` reads one for two, `pair` reads
   two for one — and their object, failure included, states the file that names it: the base, the file cut,
   the translation.
2. **Verbosity does not act on standard output.** The reading diagnostics, which
   text places at level 3, are data and are always in `warnings`.
3. **No floating-point number.** Integer milliseconds, integer counts, frame rates and
   rationals as strings, concentrations in thousandths.

**What the proof is.** **Versioned expected files**, written by hand
(`src/test/data/attendus/json/`), compared by `MatchesFile` (#543) — never the output of the
program read back by the program —, plus an independent Python script that checks that they
are valid JSON, that they carry the envelope and contain no floating-point number.
**A change of format is a fixture diff.**

**What the objects carry**, in summary — the manual carries the complete tables, replayed by
`manual-check`:

| Subcommand | `counts` |
| :--------- | :------- |
| `inspect` | no `counts`: the description — format, encoding and its origin, mark, line endings, number of subtitles, span in milliseconds, deduced grid or frame rate, anomalies by number |
| `convert` | `subtitles`; the loss, item by item (`ConversionLoss`) |
| `shift`, `transform`, `framerate`, `snap` | `subtitles`, and what they already say: the shift in ms, the positions moved, the largest displacement in ms |
| `hearing-impaired` | `cleaned`, `removed` |
| `adjust` | `subtitles`, `adjusted`, `sacrificed.{speed,minimum,gap}` — **and the constraints used**, D7 |
| `correct` | `corrected`, `removed`; `failures` as warnings — D8 |
| `replace` | `replaced` (matches replaced in the subtitles whose text changed — the number the sentence states), `matched` (matches found, whether or not the text changed: what distinguishes "nothing found" from "nothing to change") |
| `case`, `italics`, `dialogue-dashes` | `changed` |
| `sort` | `subtitles`, `moved` (the places whose subtitle changed) |
| `pair` | `subtitles` (those of the file written, subtitles born of a line included); outside `counts`, `alignment` as on the text subcommands |
| `split-file` | `subtitles`, `head`, `tail`; `destination` is the head, and `tail` — outside `counts` — the tail |
| `append` | `files`, `subtitles`, `appended`, then the losses of `convert` summed; outside `counts`, `inputs`: one element per file appended, with its own counts |

## D4 — The batch: safe, created, tree-shaped

**Settled by [ADR 0039](../adr/0039-le-lot-collisions-dossiers-et-arborescence.md)**, on
the user's decisions and on the findings of #544. In one sentence per rule:

- **two inputs with the same destination are refused before anything is written** — usage error,
  code `1`, both inputs named —; the same goes for **a destination that is an
  input** without `--in-place`;
- **the output folder is created** if it is missing; **an existing destination is overwritten**,
  by atomic write, **and the manual says so at the head of the section on the destination**;
- **`--recursive` / `-r` and directories as input**, sorted walk, no symbolic
  link, extensions of the known formats (`.txt` excluded from the walk), **tree
  preserved under `--output-dir`**, relative to the given directory;
- **the label of a write says "written"**, and the manual is aligned with it.

**The list of inputs is established in full before writing**: that is what makes these guards
verifiable, and what makes `--format json` "one object per input" unconditionally.

**The batch stays sequential.** Its measurement is born with the walk (#541 had set it aside as long as there
was nothing to walk): N generated files against the same work in a single one,
logged by `make bench`.

## D5 — Write directly; propose with `--dry-run`

**Settled by [ADR 0040](../adr/0040-correct-ecrit-directement-dry-run-propose.md)**, on
the user's decision: **`correct` writes directly**, and **`--dry-run` writes
nothing and prints the proposed changes — the text before and after, per subtitle — on
standard output**. It is the "mode that proposes without applying" that phase 12 left to
this one, and it **replaces** the confirmation page: same changes, same core
function, without the step of accepting or rejecting.

**It is uniform.** Every subcommand that writes accepts it; it requires no destination,
checks the one it is given, and returns the code of a real run. On the text
subcommands, standard output is the list of changes; on the others, what their output
would say. **Why `replace` at the same time as `correct`**: seeing what is going to be replaced before
doing it is the same need, and a separate grammar would be a second mechanism.

## D6 — The selection: `--range`

The window acts on a selection; the command line, by default, on **the whole
file**. **`--range N-M`** (counted from 1, **bounds included**, `N-` up to the
end) restricts the operation — the index already has its grammar (`index_grammar`), and an index out of
bounds is refused **naming the bound**, before any processing.

**For which subcommands**: those whose core operation takes a `Selection` and
for which the range makes sense — `adjust`, `replace`, `case`, `italics`, `dialogue-dashes`,
`correct`. **The existing seven do not take it** in this phase: it is not an oversight,
it is the scope (open point 6).

**It is also the tool of the cross-check of D7**: a disagreement between two counts is located by
narrowing the range down to one subtitle.

**A range applies to each file of the batch**, which only makes sense if the files
resemble each other; it is a limit, stated in the manual, not an error — a batch of
different files has no use for a range.

## D7 — `adjust`, and what the cross-check of #407 requires

```
subedit-cli adjust [--speed CPS|off] [--shorten] [--no-lengthen]
                   [--minimum TIME|off] [--maximum TIME] [--gap TIME|off]
                   [--range N-M] [--dry-run]
                   (--output … | --output-dir … | --in-place) <file>...
```

**The defaults are those of `DurationConstraints{}`, which are those of Gaupol and of the
window's first opening**: a speed of 15 characters per second that only lengthens,
a minimum of 1.5 s, **no maximum**, a gap of 0. `off` switches a constraint off
(*absent, not zero*, as in spec 10: a minimum of zero is worth zero); `--maximum`
switches it on. **Without any active constraint, the operation is refused** (`isAny()`): usage
error.

**The report says what was sacrificed**, through `noticeOfAdjustment` — ADR 0008: it is
the only thing phase 10 adds to Gaupol, which violates silently.

**The cross-check.** [#407](https://github.com/Guyot-Bertrand/sub-edit/issues/407)
recorded what the command line had to make possible: to record, on the same files and
with the same settings, what the script predicts and what the core declares, and **to look for
the error of one of the two** if they differ. What the framing establishes, by rereading the
two:

| The script (`measure-duration-constraints.py`) | The core (`adjustDurations`) |
| :--------------------------------------------- | :--------------------------- |
| counts **before** the adjustment, on the written positions | counts **after**, on the resulting end |
| **one room** per subtitle: `next.start − start − gap` | **one end** per subtitle, constraint by constraint |
| three pairs: **minimum against gap** (room < minimum), **speed against gap** (room < length / speed), **speed against maximum** (length / speed > maximum); plus the union of the three | three counts, **one per constraint still violated**: `sacrificed.minimum`, `sacrificed.speed`, `sacrificed.gap`; **no count of the maximum**, which is always held |
| a **maximum set at 6 s**, which is information even when nobody uses it | **no maximum by default** |
| only reads `.srt` and `.vtt` | reads the nine formats |

**The counts that compare** — reread in `adjustDurations` and in the script by
[#560](https://github.com/Guyot-Bertrand/sub-edit/issues/560), which corrected what the framing
assumed:

```
room = next.start − start − gap                     (integer milliseconds)

sacrificed.minimum  ↔  room < minimum   or   maximum < minimum
sacrificed.speed    ↔  room < need      OR   need > maximum           (the union)
sacrificed.gap      ↔  room < 0
need = length × 1000 / speed, rounded to the millisecond
```

- `sacrificed.minimum` ↔ "minimum against gap" — plus the case of a minimum greater than the
  maximum, which the core counts as a minimum: **the two coincide when the maximum is
  off or at least equal to the minimum**;
- `sacrificed.speed` ↔ **the union** of "speed against gap" and "speed against
  maximum" — **not the sum**: a subtitle in both counts once for the core.
  The script **now writes it**, under "sacrificed (predicted)";
- `sacrificed.gap` ↔ the subtitles whose room is **negative** (the end bounded at the start).
  **The framing said the script classed them as "out of scope": that was wrong** — its "out of
  scope" is "end before the start", another thing, and negative room had no
  column. It has one now;
- **the need is rounded to the millisecond, as the core rounds it** (`readingTimeOf`). The
  script compared in floating point: "Hi" at 15 characters per second asks for 133.33 ms, and a
  room of 133 ms passed for insufficient. **It was the script that was wrong**, and the
  fixture (`arrondi.srt`) shows it: without the rounding, its check fails;
- **the room does not depend on the written duration**: a subtitle whose end precedes its start
  counts for what it is, the core treating it like the others;
- **"next" is the next one in the file**, on both sides — the core does not sort on
  reading;
- **the maximum**: the core does not count it, the script does; the cross-check sets it on both
  sides (`--maximum 6`) so that both computations bear on the same question, and only compares
  the three counts above.

**What `adjust` must expose in `--format json` for the cross-check to be possible**:

- **`counts.subtitles`** (the size of the target) and **`counts.adjusted`**;
- **`counts.sacrificed.speed`, `.minimum`, `.gap`** — the three counts, as the core
  returns them;
- **`constraints`**: the constraints **used**, spelled out — the speed in
  characters per second and its two directions, the minimum, the maximum **or `null`**, the gap, in
  milliseconds. That is what makes it possible to **check that the two computations bear on the same
  settings** without reading the command line;
- **`--dry-run`**, to count without writing.

**How the comparison is proved.** What must become a guarantee rather than an
observation needs a **versioned fixture**: a small suite of files, in
`src/test/data/`, built to cover each pair and their overlaps, with **the
expected counts written by hand** from the definitions. Both tools are confronted
with it — the core by an e2e case in `--format json` and `MatchesFile`, the script by its
own check. **Replaying afterwards on the private corpus is an observation**: "the two
counts agree on the `.srt` and `.vtt` files" or "they diverge on so many
files, for such a reason"; **no file is named and no figure is attributed
to it**. If they diverge, one of the two is wrong, and the issue says which and corrects it.

**What was done** ([#560](https://github.com/Guyot-Bertrand/sub-edit/issues/560)): the fixture is `src/test/data/durees/` (nine files, SubRip and WebVTT, one per pair of constraints and per overlap), its hand-written expected results are `attendus/json/recoupement-defaut.jsonl` and `recoupement-ecart.jsonl` (two settings, one of them a gap of 0.5 s that makes negative room possible). The core is confronted with it by an end-to-end case (`CLI-ADJUST-06`), the script by `--check-fixtures`, which runs in `make check-local`. The confrontation with the private corpus is `--crosscheck`.

## D8 — `correct`

```
subedit-cli correct --tasks LIST [--code CODE] [--classes human|ocr|human,ocr]
                    [--enable NAME]... [--disable NAME]...
                    [--language CODE]
                    [--max-length N] [--max-lines N]
                    [--skip-length N|off] [--skip-lines N|off]
                    [--keep-blank-subtitles]
                    [--document main|translation] [-t FILE] [--range N-M] [--dry-run]
                    (--output … | --output-dir … | --in-place) <file>...
```

**Tasks are named, and none is checked in advance.** `--tasks` is required; it takes
a list among **`mentions`, `join-words`, `split-words`, `common-errors`, `capitalization`,
`line-break`** — the four tasks of the core (`CorrectionTask`), joining and splitting
words being two settings of the same task. **They apply in Gaupol's
order**, which `proposeCorrections` holds: mentions, joining and splitting, common errors,
capitalization, line breaking. **The order of the list changes nothing** — and the manual says so.

**`--code` names the pattern cascade**: `Script[-language[-COUNTRY]]`, `Zyyy` for any
script (`Latn`, `Latn-en`, `Latn-en-US`…). **It is required as soon as a task reads
patterns**: without an ambient language (D2), a universal default would apply *less* than what
the user believes, without saying so. **It applies to all the pattern tasks of a single
run**; a task that would want a code of its own is a second run.

**`--classes`** filters common errors **for real** (D4 of spec 12): unchecking
`ocr` removes its patterns from the application, and not only from the display.

**`--enable` / `--disable NAME`** — repeatable — set the activation of a pattern by its English
name, the name being the key (ADR 0037). **It is necessary, and it is what sets aside the
window's default values**: the shipped `.conf` files of `Latn` **deactivate the
mention patterns**, so that `--tasks mentions` would apply nothing. The two patterns
"Sound in brackets" and "Sound in parentheses" drive the scan of phase 4 (D7 of
spec 12) and are set by the same options. **A name that designates nothing is a usage
error** — the window ignores a stale override because a setting can survive a
pattern that has disappeared; an invocation has no survivor, and a typo must be
loud. **A name ambiguous between two types** is written `type:name`. **A pattern task
(`mentions`, `common-errors`, `capitalization`) with no active pattern** is refused:
"nothing to do" is an answer that gets said, not a silent success.

**`--language`** names the spell checker's dictionary (`fr_FR`, `en`…), **required with
`join-words` or `split-words`**. **Without a dictionary for that language, the run is a
usage error**, with the window's sentence, `noDictionaryFor` ("no dictionary for fr"),
**before any processing**: the window greys out the feature and says so, the command line
refuses and says so — in both cases, rather than keeping silent.

**Line breaking is measured in characters.** `CharacterLineMeasure`, in the core; the
measure in *ems* is the window's (D5 of spec 12). **`--max-length` is required with
`line-break`, without a default**: Gaupol's 24 is a value in *ems* — an em calibrated at
0.55 per letter —, and copying it as characters would break almost everything, silently.
`--max-lines` is 3, Gaupol's default, which the unit does not change. **The skip** — a
subtitle within the limits is left as it is — takes, by default, **the same bounds**,
like Gaupol; `--skip-length off` and `--skip-lines off` switch it off.

**Subtitles emptied by the correction are removed**, like the window's default
box; `--keep-blank-subtitles` leaves them empty. An emptied translation stays empty (rule
of #431, held by `proposeCorrections`).

**What `correct` says.** The count is the window's, through `noticeOfCorrection` —
"Edited N and removed M subtitles": **changed texts, never matches**.
**A pattern that cannot be read, cannot be translated or does not terminate** is named — and this is
where the command line goes beyond the window: the confirmation page names the pattern once,
without the text; **the command line names the subtitle**, which
`PatternFailure::text` carries in the core (the review of phase 12 had recorded it). At
level 1 on standard error, as a `pattern-failed` warning in JSON. **An abandoned
pattern is not a failed file**: code `0`.

**`--dry-run`** (D5) prints, per changed subtitle, the text before and the text after —
`ProposedCorrection::original` and `proposed`, `proposed` absent for a removal.

**The computation is deterministic**, and that is what makes it possible not to apply in two steps
(ADR 0040).

## D9 — The text subcommands, and `sort`

Each one is **a core operation, a grammar, a report from `wording/`**.

```
subedit-cli replace PATTERN REPLACEMENT [--regex] [--case-sensitive] [--document …] [-t FILE] [--range N-M] [--dry-run] <destination> <file>...
subedit-cli case --to title|sentence|upper|lower [--document …] [-t FILE] [--range N-M] [--dry-run] <destination> <file>...
subedit-cli italics (--on | --off) [--document …] [-t FILE] [--range N-M] [--dry-run] <destination> <file>...
subedit-cli dialogue-dashes (--add | --remove) [--document …] [-t FILE] [--range N-M] [--dry-run] <destination> <file>...
subedit-cli sort <destination> <file>...
```

- **`replace`** searches in **the visible text** and replaces in **the source text** without
  breaking a tag (rule of phase 10, `recherche.cas`). **Plain text by default,
  `--regex` for an ICU expression, case ignored by default** (`SearchOptions`, like
  the window); **`--case-sensitive`** distinguishes it. The expression is read **before any
  processing**: `reasonOf(PatternError)` as a usage error. The count is
  `noticeOfReplaceAll`, "not found" when nothing was found, `nothingToChange` when the
  match is replaced by itself.
- **`case`**: the four cases, tags intact; count `noticeOfRecase`.
- **`italics`**: in **the tags of the file's format** — a format without style
  (TMPlayer, LRC) **refuses**, file by file, with the reason, as the window switches off
  the entry without hiding it. The core takes **a direction**, not a toggle: "one operation,
  two doors, the decision stays with whoever has a user in front of them" — that is the core's
  sentence, and that is why `--on` and `--off` are two words.
- **`dialogue-dashes`**: same form, `--add` / `--remove`.
- **`sort`**: **stable** sort by start; counts the subtitles moved, **zero** when the
  file was already in order — and **the file is then written all the same**, the rule of the
  subcommands that write (`hearing-impaired` laid it down).

**All texts target the main document by default**, and the translation with `--document
translation` together with `-t` (D10).

## D10 — The two documents: `-t`, `--document`, `--align-method`

**What the analysis found**: a translation file **is already handled as a main file**.
What pairing adds to an invocation is **narrow**, and that is what is delivered:

- **`inspect -t FILE`**: the pairing report — lines attached, subtitles born,
  subtitles without translation, lines out of order —, through `noticeOf(TranslationOutcome)`, and
  in JSON. **A script knows whether a translation is aligned before correcting it**, which the
  private corpus does not make it possible to test at scale for lack of pairs.
- **`--document main|translation`** on the text subcommands, with **`-t FILE`**
  (`-t/--translation-file`, as in Gaupol) and **`--align-method position|number`** (`-a` in
  Gaupol; **position is the default**, D4 of spec 11 — the eight cases of
  `src/test/data/paires/` say why).
- **Rules**: `--document translation` **requires `-t`**, and `-t` **requires** `--document
  translation` on a text subcommand — one without the other is a usage error,
  because a file read that no gesture uses is an omission, not a preference.
  **`-t` names a file and therefore only makes sense for a single input**; with a batch, it is
  refused as `--output` is (open point 3).
- **What is written**: **the targeted document, and it alone**, at **its own path and in its
  own format** (ADR 0032). `--output FILE` names the translation's file,
  `--output-dir` puts its base name there, `--in-place` rewrites it. The main file is not touched.
- **The main text is never targeted by accident**: without `--document`, nothing changes
  for whoever does not open a translation.
- **A mention that would empty a translation writes it empty** and keeps the subtitle: the rule of
  phase 11 carries through to here.

**What these rules do not do**: they do not shift a translation with its main file.
The **position** subcommands (`shift`, `transform`, `framerate`, `snap`, `adjust`) are
given **both files**, like any batch: `subedit-cli shift --by 2
main.srt translation.srt --output-dir out/`.

**The one thing only pairing does** is write the translation retimed onto the positions
of the main file — **`pair`** (D12, gate passed): `pair MAIN -t TRANSLATION --output
FILE`. Alignment has a result that nothing else produces, and that is precisely
why it is separate from `-t`.

## D11 — The sentences and the manual

**Every new subcommand states its counts through the core.** That is the rule the conclusion
of #541 recorded in place of a parity check, whose criterion is not
decidable: **parity goes through `core/wording/`**. Concretely:

- the sentences the window also says — those of `counts`, `editing`, `translation`,
  `conversion` — are **called**, never copied;
- the sentences specific to the command line — "N subtitles shifted by…", the summary of a batch,
  the usage refusals — stay in `cli/`;
- **the text and the JSON are read from the same object** (ADR 0038), so that no sentence carries
  a number the JSON does not carry;
- everything the binary writes is **in English**; so are the test titles;
- **the manual** has **one page per subcommand**, examples replayed by `manual-check`, the
  exit codes and the errors — and **every option appears in it**, which #546 checks against
  `--help`. The `subedit-cli(1)` page and the table of `invocation.md` follow. The manual
  describes what exists: `docs/manual/subedit-cli/invocation.md` gains a section
  **"Script-readable output"** when `--format json` is delivered, and the section on
  **the destination** is rewritten by the batch.

**The manual's examples are generated by the binary** (`make manual`): they cannot
lie. **The tests' expected results, on the other hand, never are**: written by hand, by the rule of
#338.

## D12 — A gate before the last slice

**Like #435 for multiple projects, because the need is not confirmed.** The three
structural subcommands — `append`, `split-file`, `pair` — all have a real use and
**none has a known caller**: a film in two parts, a translation to retime. Building
them before someone says so means adding three manual pages and three
grammars — one of which, `append`, **breaks the model of a batch** (N inputs, one output), and
another, `split-file`, produces **two outputs** — to a tool whose quality is to be
predictable.

**The gate is placed at the entrance of slice 5**, and decided by the user (open
point 2). **What stops before it stands on its own**: slices 1 to 4 depend
on none of the three.

**Gate passed for `append`, on 5 October 2026** (#570): the user asked for the issue. `split-file`
(#571) and `pair` (#572) stay behind theirs: the decision only bears on what it names.
**The criterion "an empty file in the middle" does not play out as written**: no reader returns a file
without a subtitle, so an empty file does not exist on the command-line side. It plays out as what it is — a
file that cannot be read: the run stops, code `2`, nothing is written. The "nothing to append" case of the
core remains the window's.

**Gate passed for `split-file` on 5 October 2026** (#571), on the same request; `pair` (#572) stays
behind its own. The grammar of the two outputs: `--head` and `--tail`, both required outside `--dry-run`,
neither the input nor the same file; in JSON, `destination` is the head and `tail` the tail.

**Gate passed for `pair` on 6 October 2026** (#572), on the same request: the last of the three. `pair` is
`rewriteAll` with a pairing and an operation that changes nothing; **its sentence is the alignment, stated from
level 1** — elsewhere it is level 2, here it is the result. Its expected results are those of `paires/`,
written by hand before anything aligned anything.

## How the phase is proved

- **Each subcommand has its end-to-end cases** — the real binary, the two outputs
  kept apart, the four exit codes — **and its versioned expected results** for what it writes
  (`MatchesFile`, #543). The expected results are written by hand.
- **The batch is tested on a generated batch** (#544): collisions, missing folder, existing
  destination, overwritten input, failure in the middle and code `3`, walk of a tree and its
  preserved layout.
- **The JSON has its expected results and its validity script** (D3).
- **Correction reads neither the user's configuration nor their patterns nor their words**:
  the harness moves `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `ENCHANT_CONFIG_DIR`;
  `check-config-home.sh` already watches what the command line could touch
  (`~/.config/subedit`, `~/.config/enchant`); reading the user's patterns does not write them.
- **A benchmark of the batch** (D4) and **the benchmark of `correct`** from phase 12 (which already exists):
  the phase adds the cost of the walk, not a second benchmark of the patterns.
- **The cross-check of #407** is the only place where two independent computations are compared;
  its expected results are a fixture, its observations on the private corpus are stated
  globally (D7).

- **The translation of the names and descriptions of the patterns** — phase 15, with the rest.

  who has a batch of pairs and says so.

  The six text subcommands and `adjust` have it; `shift`, `transform`, `framerate`, `snap`, `convert`,
  `inspect` and `hearing-impaired` do not. Trigger: a caller who shifts a range.

  trigger is written in ADR 0039: a batch that shows up in the benchmark, a caller who

- **A settings file for the command line** — **set aside**: D2.
- **Interactive spell checking, a list of unknown words, a `find`, the
  merging and splitting of a subtitle, the clipboard, the duration of the video** — **set aside**

- **A JSON schema, a schema version selector** — ADR 0038, trigger written.
- **A state between two invocations** (a patch that is replayed, a cache) — ADR 0040.

## Deviations from Gaupol

**Few, and that is normal**: Gaupol's command line only opens a window. The deviations
are those of **correction** — whether or not Gaupol's assistant conforms to it — and those of the
options both have.

| What Gaupol does | What `subedit` does | Why |
| :--------------- | :------------------ | :-- |
| `-t/--translation-file` **opens** the translation in the window | **pairs** for a subcommand, on **one** main file; writes the targeted document | D10: an invocation has no window |
| the assistant asks for confirmation, each text is checked | **writes directly**; `--dry-run` proposes | ADR 0040 |
| line breaking is set in *ems*, **24 long** | in **characters**, `--max-length` **required** | D8: the measure in *ems* is the window's, and 24 characters break almost everything |
| pattern activation is read from the user's `.conf` files; the window's from our settings | **the shipped `.conf` files**, set by `--enable` / `--disable` | D2: an invocation reads no setting |

| the spell checker's language comes from the locale when nothing is chosen | **always named** (`--language`) | D2: no ambient language |
| a stale pattern name in an override is **ignored** | **a usage error** | D8: an invocation has no survivor |
| `-v/--video-file`, `+NUM` | **not taken over** | window |
| `--list-encodings` writes **on one line, comma-separated**, the encodings of `aeidon`'s table, preceded by `auto` when `chardet` is there | writes **those ICU can convert**, **one per line**, sorted by name; `--format json` makes one object per line of them | D1: iso-functional by intent, not by the list — the set is ICU's, and one line per name is readable by a script |

thankless and the least negotiable**: the phase would double a file that already has 575 lines.
